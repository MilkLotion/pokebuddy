## 열린 항목

수정 우선순위와 다음 행동은 [피드백](feedback.md)을 따른다.

### V2-01 — 타입 배지 문자 대비

18개 배지는 11px 흰 글자를 사용한다. sRGB 변수값으로 계산하면 13개가 4.5:1 미만이다. 일반 크기 문자의 최소 대비 기준은 [W3C SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 따른다. 아래 표시는 소수 둘째 자리로 반올림했다. 판정에는 반올림 전 값을 사용한다.

| 타입 | 흰 글자 대비 | 타입 | 흰 글자 대비 |
|---|---:|---|---:|
| Bug | 2.87 | Dark | 7.80 |
| Dragon | 5.12 | Electric | 1.67 |
| Fairy | 2.55 | Fighting | 2.52 |
| Fire | 4.47 | Flying | 2.08 |
| Ghost | 7.84 | Grass | 3.31 |
| Ground | 6.17 | Ice | 1.85 |
| Normal | 2.60 | Poison | 5.49 |
| Psychic | 3.68 | Rock | 2.38 |
| Steel | 2.88 | Water | 3.87 |

계산식은 `(밝은 상대 휘도 + 0.05) / (어두운 상대 휘도 + 0.05)`다. 흰색 휘도는 1이다. 원시 RGB 값은 [자산 목록](evidence/inventory.json)에 있다. 어두운 문자 또는 배경 조정의 선택은 미확정이다. 전체 앱 접근성 감사는 실행하지 않았다.

### V2-02 — 숨김 마커 색상 예외

`Visibility Marker` `154:1010`의 `154:1013`~`154:1016`은 흰색·빨강 `#FF1C1C`·검정을 직접 지정한다. 브랜드 그림 예외로 둘지 PB 변수로 연결할지 정해야 한다. 예외 결정 전에는 `PB 토큰만 사용` 규칙의 완전 충족으로 표시하지 않는다.

### V2-03 — 변수 정의와 실제 연결의 차이

01~04에서 Dimension 변수 18개 중 직접 연결을 확인한 것은 `spacing/2`, `radius/md`, `radius/full`, `stroke/thin`의 4개다. 나머지 값은 변수 정의가 있어도 해당 범위 노드에서 직접 참조되지 않는다. 내비게이션 10px 값과 밑줄 좌표는 사용자 기준값으로 유지한다. 토큰 이행 시 값과 연결을 함께 검수한다. 이전 `type/*` 3개는 해당 범위에서 직접 참조가 없다. 전 파일 사용처 검사 전에는 삭제하지 않는다.

### V2-04 — 대표 데이터와 그림 연결

Portrait의 Artwork 기본값은 `Icon / Placeholder`다. 파티 화면과 상세 Template 캡처에서도 원형 자리표시자가 보인다. 타입·성격·친밀도·상태명은 예시 자료다. 상세 Template의 피카츄에 보조 비행 타입이 보인다. 이를 실제 종 데이터의 계약으로 사용하지 않는다. 그림 교체와 Screens 데이터 검수가 필요하다.

추가된 상세 Screen 5개는 피카츄를 전기 단일 타입으로 재정의했다. 이 부분은 확인됐다. 그림 자리표시자와 파티의 리자드 타입 문제는 남아 있다.

### V2-05 — 돌봄 버튼 위계

이전 S5 기록은 밥 주기를 강조 버튼, 놀아주기를 보조 버튼으로 정의한다. 현재 상세 Template 캡처는 두 버튼 모두 강조색이다. v2에서 두 행동을 동등하게 강조할지 결정해야 한다. 이번 작업에서는 Figma 값을 변경하지 않았다.

### V2-06 — 상세 화면의 본문 스크롤 누락

다섯 상세 Screen과 내부 모든 후손의 `overflowDirection`은 `NONE`이다. 본문은 888px이며 루트 780px 프레임에서 잘린다. Base의 진화 조건·가방 버튼은 y=830, 교체·소환 해제 버튼은 y=924에 있다. 현재 설정으로는 이 버튼에 스크롤로 도달할 수 없다. 예를 들어 Base 본문은 `I217:1969;197:450`이다.

전체 콘텐츠 Template은 유지하되 실행 Screen의 본문 638px 스크롤, 고정 헤더와 모달 위치를 함께 설계해야 한다. 상세 기본·숨김·성공과 모달 상태 모두 재검사한다. [현재 S5 수용 기준](../../specs/s5.md)의 본문 스크롤 조건은 아직 충족하지 않는다.

### V2-07 — 숨김 화면의 상태 설명 불일치

Hidden 화면의 상단은 `파티 1번 · 숨김`이다. 마커도 표시된다. 버튼은 `다시 표시`다. 그러나 `I222:1064;197:559;162:203;184:180;182:159`에는 `지금 화면에 표시 중이에요.`가 남아 있다. 숨김 상태에 맞는 설명으로 바꿔야 한다. Base와 Hidden이 같은 설정 설명을 그대로 공유하지 않도록 확인한다.

### V2-08 — 모달 배경막이 완전히 불투명함

Scrim Atom `141:125`의 노드 opacity와 fill opacity는 모두 1이다. `overlay/scrim` 별칭의 색상 alpha도 1이다. Modal Scrim과 Screen 인스턴스의 opacity도 1이다. 결과적으로 Confirm과 Error에서 기존 화면이 보이지 않는다.

Legacy에서는 같은 문제를 노드 opacity 0.16으로 수정했다. 이전 F-02 기록을 참고한다. v2의 최종 불투명도는 정해야 한다. 검수 판정에서는 현재 모달을 반투명 오버레이로 기록하지 않는다.

### V2-09 — 친밀도 숫자와 막대 비율 불일치

파티 카드 3개와 상세 프로필 5개에서 track은 모두 220px, fill은 모두 156px다. 156 / 220은 약 70.91%다. 85 / 100과 71 / 100 사이에 fill 차이가 없다.

파티 카드의 progress 래퍼는 182px이고 `clipsContent=true`다. 220px track이 잘려 세 카드 모두 약 85.71% 길이로 보인다. 상세 progress 래퍼는 492px이지만 track은 220px에 머문다. 숫자만 바꾼 현재 재정의로는 값 비율과 폭 대응이 유지되지 않는다. 기준 폭과 value/max 연결 방식을 정한 뒤 0·71·85·100 값과 카드·프로필 폭을 확인해야 한다. 숫자를 variant 축으로 추가하지 않는 규칙은 유지한다.

### V2-10 — 파티 예시의 종과 타입 불일치

파티 두 번째와 세 번째 카드는 `리자드`와 `불꽃+비행`을 표시한다. [종 데이터](../../../data/species.defaults.json)의 `charmeleon.types`는 `["fire"]`다. [한국어 이름](../../../lib/names.json)의 `charmeleon.ko`는 `리자드`다. 불꽃·비행 조합은 `charizard`인 `리자몽`에 해당한다. 리자드를 유지하면 보조 타입을 숨긴다. 리자몽 의도라면 이름과 관련 예시 데이터를 함께 바꾼다.

### V2-11 — 상태 간 프로토타입 연결 없음

6개 Screen의 루트와 전체 후손을 검사했다. reaction은 0개다. 파티 카드→상세, 파티로, 숨기기↔다시 표시, 밥 주기→성공, 소환 해제→확인, 취소·실패·재시도 이동은 연결되지 않았다. 정적 화면 상태 구성과 프로토타입 이행을 구분한다.

### V2-12 — 저장 실패의 재시도 조작 미정

Error 화면은 `기존 파티를 유지했어요. 다시 시도해 주세요.`라고 안내한다. 버튼은 Confirm과 같은 `취소 / 소환 해제`다. `다시 시도` 라벨은 없다. 기존 상세 계약의 재시도·취소 흐름에 맞춰 버튼 명칭과 목적지를 정해야 한다. 저장을 실제로 실행하거나 기존 파티 유지 동작을 검증한 화면은 아니다.

### SR-01 — 초기 알 결과와 첫 업적까지의 성립 조건 부족

우선순위: 높음. 상태: 열림. 근거: [SC-03·04](../../specs/s5-scenarios.md#sc-03-시작-포인트와-알-구매), [입수처 계약](../../specs/s5.md#개체-레벨과-입수처).
초기 해금 목록과 알 허용 목록의 교집합이 아직 없다. 따라서 첫 구매로 실제 결과를 제공할 수 있는지 검증할 수 없다. 이는 이미 Q-01에 기록된 미정 사항이며 새로운 확정 결함은 아니다.
첫 선택 종만 결과로 제공되는 경우도 확인해야 한다. 같은 종 복수 보유는 확정됐지만, 같은 종 두 개체의 첫 업적 인정은 S5 계약에서 제안 상태다. SC-05의 일반적인 두 마리 조건만으로 이 차이를 덮으면 안 된다.
`[스펙 미확정]` 모든 첫 선택 후보에 대해 초기 알 적격 종이 하나 이상인지 확인한다. 시작 포인트로 알 하나를 구매할 수 있는지 확인한다. 동일 종 두 개체도 첫 업적에서 인정하는 안을 권장한다.
보완 확인: 후보별 첫 구매→결과→두 마리 표시→보상 수령 경로를 검증한다. 적격 종이 없는 상품의 차단 방식도 정한다. 실제 목록과 동일 종 업적 판정은 사용자 결정이 필요하다.

### SR-02 — 업적 안내가 알 획득 경로에 묶임

우선순위: 높음. 상태: 열림. 근거: [SC-05](../../specs/s5-scenarios.md#sc-05-두-마리-꺼내기와-첫-업적), [단계별 안내](../../specs/s5.md#행동에-따른-단계별-튜토리얼).
SC-05의 진입 조건은 초반 랜덤알에서 두 번째 개체를 얻는 것이다. 그러나 종 지정 구매로 두 개체를 얻어 먼저 표시하는 경로도 허용된다. SC-09에는 이 경로에서 첫 업적 안내로 이어지는 연결이 없다.
알을 나중에 사면 이미 업적을 받은 뒤에 파티 꺼내기 안내가 시작될 수도 있다. 현재의 ‘초반 부화 개체’는 여러 알을 역순으로 열었을 때 대상을 특정하지 못한다.
`[스펙 미확정]` 업적 달성은 두 마리 표시 상태로 판정한다. 부화 안내는 알 구매로 시작한다. 파티 안내는 아직 익히지 않은 표시 조작을 기준으로 시작한다. 안내 대상 개체와 완료 여부는 별도로 기록하는 안을 권장한다.
보완 확인: 직접 구매로 업적을 먼저 달성한 뒤 알을 부화해도 보상이나 표시 조작을 다시 요구하지 않는다. 여러 알을 역순으로 열어도 안내 대상이 바뀌지 않는 계약을 정한다.

### SR-03 — 표시 개체가 없는 상태의 복귀 흐름 누락

우선순위: 보통. 상태: 열림. 근거: [SC-07](../../specs/s5-scenarios.md#sc-07-숨김보관맞바꾸기), [기존 창 진입 계약](../../specs/s5.md#9-창과-보안).
모든 개체를 숨기면 포켓몬을 클릭해서 관리 화면에 들어갈 수 없다. 모두 박스에 보관하면 SC-02의 진입 조건인 파티 개체도 없다. 새 시나리오에는 이 상태에서 파티창을 열어 복귀하는 절차가 없다.
기존 S5 계약에는 트레이 아이콘과 `pokebuddy settings` 진입점이 있다. 따라서 앱의 진입 수단이 없다고 판정하지 않는다. 새 시나리오와 기존 진입점을 연결하지 않은 문제다.
`[스펙 미확정]` 트레이에서 관리 화면을 열고 파티로 이동하는 복귀 경로를 권장한다. 파티가 비었으면 박스에서 배치할 개체를 선택하도록 안내한다.
보완 확인: 전원 숨김과 전원 박스 보관 각각에서 포켓몬 클릭 없이 복귀한다. 숨김에서는 적립이 계속되고 빈 파티에서는 적립이 중단됨을 구별한다.

### SR-04 — 특수 기믹의 해금 순서를 일반 조건으로 확정함

우선순위: 보통. 상태: 열림. 근거: [SC-09 3단계](../../specs/s5-scenarios.md#sc-09-도감입수처파티-확장), [종별 계약](../../specs/s5.md#개체-레벨과-입수처).
SC-09는 해금과 입수처 조건을 만족한 뒤 획득하도록 일반화한다. 그러나 S5 계약에서 특수 기믹과 도감 해금의 선후 관계는 미정이다. 기믹 발견 자체로 해금과 획득이 일어나는 가능성을 승인 없이 배제한다.
`[스펙 미확정]` 구매·알·진화의 확인된 조건과 특수 기믹의 미정 조건을 분리해 적는다. 특수 기믹의 해금 순서는 해당 기믹 설계에서 정하는 안을 권장한다.
보완 확인: 알의 미해금 종 제외 규칙은 유지한다. 특수 기믹에는 승인하지 않은 선행 해금 조건을 부여하지 않는다.

### SR-05 — 제안된 예외 처리가 수용 조건에서는 확정처럼 보임

우선순위: 보통. 상태: 열림. 근거: [읽는 기준](../../specs/s5-scenarios.md#읽는-기준), SC-01·03·05·07·08·10의 수용 확인.
본문은 중복 처리, 실패 복원, 드래그 취소 등을 제안으로 표시했다. 그러나 같은 절의 수용 확인은 이 조건들을 확정 규칙과 구분하지 않는다. 후속 구현자가 사용자 승인 조건으로 가져갈 수 있다.
`[스펙 미확정]` 수용 확인을 확정 규칙과 제안 검증으로 구분한다. 제안 검증에는 관련 Q 항목 또는 결정 근거를 연결한다.
보완 확인: 아직 승인하지 않은 예외 처리를 자동 검사 통과만으로 확정하지 않는다. 문서 검토 완료와 사용자 승인을 구별한다.

### 별도 관측 — 성장 정체 이후의 돌봄 동기

근거: [SC-02](../../specs/s5-scenarios.md#sc-02-일상-돌봄과-작업-복귀), [친밀도와 포인트](../../specs/s5.md#친밀도와-경험치의-역할).
현재 규칙에서 배고픔은 기존 친밀도와 포인트 적립 속도를 직접 줄이지 않는다. 친밀도가 충분히 높거나 향후 상한에 도달하면 돌봄 없이도 그 값에 따른 적립이 계속된다. 상한 도달 사례는 상한 채택을 전제로 한 조건부 관측이다.
이는 강제성을 낮추려는 사용자 방향과 일치할 수 있다. 따라서 악용 결함으로 판정하지 않는다. 숨김과 박스의 기존 구분도 이 관측 때문에 바꾸지 않는다.
`[스펙 미확정]` 돌봄의 장기 동기는 다양한 반응과 함께 지내는 경험으로 먼저 검토한다. 경제 비교에서는 포인트 생산량이 많은 개체만 파티에 유지하려는 압력도 확인한다. 추가 버프·친밀도 감소·적립 차단을 이번 검토에서 채택하지 않는다.

### 검토 범위와 검사

숨김과 박스의 차이, 직접 부화, 준비 완료 알의 칸 점유, 업적 수동 수령, 종료 중 진행 중단은 결정 문서와 일치했다.
의미 검수: 이번에 변경한 상태 문장과 검토·피드백·계획 기록을 읽었다. 확정 규칙, 미정 사항, 조건부 관측과 권장안을 구분했다. 한 문장에 한 사실을 적었고 같은 개념의 명칭을 유지했다.
기능 구현, Figma 관측, 런타임 빌드·테스트는 미실행이다. 이 검토는 설계 문서에만 적용한다.
문서 검사: `node scripts/check-docs.cjs`에서 문서 46개, 파일 링크 574개, JSON 5개를 통과했다. `git diff --check`도 통과했다. 새 근거 링크의 제목 앵커는 본문 제목과 별도로 대조했다. 자동 구조 검사는 열린 설계 항목의 해결을 뜻하지 않는다.

### SR-06 — 알 후보 조건과 도감 해금 수의 연결 미정

우선순위: 높음. 상태: 열림. 근거: SC-04·09, S5 계약의 종별 입수처.
알에는 해금한 종만 포함한다. 동시에 알 전용 종은 도감 해금 수 같은 조건을 만족하면 후보가 될 수 있다. 조건을 만족하는 순간 해당 종도 해금되는지 정하지 않아 두 규칙을 연결할 수 없다.
조건부 반례: 어떤 알 전용 종의 도감 해금을 최초 부화에 연결하면, 미해금이라 후보에서 제외되어 처음 부화할 수 없다. 실제 조건표가 없어 이 순환이 현재 발생한다고 단정하지 않는다.
첫 선택 후보는 미보유 상태여도 모두 해금된다. 레벨 조건으로 아직 진화하지 않은 종도 해금될 수 있다. 따라서 해금 종 수와 획득 종 수를 구분해서 계산해야 한다. 초기 해금 포함 여부와 조건 달성으로 발생하는 연쇄 해금의 재평가도 필요하다.
`[스펙 미확정]` 알 전용 종의 조건 충족 시 도감 해금과 알 후보 자격을 함께 열고, 부화는 실제 획득으로 구분하는 안을 권장한다. 도감 해금 수는 중복 없는 종 수로 집계하는 안이다.
보완 확인: 각 첫 선택에서 수집 조건에 도달하는 경로가 있다. 특정 종을 얻어야 그 종을 얻을 수 있는 순환이 없다. 예시 기준 직전·도달·직후를 확인한다. 100종을 최종 수치로 고정하지 않는다.

### SR-07 — 단일 종과 미개봉 알의 획득 권리 충돌

우선순위: 높음. 상태: 열림. 근거: SC-03·04·09·10, Q-02·03, 단일 포켓몬 계약.
기존에 미정으로 기록한 결과 확정 시점과 일회 획득 제한이 결합하는 문제다. 단일 종이 알 입수처를 허용하는 경우에 적용한다. 전설·환상을 모두 알에 포함한다는 뜻은 아니다.
조건부 사례: 구매 시 결과를 저장한다면 알 A와 B가 같은 단일 종을 예약할 수 있다. 알을 열기 전에 같은 종을 기믹이나 구매로 먼저 얻는 경우도 있다. 개봉 시에만 중복 지급을 거부하면 사용자가 산 알이 부화할 수 없거나 결과가 바뀔 수 있다.
개봉 시 결과를 정하는 방식도 후보 소진·해금 변경·실패 후 재시도의 처리가 필요하다. 어느 방식을 택해도 서로 다른 입수처와 준비 중인 알을 함께 검사해야 한다.
`[스펙 미확정]` 구매 시 결과 확정을 택하면 단일 종의 획득 권리를 함께 예약하는 안을 검토한다. 예약과 실제 획득 이력은 분리한다. 다른 획득 경로를 막는 기간과 사용자 안내는 별도 결정한다.
보완 확인: 같은 단일 종을 두 번 지급하지 않는다. 재실행으로 제한을 우회하지 않는다. 이미 산 알이 영구히 열리지 않는 상태를 만들지 않는다. 저장 실패로 유일한 획득 기회를 잃지 않는 계약을 정한다. 후보가 비면 포인트 차감 전에 알 구매 가능 여부를 처리한다.

### SR-08 — 단일 종 진화와 이전 모습 복귀 안내 충돌

우선순위: 보통. 상태: 열림. 근거: SC-06 6단계와 SC-09 단일 종 분기.
SC-06은 이전 종이 다시 필요하면 별도 개체를 얻도록 안내한다. 단일 종을 진화시킬 수 있도록 배정하는 경우에는 이전 종을 다시 얻을 수 없다. 단일 지정 종에 진화가 없으면 이 사례는 적용되지 않는다.
추가 조건: 진화로 도달하는 종도 단일로 지정한다면, 이미 그 종을 획득한 저장에서 다른 개체를 해당 종으로 진화할 수 있는지 판정해야 한다. 같은 개체 ID 유지와 종별 획득 이력은 서로 다른 기준이다.
`[스펙 미확정]` 진화 가능 여부와 별도로 종별 획득 제한을 검사하는 안을 권장한다. 이전 종의 재획득이 불가능하면 진화 확인에서 그 사실을 안내하는 안이다. 종 단위인지 진화 계열 단위인지의 제한 범위도 실제 배정 전에 확인한다.
보완 확인: 다시 얻을 수 없는 종에 재획득을 보장하지 않는다. 단일 종을 진화시켜도 이전 종의 획득 이력을 지우지 않는다. 종별 조건표와 진화 경로를 함께 검토한다.

### SR-09 — 작업 중 중단 상태와 게임 시간의 기준 미정

우선순위: 높음. 상태: 열림. 근거: SC-02·04·07·10, Q-05. 기존 절전·잠금 미정 사항을 일상 사용 흐름으로 확장했다.
관리 화면 닫기, 포켓몬 전원 숨김, PC 잠금, 절전, 앱 종료를 구분해야 한다. 관리 화면을 닫아도 게임은 계속되고, 파티를 숨겨도 상태가 진행되며, 앱 종료 중에는 진행하지 않는다는 결정은 있다. 잠금·절전 중 진행은 없다거나 있다는 결정을 아직 하지 않았다.
조건부 사례: 부화까지 1분 남은 상태에서 PC를 절전한 뒤 돌아온다. 알 준비·배고픔·버프·포인트가 각기 다른 시간 기준을 쓰면 종료 상태 유지와 다른 결과를 보일 수 있다.
`[스펙 미확정]` 상태별로 각 타이머의 진행·중단·재개를 하나의 표로 정한다. 개체의 박스 이동과 앱 종료에서 포인트 부분 진행이 초기화되거나 중복 지급되지 않도록 계약을 정한다.
보완 확인: 관리 화면을 닫는 것과 앱 종료를 구분한다. 잠금·절전 후 동일한 시간 정책으로 복귀한다. 친밀도 변화 중 적립 간격 재계산과 남은 버프 시간도 확인한다.

### SR-10 — 여러 상태 안내가 작업을 방해하지 않는 흐름 부족

우선순위: 보통. 상태: 열림. 근거: SC-02·04·06·05, 현재 설계의 돌봄을 알리는 원칙.
알림을 강제하지 않는 원칙은 확정됐지만, 여러 개체의 배고픔·부화 가능·진화 가능·업적 달성이 겹쳤을 때의 표시 방식은 없다. 튜토리얼을 하나씩 보여주는 결정만으로 일반 상태 알림까지 처리되지는 않는다.
조건부 사례: 여섯 마리가 배고픈 구간에 있고 여러 알이 준비 완료된다. 각각 말풍선을 반복하면 작업 중 짧게 구경하는 목적을 해칠 수 있다. 숨긴 개체의 배고픔을 어디에서 확인할지도 미정이다.
`[스펙 미확정]` 작업 중에는 포커스를 가져오지 않는 표시를 쓰고 관리 화면에 미확인 상태를 모아 두는 안을 권장한다. 반복 간격과 숨김 중 표현은 별도로 정한다.
보완 확인: 동시에 여러 상태가 바뀌어도 작업을 계속할 수 있다. 나중에 관리 화면에서 부화·진화 가능 상태를 찾을 수 있다. 숨김을 풀어야만 돌봄 필요 상태를 알 수 있는 구조인지 검토한다.

### SR-02 후속 — 닫은 안내와 다른 안내의 진행 관계

상태: 일부 보완 유지. SC-05의 시작 조건과 순차 표시 원칙은 확정됐다. 다음 사례는 기존 항목에 포함하며 새 ID로 중복 집계하지 않는다.
파티 안내를 닫고 업적창을 처음 열면, 중단한 파티 안내가 업적 안내를 막는지 정하지 않았다. 안내를 한 번에 하나만 표시하는 것과 중단한 안내가 전체 대기열을 막는 것은 별개다.
업적창을 미달성 상태에서 먼저 방문하면 보상 받기를 실습할 수 없다. 이때 안내를 완료할 수 있는지, 실제 첫 달성에서 수령 부분만 이어가는지 필요하다. 닫은 사이 개체를 표시·보관하거나 업적 보상을 이미 받으면 재개 내용도 달라져야 한다.
`[스펙 미확정]` 닫은 안내는 관련 화면에 보류하고 다른 화면의 안내는 시작할 수 있게 하는 안을 권장한다. 재개할 때 현재 상태를 확인하고 이미 끝낸 행동은 반복 요구하지 않는 안이다.
보완 확인: 안내 중단이 다른 기능 이용과 안내를 막지 않는다. 미달성 업적창 방문만으로 보상을 만들지 않는다. 첫 방문·첫 달성·수령·안내 완료를 별도로 확인한다.

### 기존 항목과 문서 정리

SR-01은 실제 초기 후보·가격 검증이 남았다. SR-03·04는 확정한 좁은 범위의 설계 보완을 유지한다. SR-05는 수용 조건의 승인 여부 표기 정리가 남았다.
SC-05의 전체 흐름 표는 모든 진입에서 파티 3칸이 되는 것처럼 적혀 있다. 실제로는 첫 칸 보상을 받은 경우에만 해당한다. 이는 새 사용자 결정 없이 문구를 바로잡을 수 있다.
SC-06의 경험사탕 사용은 항상 레벨 상승을 보장하는 문장이다. 경험치를 얻고 필요량을 채웠을 때 레벨이 오르는 분기를 표현해야 한다. 수치와 아이템 소모 정책은 별도다.
와이어프레임 전에 기본먹이 선택·프리미엄먹이 대상 확인, 박스 개체 돌봄·사탕 사용 허용, 이미 활성화한 버프에 재사용하는 경우를 상세 행동으로 작성해야 한다. 이는 기존 Q-06·08의 남은 계약이며 새로운 확정 결함으로 집계하지 않는다.
기존 저장 이식, 두 번째 업적, 알 돌봄의 종류·단축량, 모니터 변경 복원, 에이전트 보상 수치는 여전히 기존 결정 목록의 후속 대상이다. 이번 검토는 이 항목들을 해결하지 않았다.
