# 플레이 버그 3건

사용자가 플레이 중에 본 버그 3건을 고친다.
작업 절차는 [문서 작업 절차](../../contributing/workflow.md)를 따른다.

| 버그 | 상태 |
|---|---|
| 1. 여러 마리가 똑같이 움직인다 | 코드 완료. 시험 통과. 앱 화면 확인은 미실행 |
| 2. 도감 상세를 열면 스크롤이 튄다 | 도감 기기 창 구현 완료. 시험 통과. 개발 실행기 캡처 확인 |
| 3. 화석·패러독스가 처음부터 해금돼 있다 | 완료. 알 색 A 확정. 모든 미해금 종 실루엣 구현 |

### 원인 (관측)

1번:
- 무대 틱 하나가 모든 마리에 같은 상태 변화를 같은 틱에 넘긴다(`src/main/stage.ts` 틱 루프).
- 상태가 바뀌면 brain이 쉬기로 돌리고 작업 중이면 바로 움직인다(`src/motion/brain.ts` `toRest`, `nextAt = now`). 그래서 전원이 같은 틱에 같은 방향을 보고 같은 동작을 시작한다.
- 렌더러는 동작이 바뀌면 첫 프레임부터 다시 돈다(`src/renderer/sprites.ts` `play`). 그래서 같은 동작의 박자가 맞는다.

2번:
- 칸을 누르면 도감 칸 1110개를 다시 만든다(`src/renderer/manage.ts` `pickDex` → `drawDex`).
- 칸은 `content-visibility: auto`와 추정 높이 108px를 쓴다. 추정과 실제 높이가 달라 스크롤 위치가 바뀐다.

3번:
- `src/tools/build-unlocks.ts`가 진화 전 첫 단계 종에 `base`를 준다. 화석 15종과 패러독스 20종도 받았다.

### 범위와 수용 조건

1. 여러 마리가 같은 상태 변화를 받아도 반응 시각이 마리마다 다르다. 되풀이 동작은 마리마다 다른 프레임에서 시작한다.
2. 종 목록 알(`data/eggs.json` `pool`)의 종은 `base` 규칙을 받지 않는다.
3. 랜덤패러독스알이 상점과 랜덤알 보너스에 있다.
4. 옛 저장은 규칙 없고 얻지 않은 종의 해금을 한 번 잃는다. 얻은 종은 남는다.
5. 2번과 실루엣 표시는 Figma 확인 뒤 구현한다.

## 작업

날짜: 2026-09-27.

**1번**
- `src/motion/pet-motion.ts`: 옵션 `reactMs`를 더했다. 상태가 바뀌면 0~`reactMs` 사이 무작위 시각 뒤에 brain에 넘긴다. 활동 시각(`activeAt`)은 지연 없이 잡는다. 기본값은 0(바로)이라 기존 시험 순서가 그대로다.
- `src/main/stage.ts`: `REACT_SPREAD_MS = 1200`을 넘긴다.
- `src/renderer/sprites.ts`: 되풀이(`loop`) 동작은 무작위 프레임과 무작위 남은 시간에서 시작한다. 한 번 재생·멈춤 동작은 첫 프레임부터다.
- 계획에서 뺀 것: brain의 `nextAt = now` 흔들기와 마리별 씨앗 난수. 반응 지연만으로 전환 틱이 갈린다. 마리마다 `Math.random`을 따로 불러 이미 독립이다.

**3번**
- `data/eggs.json`: `paradox` 알을 더했다. 이름 "랜덤패러독스알", 2,000P, `single: true`, 20종. 랜덤알 `bonus`에 `paradox: 0.02`를 더했다.
- 알 색(`palette`)은 제안 값이다. 자홍 무늬에 옅은 분홍 바탕이다. Figma 확인 전이다.
- `src/tools/build-unlocks.ts`: 종 목록 알의 종을 `base`에서 뺀다. `data/unlocks.json`을 다시 만들었다. 35종의 `base`가 빠졌다.
- 다시 만들 때 `lunala`·`solgaleo`의 진화 규칙에 `when`(밤·낮)이 붙었다. `data/evo.json`에는 이미 있던 값이다. 표가 늦게 만들어져 있었다.
- 해금 정리: `DexV3.rulesRev`와 `SAVE_V3_RULES.unlockRev = 1`을 더했다. `unlockByRules`가 먼저 `pruneUnlocks`를 부른다. 판이 낮으면 규칙 없고 얻지 않은 종의 해금을 지우고 판을 올린다. 새 저장은 지금 판으로 시작한다. v2에서 옮긴 저장은 판 0이다.
- 문서: [밸런스 수치](../../specs/balance.md), [S5 기능 계약](../../specs/s5.md), [현재 설계](../../design.md), [명칭](../../terms.md).

**2번 구현**
- `data/dex-text.json`: `height`(데시미터)·`weight`(헥토그램)를 더했다. 출처는 PokeAPI `pokemon.csv` 기본 모습이다(`src/tools/build-dex-text.ts`). 기존 분류·설명문은 바뀌지 않았다(비교 0건).
- `src/tx/dex-detail.ts`: `height`·`weight`를 "1.1m"·"19.0kg"으로 준다. 미해금은 빈 문자열이다.
- `src/main/dex-window.ts`(새 파일): 테두리 없는 투명 창(폭 380). 관리 창 내용 영역 오른쪽 위에 붙는다. 오른쪽에 자리가 없으면 왼쪽에 붙고 경첩 면도 옮긴다. 관리 창을 옮기면 따라간다. 관리 창의 자식 창이라 같이 닫힌다. 높이는 렌더러가 잰 값이다.
- `src/renderer/dex.html`·`dex.ts`(새 파일): Figma 기기 화면. 그림은 빈 테두리를 잘라 정수 배(최대 2배)로 그린다. 미해금은 `brightness(0)` 실루엣이다. 울음소리는 미해금이거나 소리 설정이 꺼지면 막는다. 방향키·Esc를 받는다.
- `src/main/manage-window.ts`·`preload.ts`·`src/shared/manage.d.ts`: 채널 `manage:dex-open`·`manage:dex-step`·`manage:dex-closed`와 `dexdev:*`를 더했다.
- `src/renderer/manage.ts`·`manage.html`: 격자 아래 상세 패널을 없앴다. 칸을 누르면 고른 칸 표시만 바꾸고 격자는 다시 그리지 않는다. 이전·다음은 관리 창의 지금 목록(검색·칩 적용) 순서를 따르고, 그 칸을 화면 안으로 스크롤한다. 미해금 칸도 그림을 받아 실루엣으로 칠한다.
- `scripts/dev-manage.cjs`: `--dex-shot <파일>`로 기기 창을 찍는다.
