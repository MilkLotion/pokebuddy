# 문서 작업 절차

## 작업을 시작할 때

작업 기록은 저장소 밖의 `worklog/` 에 둔다(`.gitignore`). 공개 문서(`docs/`)는 지금 동작과 규칙만 적고 `worklog/` 를 링크하지 않는다.

1. `worklog/progress.md`에서 현재 작업을 확인한다.
2. 관련 기능 계약과 기존 작업 폴더를 읽는다.
3. 같은 기능의 후속 수정이면 기존 기록에 내용을 추가한다.
4. 새 기능이나 독립 작업이면 `worklog/records/<작업명>/record.md`를 만든다.

작업명은 소문자 영문과 하이픈을 사용한다. 채팅 제목이나 날짜만으로 폴더를 만들지 않는다.

## 기록을 작성할 때

기본 기록은 파일 하나다. 다음 절을 순서대로 둔다.

| 절 | 기록할 내용 | 역할 지침 |
|---|---|---|
| 설계 | 목표, 범위, 근거, 위험, 수용 조건 | [설계](roles/design.md) |
| 작업 | 실제 변경과 관련 파일 | [작업](roles/work.md) |
| 검수 | 실행 명령, 확인 범위, 결과 | [검수](roles/review.md) |
| 피드백과 수정 | 발견 사항, 조치, 남은 문제 | [피드백](roles/feedback.md), [수정](roles/revision.md) |

이미 `plan.md`, `review.md`, `feedback.md`로 나뉜 기록은 유지한다. 작은 후속 수정마다 파일을 더 만들지 않는다.
반복해서 참조할 독립 계약이 생기면 `docs/specs/`로 분리한다. 작업별 JSON·캡처는 그 작업의 `evidence/`에 둔다.
문서 구조 변경처럼 파일 이동 근거가 필요하면 해당 작업 기록에 이동 표를 적는다. 현재 문서의 사본을 매번 만들지 않는다.

## 작업을 끝낼 때

1. 변경한 문장에 [작성 원칙](writing.md)을 적용한다.
2. 문서 구조와 링크를 검사한다.
3. 관련 기능이 바뀌었으면 필요한 기능 검사를 실행한다.
4. 작업 기록에 완료 범위와 미해결 문제를 적는다.
5. 상태가 바뀌었으면 `worklog/progress.md`를 갱신한다.
6. 결정이나 용어가 바뀌었으면 해당 기준 문서만 갱신한다.
7. 완료한 작업 주기는 `worklog/history/YYYY-MM.md`에 한 항목으로 기록한다.

월별 이력에는 결과 한 문장과 상세 기록 링크를 적는다. 수치·검사 결과·미정 사항을 모든 문서에 복사하지 않는다.
문서 작업만 했으면 앱 구현을 완료로 표시하지 않는다. 빌드·린트는 사용자 요청 없이 자동 실행하지 않는다.

## 정정과 보관

- 미확정 항목에는 `[스펙 미확정]`을 붙인다.
- 원래 제안의 채택 근거가 없으면 제안으로 기록한다.
- 과거 이력은 정정 날짜와 근거를 덧붙인다.
- 대체된 설계는 보관하지 않고 삭제한다. 이전 내용은 git 이력에서 찾는다.
- 완료했지만 유효한 구현 근거는 해당 `worklog/records/` 폴더에 남긴다.
- 파일을 이동하면 문서 링크와 코드 주석의 참조 경로를 함께 갱신한다.

검사는 저장소 루트에서 실행한다.

```text
node scripts/check-docs.cjs
git diff --check
```

## 판단 근거를 남기는 방법

[Platty 동작 원리](https://github.com/paradigmshift-labs/platty/blob/main/guide/ko/how-platty-works.md)는 이유·정정·제약·맥락을 관련 대상에 연결한다. 출처와 확정 여부도 보존한다. 이 프로젝트는 이 원칙을 파일 기록에 적용한다. Platty를 설치하거나 자동 분석을 연결한 상태는 아니다.

관련 작업 기록에 아래 정보를 함께 적는다. 별도 메모 파일은 기본으로 만들지 않는다.

| 항목 | 기록 방법 |
|---|---|
| 대상 | 관련 기능 계약의 절이나 코드 경로를 연결한다. |
| 내용 | 판단 이유, 사용자 정정, 제약 또는 배경을 적는다. |
| 출처 | 발언 날짜·대화 링크·코드·검수 결과를 적는다. |
| 확정 여부 | 확인한 사실과 `[스펙 미확정]` 제안을 구분한다. |
| 후속 정정 | 이전 기록을 지우지 않고 정정 날짜와 근거를 추가한다. |

근거는 작업 기록에 남기고, 공개 기능 계약에는 링크하지 않는다. 이후 수정자는 내용을 바꾸기 전에 로컬의 작업 기록을 읽는다. 근거가 없으면 이유를 추정해서 채우지 않는다.
