# 기술 문서 작성 원칙

## 적용 범위

ASD-STE100은 영어 기술 문서를 위한 통제 언어다. 작성 규칙과 사전으로 구성된다. 한국어 문서는 아래 프로젝트 원칙을 적용한다. 한국어 문서의 공식 ASD-STE100 준수를 주장하지 않는다. [공식 설명](https://www.asd-ste100.org/about.html)을 참고한다.

한 문장에 한 지시를 쓰고, 조건을 먼저 제시하는 원칙은 [공식 Issue 9의 절차 작성 규칙](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf)을 참고했다. 아래의 근거 관리와 기록 위치 규칙은 이 프로젝트의 규칙이다.

현재 기준 문서와 새 작업 기록에 적용한다. 과거 이력·인용·코드·명령·JSON 값은 문체를 맞추려고 바꾸지 않는다. 루트와 확장의 README는 제품 소개 문체를 유지한다. 설명서([guide.md](../guide.md))는 사용자에게 말하는 '-요'체로 쓴다(2026-10-24 사용자 결정 "다 보단 요 체로"). 표 칸과 목록의 명사형 끝맺음은 그대로 둔다. 기능 사실과 명칭은 같은 근거를 사용한다.

## 문장

- 한 문장에 한 사실이나 한 지시를 쓴다.
- 조건이 있으면 조건을 먼저 쓴다.
- 행동의 주체와 대상을 적는다.
- 절차에서는 실행할 동사를 쓴다.
- 한 문단에는 한 주제만 적는다.
- 서로 다른 검사나 결과를 가운데점으로 길게 연결하지 않는다.
- 같은 기능에는 같은 명칭을 사용한다. 화면 명칭은 [명칭 사전](../terms.md)을 따른다.
- 경로·명령·필드·노드 ID는 원래 식별자를 사용한다.
- 근거 없는 강조와 모호한 정도 표현을 지운다.
- 날짜는 `YYYY-MM-DD`로 쓴다.

한국어 문장에 영어 단어 수 제한을 기계적으로 적용하지 않는다. 의미를 읽고 분리할 지점을 판단한다.

## 근거와 상태

| 쓸 내용 | 필요한 근거 |
|---|---|
| 사용자 결정 | 직접 발언이나 확인 가능한 대화 링크 |
| 구현 완료 | 구현 위치와 해당 검증 결과 |
| 검수 통과 | 실제 실행한 명령 또는 관측 방법과 검사 범위 |
| 제안 | `[스펙 미확정]`과 아직 정하지 않은 내용 |
| 과거 결과 | 검사 날짜와 당시 적용 범위 |

코드에 기능이 있다는 이유로 사용자 결정이라고 쓰지 않는다. 파일이 있다는 이유로 구현 완료라고 쓰지 않는다.
`완료` 앞에는 완료한 범위를 적는다. 실행하지 않은 검사는 `미실행`으로 적는다.

## 수정 예시

| 수정 전 | 수정 후 |
|---|---|
| 잘 정리했고 전부 검수했다. | 문서 파일을 이동했다. 상대 링크 검사에서 누락이 없었다. |
| 버튼·모달·스크롤·저장 처리가 완료됐다. | 모달의 중앙 정렬을 확인했다. 스크롤 연결은 없다. 저장 처리는 미구현이다. |
| 대상과 재고를 바꾸고 실패하면 복원한다. | 저장에 실패하면 대상 상태를 복원한다. 재고도 복원한다. |

## 완료 전 의미 검수

변경한 문장을 읽고 아래 항목을 확인한다. 결과는 해당 작업 기록의 검수 절에 적는다.

- 문장 하나에 서로 다른 사실이나 행동을 묶지 않았는가?
- 조건·주체·대상을 문장만으로 알 수 있는가?
- 사용자 결정·관측 사실·제안의 근거를 구분했는가?
- 같은 개념에 같은 명칭을 사용했는가?
- 완료 범위와 미실행 검사를 구분했는가?
- 같은 사실을 여러 문서에 복사하지 않고 원본으로 연결했는가?

`node scripts/check-docs.cjs`는 구조·파일 링크·JSON 구문을 검사한다. 이 의미 검수를 대신하지 않는다.
