# pokebuddy 현재 설계

갱신: 2026-09-25. 실제 앱은 S5 새 게임 규칙을 저장 v3 로 돌린다. 남은 화면과 기능은 [작업 후보](progress.md#작업-후보)를 따른다. 번호의 뜻은 [번호 체계](terms.md#번호-체계)를 따른다.

이 문서는 채택한 결정을 기록한다. 구현 상태는 [진행 현황](progress.md)을 따른다. S5 기능 계약은 [S5 기능 계약](specs/s5.md)을 따른다.
확정한 결정을 사용 순서로 연결한 [사용자 시나리오](specs/s5-scenarios.md)를 작성했다. 화면 역할과 예외 처리의 새 제안은 확정 결정과 구분한다.
정리 이전의 결정과 예시는 [설계 보관본](archive/s5-legacy/design-before-v2-cleanup.md)에 보존했다. 과거 시안의 값은 현재 구현 규칙을 덮어쓰지 않는다.

## 제품 목적

2026-09-21 사용자 설명을 기준으로 한다. 출처와 재설계 범위는 [제품 목적 재확인](work/s5-design-system-v2/plan.md#제품-목적부터-재검토)에 기록한다.

- 사용자는 컴퓨터를 켠 직후 앱을 켜고 싶어 한다.
- 사용자는 PC에서 자유롭게 노는 포켓몬을 구경한다.
- 게임은 눈에 보이는 방치형 게임의 느낌을 제공한다.
- 사용자는 포켓몬을 조금씩 직접 돌본다.
- 게임은 일하는 중 잠깐 쉬어 가는 경험을 제공한다.
- 돌보지 않는 동안 배고픔 같은 상태가 변한다. 사용자는 나중에 조금 챙겨준다.

사용자는 50분 작업과 10분 휴식을 짧은 리프레시의 예시로 들었다. 고정 타이머, 돌봄 주기, 플레이 시간은 아직 정하지 않았다.
상태 변화의 속도와 상한은 아직 정하지 않았다. 앱을 다시 켜면 종료한 상태에서 이어간다. 종료 중에는 게임 상태를 진행하지 않는다.
PC 잠금·절전·앱 종료 중에는 배고픔·친밀도·포인트·버프 시간·알 준비 시간·먹이 쿨타임을 멈춘다. 값과 부분 진행을 보존하고 복귀 후 이어간다. 설정창만 닫거나 포켓몬을 숨긴 상태에서는 기존 파티·박스 규칙대로 진행한다. 상세 기준은 [실행 상태별 시간](specs/s5.md#실행-상태별-시간)을 따른다.

### 돌봄을 알리는 원칙

화면에 보이는 포켓몬은 배고픔이 높은 구간에서 작은 말풍선이나 행동으로 먼저 표현한다. 사용자는 돌봄 시점을 선택한다. 알림은 돌봄을 강제하지 않는다.
숨겨진 포켓몬의 배고픔은 파티창의 상태 표시로만 확인한다. 배고픔 때문에 숨김을 해제하거나 창을 자동으로 열지 않는다. 근거는 [숨김 개체의 배고픔 상태 표시](work/s5-design-system-v2/plan.md#숨김-개체의-배고픔-상태-표시)를 따른다.
사용자는 5단계 중 4·5단계에서 알리는 예시를 제시했다. 나머지 구간에서는 사용자가 구경하다가 자발적으로 돌본다.
보이는 포켓몬이 배고픔 알림 구간에 진입하면 말풍선을 한 번 표시한다. 같은 구간에서는 말풍선을 반복하지 않고 가끔 배고픈 행동을 한다. 더 심한 구간에 진입하면 말풍선을 다시 한 번 표시한다. 근거는 [배고픔 표현 반복 정책](work/s5-design-system-v2/plan.md#배고픔-말풍선과-행동의-반복-정책)을 따른다.
단계 수와 수치 경계는 아직 확정하지 않았다. 행동 간격과 여러 포켓몬의 동시 표현도 아직 정하지 않았다.
출처와 세부 제안은 [배고픔 표현 설계](work/s5-design-system-v2/plan.md#배고픔-표현과-선택적인-돌봄)를 따른다.

### 상태 알림 배너

부화 준비 완료는 알별로 알린다. 진화 가능은 개체별로 알린다. 업적 달성은 업적별로 알린다. 같은 종류의 알림도 묶지 않는다. 배너는 한 번에 하나씩 순차 표시한다. 상세 계약은 [알림 배너의 개별 표시](specs/s5.md#알림-배너의-개별-표시)를 따른다.
배너 알림 소리는 기본으로 켠다. 설정에서 무음으로 전환할 수 있다. 소리는 사용하는 OS의 기본 시스템 알림음을 사용한다. 근거는 [알림 소리 정정](work/s5-design-system-v2/plan.md#기본-알림-소리와-os-시스템-알림음)을 따른다.
한 번 표시한 부화·진화·업적 배너는 같은 미처리 상태를 다시 알리지 않는다. 앱을 다시 켜도 반복하지 않는다. 해당 메뉴의 부화 가능·진화 가능·업적 미수령 상태는 유지한다. 근거는 [상태 알림 반복 금지](work/s5-design-system-v2/plan.md#표시한-상태-알림의-반복-금지)를 따른다.
기다리는 동안 대상이 더 이상 미처리 상태가 아니면 그 배너를 표시하지 않는다. 표시 전에 앱이 종료된 배너는 재실행 후 이어서 표시한다. 표시 중에 앱이 종료된 배너는 표시한 것으로 처리한다. 근거는 [대기 배너 처리](work/s5-design-system-v2/plan.md#대기-배너의-무효화와-재실행-처리)를 따른다.
여러 배너가 기다리면 먼저 생긴 배너부터 표시한다. 같은 순간이면 부화 → 진화 → 업적 순서를 따른다. 같은 종류는 화면의 목록 순서를 따른다. 근거는 [배너 표시 순서](work/s5-design-system-v2/plan.md#배너-동시-발생의-표시-순서)를 따른다.

### 배고픔 상태 디버프

배고픔 상태 디버프는 새로 얻는 친밀도 증가량을 조금 줄인다. 이미 쌓인 친밀도는 줄이지 않는다.
사용자가 제시한 기본 1배와 디버프 0.8배는 예시다. 실제 배율은 아직 정하지 않았다.
적용할 배고픔 구간과 친밀도 획득 경로는 아직 정하지 않았다. 해제 조건도 아직 정하지 않았다.
알림을 표시하는 조건과 디버프를 적용하는 조건을 같은 것으로 확정하지 않는다.
근거는 [배고픔 디버프 후속 결정](work/s5-design-system-v2/plan.md#배고픔-상태-디버프)에 있다. 현재 구현의 효과는 이번 설계에서 재검증하지 않았다.

### 친밀도 획득과 확장 후보

사용자는 함께 켜 두는 시간에 친밀도를 얻는 방식을 확인했다. 밥 주기와 놀아주기는 추가 친밀도를 제공한다.
던전 탐험은 향후 확장 구상이다. 추가할 때 경험사탕 5종과 이상한사탕, 경험치를 얻는 경로로 사용한다. 구체적인 탐험 규칙과 구현 시점은 미정이다.
사용자는 에이전트 사용에 별도의 추가 이득을 주는 방향을 선택했다. 기본 보상과 에이전트 보상이 같은 보너스 한도를 공유하는 안은 채택하지 않는다.
선택 이유: 사용자는 한도를 채운 뒤 앱을 끄게 되는 경험을 우려했다. 추가 보상의 크기와 계산 방식은 아직 정하지 않았다.
기존 친밀도·포인트 상한 각각의 처리 여부는 아직 정하지 않았다. 이번 결정만으로 기존 상한 전체를 삭제하지 않는다.
현재 구현 관측과 밸런스 제안은 [친밀도 획득과 에이전트 보상](work/s5-design-system-v2/plan.md#친밀도-획득과-에이전트-보상)을 따른다.

사용자는 “자동기능은 없고”라고 설명했다. 2026-09-22 확인: 자동기능 없음은 게임 진행을 대신 해 주는 기능이 없다는 뜻이다. 자동 먹이, 자동 부화, 자동 진화, 자동 보상 수령, 자동 교체를 제공하지 않는다. 로그인 시 시작 같은 앱 실행 편의 기능은 이 범위에 포함하지 않는다. 근거는 [자동기능 없음의 범위](work/s5-design-system-v2/plan.md#자동기능-없음의-범위)를 따른다.
2026-09-22 결정: 설정 일반의 `로그인 시 시작` 항목은 기본값을 켜짐으로 둔다. 사용자는 설정에서 끌 수 있다. 근거는 [로그인 시 시작 기본값](work/s5-design-system-v2/plan.md#로그인-시-시작의-기본값-켜짐)을 따른다.
아래 기존 기능 결정이 이 목적에 적합한지는 재검토한다. 이번 목적 정의는 기존 기능의 삭제 지시가 아니다.

## 놀이공간과 직접 돌봄

사용자는 화면 전체에서 포켓몬이 자유롭게 활동하는 옵션을 원한다. 사용자가 활동 영역을 지정하는 옵션도 제공한다.
첫 사용은 화면 전체에서 시작한다. 튜토리얼에서 놀이공간을 바꿀 수 있음을 알려준다. 놀이공간 튜토리얼은 첫 돌봄 튜토리얼을 마치거나 스킵하면 시작한다. 근거는 [놀이공간 튜토리얼 시작](work/s5-design-system-v2/plan.md#놀이공간-튜토리얼의-시작-계기)을 따른다.
튜토리얼에서 밥 주기와 놀아주기를 직접 해본다. 스킵하거나 닫으면 해당 튜토리얼을 다시 보여주지 않는다. 튜토리얼 다시보기는 제공하지 않는다. 이후 사용법은 가이드북에서 확인한다. 놀이공간 변경은 화면 설명으로 알려준다. 튜토리얼에서 실제 영역 변경을 요구하지 않는다.
시작 포인트로 상점에서 랜덤알을 구매하도록 알려준다. 부화한 두 번째 포켓몬은 처음에 숨긴 상태로 파티에 들어간다. 사용자가 파티창에서 꺼내며 표시 조작을 익힌다. 이후 첫 업적 배너의 `바로가기`로 업적창에 가서 보상을 받는 흐름이다.
시작 포인트는 다른 상품에도 사용할 수 있다. 랜덤알 구매를 강제하지 않는다. 다른 곳에 사용해도 일반 게임 진행을 막지 않는다.
튜토리얼은 기능별 단계로 나눈다. 사용자가 해당 행동을 했을 때 관련 튜토리얼을 시작한다. 시작 포인트를 다른 곳에 썼다가 나중에 알을 구매하면 그때 부화 튜토리얼을 시작한다.
한 단계의 지연 때문에 다른 기능의 사용을 막지 않는다. 단계별 진행과 재개 규칙은 [행동에 따른 단계별 튜토리얼](specs/s5.md#행동에-따른-단계별-튜토리얼)를 따른다.
파티 튜토리얼은 첫 포켓몬과 다른 개체를 처음 획득했을 때 시작한다. 종이나 숨김 여부를 시작 조건으로 사용하지 않는다. 근거는 [파티와 업적 튜토리얼의 시작 조건](work/s5-design-system-v2/plan.md#파티와-업적-안내의-시작-조건)을 따른다. 업적 튜토리얼은 2026-09-22에 제거했다. 업적 이용은 업적 배너와 업적창으로 익힌다. 근거는 [업적 튜토리얼 제거](work/s5-design-system-v2/plan.md#업적-배너의-바로가기와-업적-안내-제거)를 따른다.
튜토리얼을 건너뛰어도 동일한 시작 포인트를 한 번 지급한다. 가이드북 열람으로 포인트를 지급하지 않는다. 지급량은 미정이다.
업적은 조건 달성과 보상 수령을 구분한다. 업적창에서 보상을 받아야 칸을 연다. 자동으로 칸을 여는 제안은 채택하지 않는다.
각 업적의 보상은 한 번만 받는다. 받지 않은 보상은 창 닫기와 앱 재실행 후에도 미수령 상태로 남는다. 수령 기한은 두지 않는다. 반복형 업적이 필요하면 별도 종류로 나중에 설계한다. 근거는 [1회 수령과 미수령 유지](work/s5-design-system-v2/plan.md#업적-보상의-1회-수령과-미수령-유지)를 따른다.
여러 튜토리얼은 하나씩 보여준다. 진행 중인 튜토리얼을 마치거나 건너뛰면 다음 튜토리얼을 보여준다. 화면을 강제로 전환하지 않는다. 닫기는 해당 튜토리얼의 스킵으로 처리한다. 닫은 튜토리얼을 재개하지 않는다. 근거는 [튜토리얼 닫기와 가이드북](work/s5-design-system-v2/plan.md#튜토리얼-닫기와-가이드북)을 따른다.
진행 중인 튜토리얼이 앱 종료로 끊기면 스킵으로 처리하지 않는다. 재실행 후 그 튜토리얼을 처음부터 다시 보여준다.
여러 튜토리얼 조건이 생기면 먼저 생긴 조건부터 보여준다. 같은 순간이면 첫 돌봄 → 상점 → 부화 → 파티 → 놀이공간 순서를 따른다. 표시 전에 앱이 종료된 대기 튜토리얼은 재실행 후 같은 규칙으로 보여준다. 근거는 [동시 튜토리얼 순서](work/s5-design-system-v2/plan.md#동시-안내-조건의-발생-순서와-흐름-우선순위)를 따른다. 근거는 [끊긴 튜토리얼의 재표시](work/s5-design-system-v2/plan.md#앱-종료로-끊긴-안내의-처음부터-재표시)를 따른다.
튜토리얼 구매와 업적 수령의 상세 흐름은 [첫 구매와 업적 보상 수령](specs/s5.md#첫-구매와-업적-보상-수령)을 따른다.
첫 선택 후보는 별도 목록으로 지정한다. 사용자는 그 안에서 원하는 진화 전 포켓몬을 자유롭게 고른다. 사용자가 확인한 예시는 리자몽을 원할 때 파이리부터 시작하는 것이다.
첫 선택 후보는 모두 처음부터 도감에 해금한다. 해금만으로 개체를 지급하지 않는다. 초기 랜덤알은 첫 선택 후보 중 알 입수가 허용된 종을 대상으로 한다. 종별 전용 입수처는 유지한다.
시작 포인트는 랜덤알 하나를 구매할 수 있는 금액으로 지급한다. 다른 상품에도 사용할 수 있다. 실제 후보 종과 가격·확률은 미정이다. 근거는 [초기 해금과 첫 알 구매](work/s5-design-system-v2/plan.md#초기-해금과-첫-알-구매)를 따른다.
모든 해금 종을 첫 선택 후보로 자동 포함하지 않는다. 첫 선택 목록의 근거는 [첫 선택 후보 목록](work/s5-design-system-v2/plan.md#첫-선택-후보-목록)을 따른다.
이후 획득은 랜덤·구매·해금 경로로 설계한다. 각 경로의 조건과 제공 방식은 미정이다.
첫 선택과 성장의 근거는 [첫 포켓몬과 이후 획득](work/s5-design-system-v2/plan.md#첫-포켓몬과-이후-획득)을 따른다.
영역 드래그는 사용자가 제안한 지정 방식이다. 구체적인 조작은 아직 정하지 않았다.
화면 용어는 사용자가 사용한 `놀이공간`을 기준으로 정리한다. 내부 `stage` 식별자는 유지한다.
돌봄은 클릭 한 번으로 시작한다. 사용자는 반응을 구경한다. 원하면 더 놀아줄 수 있다.
반복해서 놀아주면 다양한 반응을 볼 수 있는 방향이다. 2026-09-22 결정: 오래 놀아주기 버프와 장난감을 채택한다. 2026-09-24 에 버프가 켜지는 조건을 바꿨다. 놀아주면 놀아주기 상태가 20분 붙는다. 이 상태 자체에는 효과가 없다. 놀아주기 쿨타임은 10분이다. 쿨타임이 지난 뒤 상태가 남은 10분 안에 다시 놀아주면 중첩이 오른다. 3중첩이 되면 오래 놀아주기 버프가 켜진다. 상태가 끝나면 중첩은 0으로 돌아간다. 근거는 [돌봄 명령](work/s5-design-system-v2/plan.md#돌봄-명령)을 따른다. 장난감 놀이는 일반 놀아주기와 같은 반응 애니메이션에 파티클 같은 효과를 더한다. 근거는 [오래 놀아주기와 장난감](work/s5-design-system-v2/plan.md#오래-놀아주기-버프와-장난감-채택)을 따른다. 오래 놀아주기 버프는 놀아준 한 마리의 친밀도 증가량을 일정 시간 높인다. 효과는 프리미엄먹이 버프보다 낮다. 장난감은 1회성이며 한 번 놀아주면 1개를 소비한다. 근거는 [버프 효과와 1회성 장난감](work/s5-design-system-v2/plan.md#오래-놀아주기-버프-효과와-1회성-장난감)을 따른다. 장난감은 가방에서 드래그해 포켓몬 위에 드롭하여 사용한다. 장난감을 사용하면 오래 놀아주기 버프와 같은 버프를 준다. 근거는 [장난감의 드래그 사용](work/s5-design-system-v2/plan.md#장난감의-드래그-사용과-같은-버프)을 따른다.
기본먹이는 무료로 무제한 제공한다. 만복도 회복 효율은 매우 낮게 설정한다. 실제 회복량은 미정이다. 근거는 [기본먹이 제공과 효율](work/s5-design-system-v2/plan.md#기본먹이-무제한-제공과-낮은-회복-효율)을 따른다. 상점에서 구매하는 프리미엄먹이는 일정 시간 친밀도 증가량을 높인다.
기본먹이는 만복도를 일정량 회복한다. 밥 주기 자체에 쿨타임을 적용한다. 만복도가 최대이거나 쿨타임 중이면 먹일 수 없다. 쿨타임은 개체별로 적용한다. 같은 개체의 기본먹이와 프리미엄먹이가 쿨타임을 공유한다. 다른 개체의 밥 주기는 막지 않는다. 쿨타임은 파티의 숨김 상태에서도 진행한다. 박스 보관 중에는 남은 시간을 보존한다. 복귀하면 남은 시간부터 이어간다. 길이는 미정이다. 근거는 [개체별 먹이 공통 쿨타임](work/s5-design-system-v2/plan.md#개체별-먹이-공통-쿨타임)을 따른다. 근거는 [기본먹이 회복과 쿨타임](work/s5-design-system-v2/plan.md#기본먹이-일정량-회복과-밥-주기-쿨타임)을 따른다.
기본먹이를 여러 번 주면 배고픔에서 서서히 회복할 수 있다. 쿨타임과 자연 감소를 고려해 회복 가능한 수치로 설계한다. 상세 기준은 [일상 사용 계약](specs/s5.md#일상-사용-계약)을 따른다.
프리미엄먹이 버프는 먹이를 준 한 마리에게만 적용한다.
먹이 사용은 만복도를 기준으로 한다. 만복도가 최대이면 기본먹이와 프리미엄먹이를 줄 수 없다. 프리미엄먹이는 만복도를 최대까지 채운다. 같은 먹이를 다시 주면 버프 시간을 기본 지속시간으로 갱신한다. 남은 시간을 더하지 않는다. 근거는 [만복도와 버프 갱신](work/s5-design-system-v2/plan.md#만복도와-프리미엄먹이-버프-갱신)을 따른다.
만복도는 높을수록 배부른 수치다. 기존 배고픔 상태와 별개의 자원을 추가하지 않는다. 아래 S3 구현의 배고픔 값은 기존 코드 설명이며 만복도 변환식은 아직 정하지 않았다.
`규토리`는 이름 후보다. `1.1배`는 예시 배율이다. 효과의 지속시간과 적용할 친밀도 획득 경로는 미정이다.
상세 계약과 미정 항목은 [일상 사용 계약](specs/s5.md#일상-사용-계약)을 따른다. 정정 근거는 [놀이공간·돌봄·재개 결정](work/s5-design-system-v2/plan.md#놀이공간-돌봄-재개-결정)에 있다.

| 겹침 | 겹침을 허용한다. 나중에 소환한 마리를 앞에 그린다. 드래그와 모습 변경은 순서를 바꾸지 않는다. |
| 숨김 | 숨겨도 파티 배치와 육성을 유지한다. 다시 표시하면 마지막에 그린다. 재시작하면 저장된 파티 순서로 그린다. |
| 여러 창 | [스펙 미확정] 현재는 창마다 같은 파티를 표시한다. 창별 파티 배분은 별도 설계가 필요하다. |

## 성격과 육성

원작 25개 성격을 사용한다. 성격은 다섯 축으로 움직임과 상태에 영향을 준다. 값과 명칭은 [성격 자료](../data/natures.json)를 따른다. 움직임 배율은 [params.ts](../src/motion/params.ts)를 따른다.
S3 육성(옛 규칙)은 2026-09-25 에 코드에서 걷었다. 지금 육성은 S5 규칙이다. S2 당시의 적립 중단 기록은 현재 규칙이 아니다.
친밀도는 감소하지 않는다. 배고픔과 기분은 변한다. 숨긴 파티 포켓몬도 육성을 유지한다.

아래 표는 v2 의 규칙이다. 2026-09-24 부터 실제 앱은 v3 규칙을 쓴다. v3 값은 [밸런스 수치](specs/balance.md)를 따른다. v3 의 에이전트 보상은 토큰이 아니라 작업 시간으로 적립 속도를 2배로 만든다.

| v2 중립 규칙 | 값 |
|---|---|
| 켜 두기 | 시간당 친밀도 +6 |
| 토큰 적립 | 1,000토큰당 친밀도 +1 |
| 토큰 미지원 작업 | 시간당 친밀도 +12 |
| 하루 친밀도 상한 | 마리별 200 |
| 토큰 포인트 | 10,000토큰당 +1 |
| 하루 포인트 상한 | 50 |
| 배고픔 | 시간당 +10 |
| 밥 주기 | 배고픔 −40 |

v2 규칙의 구현 검수는 [S3 검수](work/s3/review.md)에 있다. 지금 계산은 [시간 처리](../src/state/time.ts)와 [규칙표](../src/save/rules.ts)를 따른다. Figma의 친밀도 100 예시는 런타임 상한 변경의 근거가 아니다.

## 도감 · 해금

2026-09-21 후속 결정: 진화 조건을 충족하면 진화 가능 상태를 알린다. 사용자가 원할 때 직접 진화시킨다.
진화는 한 번에 다음 한 단계로만 진행한다. 다음 단계 조건도 이미 충족했다면 사용자가 다시 선택해 진화할 수 있다. 중간 단계를 건너뛰거나 자동으로 연속 진화하지 않는다. 현재 단계에 머무를 수 있다. 근거는 [단계별 직접 진화](work/s5-design-system-v2/plan.md#단계별-직접-진화)를 따른다.
여러 진화 분기가 가능하면 사용자가 후보 중에서 선택한다. 리전폼 진화 조건을 충족하면 해당 경로에서는 지정한 리전폼으로 진화한다. 해당 조건이 없고 일반 조건을 충족하면 일반 폼으로 진화한다. 같은 경로의 폼을 임의로 선택하지 않는다. 근거는 [분기 진화와 리전폼 조건](work/s5-design-system-v2/plan.md#분기-진화-선택과-리전폼-조건)을 따른다.
진화 결과는 실제 진화 실행 시점의 조건으로 판단한다. 알림 시점에 고정하지 않는다. 실행 전에 결과 종과 폼을 보여주고 사용자 확인을 받는다. 근거는 [조건 판정과 결과 확인](work/s5-design-system-v2/plan.md#진화-실행-시-조건-판정과-결과-확인)을 따른다.
진화 가능과 업적 달성은 화면 한쪽의 작은 배너로 잠깐 알린다. 클릭하지 않으면 배너는 사라진다. 진화 배너는 해당 개체의 상세 화면으로 연결한다. 업적 배너는 `업적 달성` 제목, 업적 표시와 이름, `바로가기` 버튼으로 구성한다. `바로가기`를 누르면 해당 업적의 보상 수령 화면으로 이동한다. 근거는 [업적 배너의 바로가기](work/s5-design-system-v2/plan.md#업적-배너의-바로가기와-업적-안내-제거)를 따른다. 업적 배너는 화면 우측 아래에 한 번 표시한다. 미수령 보상이 있으면 헤더의 업적창 아이콘에 dot를 표시한다. 근거는 [우측 아래 표시와 dot](work/s5-design-system-v2/plan.md#업적-알림의-우측-아래-표시와-업적창-dot)를 따른다. 진화와 보상 수령은 별도로 직접 진행한다. 근거는 [진화와 업적의 배너 알림](work/s5-design-system-v2/plan.md#진화와-업적의-배너-알림)을 따른다.
2026-09-21 후속 방향: 친밀도를 개체별로 관리한다. 일반 개체의 완료한 진화는 이전 단계로 되돌리지 않는다. 지정한 단일 포켓몬 진화 계열은 아래 공유 `sid` 예외를 따른다. 같은 개체의 진화 단계를 자유롭게 바꾸는 제안은 철회한다.
진화 후에도 개체 ID, 친밀도, 성격, 레벨, 누적 경험치를 유지한다. 만복도와 남은 버프·먹이 쿨타임을 유지한다. 파티·박스 위치와 숨김 상태도 유지한다. 근거는 [진화 시 개체 정보 유지](work/s5-design-system-v2/plan.md#진화-시-개체-정보-유지)를 따른다.
단일 포켓몬 진화의 후속 예외: 전설·환상·준전설 등 지정한 진화 계열은 같은 `sid`의 한 개체로 관리한다. 친밀도·레벨 등 진행 상태를 공유한다. 새 개체 ID 발급과 독립 개체 지급은 철회한다. 선택 가능한 종 중 하나만 꺼낼 수 있다. 스탯은 현재 선택한 종의 기준을 적용한다. 단일 포켓몬 전용 재획득 불가 경고는 추가하지 않는다. 일반 진화는 기존 철회 불가 규칙을 유지한다. 근거는 [공유 sid 정정](work/s5-design-system-v2/plan.md#단일-포켓몬-진화-계열의-공유-sid-정정)을 따른다.
코스모움 두 개체 획득 구상은 채택하지 않았다. 기존 공유 개체와 두 종 동시 제공 규칙을 유지한다. 근거는 [기존안 유지 결정](work/s5-design-system-v2/plan.md#코스모움-기존-공유-개체안-유지)을 따른다.
코스모움에서 한 번 진화하면 솔가레오와 루나아라를 함께 제공한다. 둘 다 같은 `sid`의 교체 가능한 종으로 열린다. 각 종을 얻기 위해 따로 진화를 반복하지 않는다. 동시에 꺼낼 수 있는 종은 하나다. 게임 시간의 낮에 진화하면 현재 종은 솔가레오가 된다. 밤이면 루나아라가 된다. 진화할 종을 따로 선택하지 않는다. 게임 시간 기능은 향후 구현한다. 네크로즈마는 이 공유 `sid` 계열과 별개인 포켓몬이다. 근거는 [게임 시간에 따른 결과](work/s5-design-system-v2/plan.md#게임-시간에-따른-솔가레오와-루나아라-진화-결과)를 따른다. 동시 제공의 근거는 [동시 제공 정정](work/s5-design-system-v2/plan.md#솔가레오와-루나아라의-동시-제공-정정)을 따른다.
솔가레오와 루나아라를 함께 제공하는 순간 도감에 두 종 모두 획득한 것으로 기록한다. 아직 꺼내지 않은 종도 포함한다. 공유 `sid` 하나와 도감의 두 종 기록을 구분한다. 근거는 [동시 획득 기록](work/s5-design-system-v2/plan.md#솔가레오와-루나아라의-도감-동시-획득-기록)을 따른다.
해당 계열의 종 선택은 박스에서 교체하는 흐름으로 제공한다. 파티에 같은 `sid`가 있으면 기존 칸의 종을 교체한다. 빈칸이 있어도 추가 칸을 차지하지 않는다. 교체 후에는 기존 박스 교체 규칙대로 숨김 상태로 둔다. 근거는 [파티 칸 유지 결정](work/s5-design-system-v2/plan.md#공유-sid-종-교체의-기존-파티-칸-유지)을 따른다. 상세 화면에서 종을 선택하는 제안은 채택하지 않는다. 근거는 [박스 교체 결정](work/s5-design-system-v2/plan.md#공유-sid-진화-계열의-박스-교체-흐름)을 따른다.
도감 해금에는 개별 포켓몬의 레벨을 사용한다. 종마다 입수처를 구분한다. 구매 가능한 종은 해금 후 상점 구매 항목에 추가한다. 진화 전용 종은 상점에 추가하지 않는다.
사용자 예시: 파이리 레벨 16에서 리자드를 해금한다. 리자드는 파이리를 진화시켜서만 얻는다. 종별 최종 조건표는 아직 정하지 않았다.
친밀도와 경험치는 별도로 관리한다. 경험치로 개체의 레벨이 오른다. 현재 재설계에서는 친밀도를 통해 포인트를 얻고 상점에서 경험사탕을 구매해 레벨을 올린다.
경험사탕은 XS·S·M·L·XL 5종으로 구성한다. 별도 도구인 이상한사탕은 개체 레벨을 1 올린다. 새 레벨의 경험치 진행은 0부터 시작한다. 근거는 [이상한사탕 경험치 정정](work/s5-design-system-v2/plan.md#이상한사탕의-다음-레벨-경험치-초기화)을 따른다. 개체 레벨 상한 100은 유지한다. 100레벨에서는 이상한사탕을 사용할 수 없고 소비하지 않는다. 근거는 [이상한사탕 상한 결정](work/s5-design-system-v2/plan.md#이상한사탕의-100레벨-사용-차단)을 따른다. 효과량과 가격 등 미정 사항은 [사탕 구성 결정](work/s5-design-system-v2/plan.md#경험사탕-5종과-이상한사탕-및-이미지-조사)에 기록한다.
개체의 최대 레벨은 100이다. 최대 레벨에서도 친밀도 성장과 포인트 적립은 기존 규칙대로 계속한다. 근거는 [개체 레벨 상한](work/s5-design-system-v2/plan.md#개체-레벨-상한-100)을 따른다.
경험사탕XS·S·M·L·XL과 이상한사탕은 모두 상점 구매, 업적 보상, 탐험 보상으로 얻는다. 탐험은 향후 확장이다. 근거는 [공통 입수 경로](work/s5-design-system-v2/plan.md#사탕-공통-입수-경로)를 따른다.
사탕 6종은 처음부터 상점에서 판매한다. 별도 해금 조건을 두지 않는다. 가격으로 구매 시점을 조절한다. 실제 가격과 보상표는 미정이다. 근거는 [초기 상점 판매](work/s5-design-system-v2/plan.md#사탕-전종의-초기-상점-판매)를 따른다.
이상한사탕은 한 개체와 사용 수량을 선택한다. 예상 레벨을 확인한 뒤 여러 개를 한 번에 사용할 수 있다. 최대 선택 수량은 보유량과 `100 - 현재 레벨` 중 작은 값이다. 근거는 [수량 선택 결정](work/s5-design-system-v2/plan.md#이상한사탕-수량-선택과-세션-인계)을 따른다.
이상한사탕도 파티와 박스의 보유 개체 모두에게 직접 사용할 수 있다. 숨김 여부로 제한하지 않는다. 사용으로 배치·표시 상태를 바꾸지 않는다. 근거는 [이상한사탕 대상 결정](work/s5-design-system-v2/plan.md#이상한사탕의-파티와-박스-대상-허용)을 따른다.
경험사탕은 파티와 박스의 보유 개체 모두에게 직접 사용할 수 있다. 숨김 상태여도 사용할 수 있다. 사탕 사용을 위해 배치나 표시 상태를 바꾸지 않는다. 박스의 시간에 따른 성장 정지는 유지한다. 근거는 [경험사탕의 대상 범위](work/s5-design-system-v2/plan.md#경험사탕의-파티와-박스-대상-허용)를 따른다.
경험사탕은 대상 한 개체와 사용 수량을 선택한다. 여러 개를 한 번에 사용할 수 있다. 획득 경험치와 예상 레벨을 확인한 뒤 사용한다. 근거는 [수량 선택과 결과 미리보기](work/s5-design-system-v2/plan.md#경험사탕-수량-선택과-결과-미리보기)를 따른다.
100레벨인 개체에는 경험사탕을 사용할 수 없다. 그 전에는 100레벨 도달에 필요한 사탕 개수까지만 선택한다. 마지막 사탕의 초과 경험치는 소멸한다. 소멸할 양은 사용 전에 표시한다. 근거는 [경험사탕 상한 처리](work/s5-design-system-v2/plan.md#경험사탕-상한-사용과-초과-경험치)를 따른다.
친밀도는 포인트 적립으로 소모하지 않는다. 현재 친밀도가 높을수록 포인트 적립 간격이 짧아진다. 친밀도가 새로 증가하지 않아도 시간에 따라 포인트를 얻는다.
사용자 예시: 친밀도 100이면 100초마다 1포인트, 90이면 110초마다 1포인트다. 실제 수치와 계산식은 아직 정하지 않았다.
파티에 배치한 개체가 각자의 친밀도에 따라 포인트를 적립한다. 개체별 적립 결과를 보유 포인트에 합산한다. 숨긴 파티 개체도 적립을 유지한다. 파티 밖의 개체는 적립하지 않는다.
숨김은 화면 표시만 끈다. 숨긴 파티 개체도 친밀도 성장, 배고픔 변화와 버프 시간 경과를 유지한다.
모두 숨기거나 박스에 보관했으면 트레이에서 관리 화면을 열고 파티로 이동한다. 숨긴 개체는 다시 표시한다. 파티가 비었으면 박스에서 보유 개체를 골라 배치한다. 근거는 [표시 개체가 없을 때 복귀](work/s5-design-system-v2/plan.md#표시-개체가-없을-때-복귀)를 따른다.
박스 보관은 파티에서 개체를 빼는 것이다. 보관 중에는 포인트를 적립하지 않는다. 친밀도·배고픔·남은 버프 시간을 보존한다. 다시 배치하면 보존한 상태에서 이어간다.
기존 박스 제외 방향은 이 보관 계약으로 정정한다. 박스 UI의 형태와 조작은 아직 정하지 않았다. 상세 상태 표는 [파티 표시와 박스 보관](specs/s5.md#파티-표시와-박스-보관)을 따른다.
앱 종료 중에는 적립하지 않는다는 종료 상태 유지 원칙을 따른다. 배치 변경 시 진행 중인 적립 시간을 어떻게 처리할지는 미정이다.
채택 근거는 [파티 개체의 포인트 적립](work/s5-design-system-v2/plan.md#파티-개체의-포인트-적립)을 따른다.
후속 정정은 [현재 친밀도에 따른 포인트 적립](work/s5-design-system-v2/plan.md#현재-친밀도에-따른-포인트-적립)을 따른다. 해금은 개체의 즉시 지급이나 무료 재소환을 뜻하지 않는다.
성장 경로의 근거는 [친밀도와 경험치 분리](work/s5-design-system-v2/plan.md#친밀도와-경험치-분리)를 따른다. 이는 새 설계이며 현재 구현 완료 상태가 아니다.
후속 근거는 [개체 레벨과 종별 입수처](work/s5-design-system-v2/plan.md#개체-레벨과-종별-입수처)를 따른다.
근거와 기존 설계의 재검토 범위는 [개체별 육성과 되돌릴 수 없는 진화](work/s5-design-system-v2/plan.md#개체별-육성과-되돌릴-수-없는-진화)를 따른다.

현재 S4는 [해금 자료](../data/unlocks.json)와 [종 자료](../data/species.defaults.json)를 사용한다. 구현 규칙은 [S4 계획](work/s4/plan.md)을 따른다.
기존 S5의 종 등록 기반 소환은 개체별 육성에 맞게 재검토한다. 도감 해금, 개체 획득, 보유 개체 배치를 구분하는 상세 계약은 미정이다.
같은 종을 여러 개체 보유할 수 있다. 같은 종의 개체들을 동시에 파티에 배치할 수 있다.
새 개체는 사용할 수 있는 빈 파티 칸에 배치한다. 빈 칸이 없으면 박스에 보관한다. 교체는 선택한 파티 개체와 박스 개체를 한 번에 맞바꾼다.
첫 포켓몬 이후 새 개체가 파티에 배치되면 숨김 상태로 시작한다. 구매·부화·특수 획득에 같은 규칙을 적용한다. 사용자가 직접 화면에 꺼낸다. 근거는 [새 개체의 숨김 배치](work/s5-design-system-v2/plan.md#새-개체-획득-시-숨김-배치)를 따른다.
박스 개체를 빈 칸에 배치하거나 파티 개체와 맞바꿔도 들어온 개체는 숨김 상태다. 사용자가 별도로 꺼내기를 해야 화면에 나타난다. 근거는 [박스 복귀와 교체 후 숨김](work/s5-design-system-v2/plan.md#박스-복귀와-교체-후-숨김-유지)을 따른다.
박스 보관 시 개체별 포인트 부분 진행을 보존한다. 박스에서는 진행하지 않는다. 파티에 복귀하면 숨김 상태에서도 보존한 지점부터 이어간다. 근거는 [포인트 부분 진행 보존](work/s5-design-system-v2/plan.md#박스-보관-시-포인트-부분-진행-보존)을 따른다.
친밀도가 올라 포인트 적립 간격이 바뀌면 기존 진행 비율을 유지한다. 남은 부분부터 새 속도를 적용한다. 이전 경과 시간에 새 속도를 소급 적용하지 않는다. 근거는 [진행 비율 유지](work/s5-design-system-v2/plan.md#친밀도-변화-시-포인트-진행-비율-유지)를 따른다.
상세 계약은 [개체 획득과 파티 교체](specs/s5.md#개체-획득과-파티-교체)를 따른다.
새 게임의 파티는 2칸으로 시작한다. 상점에서 포인트로 2칸을 추가 구매한다. 업적으로 나머지 2칸을 해금한다. 최대 파티는 6칸이다.
박스에는 게임 규칙상 보유 개체 수 제한을 두지 않는다. 박스는 원작처럼 30칸(6열×5행) 박스 여러 개로 나누고 넘겨 본다. 박스가 모두 차면 새 박스를 자동으로 추가한다. 검색은 모든 박스를 대상으로 한다. 근거는 [원작식 박스 구조](work/s5-design-system-v2/plan.md#원작식-박스-구조와-검색)를 따른다. 구매 가격은 미정이다. 구매와 업적에 공통된 필수 해금 순서를 두지 않는다.
첫 번째 칸 업적은 파티의 두 마리를 실제로 화면에 꺼내면 달성한다. 숨긴 채 두 칸에 배치한 것만으로는 달성하지 않는다. 달성 후 다시 숨겨도 달성을 유지한다. 업적창에서 보상을 받으면 한 칸을 추가한다. 참여 유도가 목적이다.
같은 종의 서로 다른 두 개체도 첫 업적에서 인정한다. 파이리 두 마리를 꺼내도 달성한다. 근거는 [동일 종의 첫 업적 인정](work/s5-design-system-v2/plan.md#동일-종의-첫-업적-인정)을 따른다.
[스펙 미확정] 두 번째 칸 업적의 조건은 사용자가 구상 중이다. 상점의 구매 가능한 파티 칸 2개를 모두 구매하는 조건은 과거 후보이며 채택하지 않았다. 조건 확정은 보류한다.
수용 정책은 [파티 칸과 박스 수용 정책](work/s5-design-system-v2/plan.md#파티-칸과-박스-수용-정책)을 따른다. 업적의 후속 결정은 [참여 유도 업적](work/s5-design-system-v2/plan.md#참여-유도-업적)을 따른다.
[스펙 미확정] 재소환과 반복 보상은 구현 전에 확정한다. 진화 시 개체 정보 유지 범위는 후속 결정을 따른다. 저장 이식과 남은 승계 항목은 별도로 설계한다.

## 상점

S4(옛 상점)는 포켓몬·칸·민트·먹이·색 구매를 제공했다. 가격과 보상은 `data/shop.json`에 있었다. 2026-09-25 에 옛 상점 코드를 걷었고, 2026-09-27 에 읽는 코드가 없는 이 자료도 지웠다. 지금 상점은 [밸런스 수치](specs/balance.md)의 가격표를 따른다.
가방은 칸 수와 종류별 보유 수량을 제한하지 않는다. 보관 제한 없음은 사탕의 사용 수량 한도를 바꾸지 않는다. 근거는 [가방 보관 결정](work/s5-design-system-v2/plan.md#가방-보관-제한-없음)을 따른다.
구매·사용·보상 수령은 관련 상태 변경을 하나의 거래로 처리한다. 성공하면 전부 반영한다. 실패하면 전부 이전 상태를 유지한다. 완료된 거래를 재시도해도 중복 지급하거나 비용을 다시 차감하지 않는다. 근거는 [거래 실패 원칙](work/s5-design-system-v2/plan.md#거래-실패-원자성과-코스모움-분리안-재검토)을 따른다.
거래 실패 후에는 실패 처리만 제공한다. 실패 복구용 선택값 보존과 다시 시도 버튼을 추가하지 않는다. 자동 재시도도 추가하지 않는다. 상태 보존과 완료 거래의 중복 방지는 유지한다. 근거는 [실패 처리 범위](work/s5-design-system-v2/plan.md#거래-실패-처리만-제공)를 따른다.
부화·진화·교체에도 같은 거래 원칙과 실패 처리를 적용한다. 부화 저장에 실패하면 알은 부화 가능 상태로 남는다. 다시 열면 그 시점의 조건으로 결과를 새로 정한다. 근거는 [복합 동작의 거래 적용](work/s5-design-system-v2/plan.md#부화진화교체의-트랜잭션-적용)을 따른다.
진화·교체를 확정 전에 취소하면 아무 상태도 바꾸지 않는다. 공유 `sid` 종 교체, 첫 선택, 놀이공간 적용도 실패하면 이전 상태를 유지한다. 첫 선택을 확정하기 전에 닫으면 다음 실행 때 선택 화면을 다시 연다. 근거는 [취소와 남은 저장 실패](work/s5-design-system-v2/plan.md#확정-전-취소와-남은-저장-실패의-처리)를 따른다.
S5는 획득과 사용을 분리한다. 사탕 6종은 획득 경로와 관계없이 공통 가방에 종류별로 보관한다. 가방에서 사탕, 대상 개체, 수량을 순서대로 선택한다. 결과를 확인한 뒤 직접 사용한다. 근거는 [사탕 보관과 사용 결정](work/s5-design-system-v2/plan.md#사탕의-공통-가방-보관과-직접-사용)을 따른다. 알은 구매 직후 돌보미집에 배치하는 후속 계약을 따른다.
2026-09-21 후속 결정: 기본먹이와 별도로 프리미엄먹이를 판매한다. 기존 S5의 먹이 판매 제거 방향은 [일상 사용 계약](specs/s5.md#일상-사용-계약)으로 대체한다. 기존 S4 먹이 효과를 새 버프 규칙으로 자동 승계하지 않는다.
랜덤알은 최대 5분의 대기를 기준으로 부화 준비를 진행한다. 돌봄 같은 활동은 대기시간을 단축한다. 준비 시간이 끝나면 부화 가능 상태가 된다. 사용자가 직접 열어야 부화한다.
알 구매가 완료되면 준비 타이머를 바로 시작한다. 별도 부화 시작 조작은 요구하지 않는다.
알별로 준비 진행도를 관리한다. 알 돌봄 행동은 쓰다듬기와 노래 들려주기다. 상점의 부화시간 단축 도구는 채택하지 않는다. 기본 대기 시간을 늘리면 다시 검토한다. 근거는 [알 돌봄 행동](work/s5-design-system-v2/plan.md#알-돌봄-행동의-채택)을 따른다.
돌보미집은 메뉴로 구성한다. 돌보미집은 박스 메뉴 안에 둔다. 근거는 [설정창 구성](work/s5-design-system-v2/plan.md#관리-창의-탭과-헤더-구성)과 [박스 메뉴 분리](work/s5-design-system-v2/plan.md#박스-메뉴-분리)를 따른다. 알은 데스크톱 놀이공간에 배치하지 않는다. 돌보미집 내부에는 알을 최대 6개 배치한다. 배치한 알은 각자의 타이머로 동시에 진행한다. 돌봄은 선택한 알에 개별 적용한다. 파티 칸과 돌보미집의 알 칸은 별개다.
알의 부화 준비가 완료되는 순간 작은 알림을 한 번 제공한다. 사용자가 직접 열어야 부화한다. 근거는 [메뉴형 돌보미집과 알림](work/s5-design-system-v2/plan.md#메뉴형-돌보미집과-부화-준비-완료-알림)을 따른다.
알림은 화면 한쪽의 작은 배너로 잠깐 표시한다. 배너의 `바로가기`를 누르면 돌보미집을 연다. 누르지 않으면 배너는 사라진다. 세 배너 모두 `바로가기` 버튼을 쓴다. 근거는 [빈 화면 제안 검토](work/s5-design-system-v2/plan.md#빈-화면-제안-검토)를 따른다. 알은 직접 부화할 때까지 유지한다. 근거는 [배너와 클릭 이동](work/s5-design-system-v2/plan.md#부화-준비-완료-배너와-클릭-이동)을 따른다.
돌보미집이 6개의 알로 가득 차면 추가 알 구매를 막는다. 부화 가능한 알도 직접 열기 전까지 칸을 차지한다. 직접 부화해 칸이 비면 다시 구매할 수 있다. 구매한 초과 알을 따로 보관하지 않는다.
배치 근거는 [돌보미집과 알 6개](work/s5-design-system-v2/plan.md#돌보미집과-알-6개)를 따른다. 구매 제한 근거는 [돌보미집 만석 처리](work/s5-design-system-v2/plan.md#돌보미집-만석-처리)를 따른다.
랜덤알의 결과는 해금한 종 중 알 입수처가 허용된 종으로 제한한다. 진화 전용 종은 해금해도 제외한다. 구체적인 종 목록·확률·해금 판정 시점과 활동별 단축량은 미정이다.
랜덤알은 무작위 결과와 부화 과정을 제공한다. 종 지정 구매는 원하는 종을 확정해서 얻는 대신 더 비싼 방향이다. 실제 가격은 미정이다.
구매 시 해당 알의 개체 식별자(sid)에 가능한 종 범위를 저장한다. 구매 후 새로 해금한 종은 이미 구매한 알에서 나오지 않는다.
알 구매부터 직접 열기 직전까지 행동 조건을 쌓을 수 있다. 준비 완료 뒤에도 돌봄과 탐색을 이어간다. 직접 열 때까지 충족한 조건으로 결과를 결정한다. 근거는 [알 행동 누적 기간](work/s5-design-system-v2/plan.md#직접-열기-전까지-알-행동-누적)을 따른다.
일반 알에서 행동 조건을 충족하면 그 조건에 대응한 포켓몬으로 부화한다. 미충족이면 저장한 범위에서 무작위로 부화한다. 행동을 하지 않아도 부화는 가능하다. 준비 시간과 직접 열기 원칙은 유지한다. 근거는 [일반 알의 행동 조건과 결과 분기](work/s5-design-system-v2/plan.md#일반-알의-행동-조건과-결과-분기)를 따른다.
알 행동 조건을 지정하는 종에는 조건을 하나만 둔다. 같은 종에 여러 대체 조건을 두지 않는다. 서로 다른 종의 조건을 한 알에서 여러 개 충족하는 것은 가능하다. 근거는 [종별 단일 행동 조건](work/s5-design-system-v2/plan.md#알-행동-조건의-종별-단일-지정)을 따른다.
여러 행동 조건을 충족해 대응 종이 여러 개이면 그 종들 중 수집 난이도 가중치로 추첨한다. 후보가 한 종이면 그 종으로 부화한다. 충족하지 않은 종을 섞지 않는다. 근거는 [복수 조건의 난이도 가중치](work/s5-design-system-v2/plan.md#복수-행동-조건-후보의-난이도-가중치)를 따른다. 사용자가 시도하며 조건을 알아가는 경험을 지향한다. 실제 가중치는 미정이다. 발견 경험의 근거는 [복수 조건과 발견 경험](work/s5-design-system-v2/plan.md#복수-행동-조건의-무작위-결과와-발견-경험)을 따른다.
행동 조건을 충족하지 않은 일반 무작위 부화는 종별 수집 난이도 1~5에 따른 공통 가중치를 사용한다. 종마다 상세 확률을 직접 입력하지 않는다. 1은 얻기 쉬운 쪽, 5는 얻기 어려운 쪽으로 표기한다. 실제 가중치는 미정이다. 근거는 [수집 난이도와 부화 가중치](work/s5-design-system-v2/plan.md#수집-난이도에-따른-일반-부화-가중치)를 따른다.
입수처는 종마다 지정한다. 알 전용 종과 특수 기믹 전용 종도 둔다. 특수 기믹 전용 종은 구매나 알에서 나오지 않는다. 해금됐다는 이유로 모든 입수처에 자동 포함하지 않는다.
종별 목록과 특수 기믹은 추후 정한다. 근거는 [종별 입수처 지정](work/s5-design-system-v2/plan.md#종별-입수처-지정)을 따른다.
특수 기믹 전용 종은 선행 도감 해금을 요구하지 않는다. 해당 기믹을 수행하면 도감 해금과 개체 획득이 함께 일어난다. 근거는 [특수 기믹의 선행 해금 제외](work/s5-design-system-v2/plan.md#특수-기믹의-선행-해금-제외)를 따른다.
해금 후 입수처와 획득 제한은 종마다 지정한다. 기믹으로 처음 얻은 뒤 상점이나 알에서 추가 획득하는 종도 둔다. 계속 기믹으로만 얻는 종과 단일 포켓몬도 따로 지정한다. 최초 획득이 기믹이었다는 이유로 후속 상점·알 입수를 일괄 금지하지 않는다.
알 전용 종에도 도감 해금 수 같은 후보 진입 조건을 지정한다. 도감 100종 이상 해금은 사용자 예시다. 조건 달성은 무작위 획득 기회를 열며 즉시 개체를 지급하지 않는다. 실제 조건표는 미정이다. 근거는 [종별 후속 입수처와 조건부 알 후보](work/s5-design-system-v2/plan.md#종별-후속-입수처와-조건부-알-후보)를 따른다.
단일 포켓몬으로 지정한 종은 해당 저장에서 딱 한 번만 획득할 수 있다. 전설의 포켓몬과 환상의 포켓몬은 적용 예시다. 실제 지정은 종별로 한다. 근거는 [단일 포켓몬의 일회 획득](work/s5-design-system-v2/plan.md#단일-포켓몬의-일회-획득)을 따른다.
단일 포켓몬은 일반 알에서 획득할 수 없다. 일반 무작위 결과와 행동 조건 결과에서 모두 제외한다. 근거는 [단일 포켓몬의 알 입수 제외](work/s5-design-system-v2/plan.md#단일-포켓몬의-알-입수-제외)를 따른다.
2026-09-26 결정: 전설·준전설·환상·울트라비스트 98종(진화 전 기본형)을 단일 포켓몬으로 지정한다. 이 종은 일반 알에서는 나오지 않고 단일 포켓몬 알에서만 나온다. 단일 포켓몬 알은 랜덤준전설알·랜덤울트라비스트알·랜덤환상알·랜덤전설알 네 가지다. 랜덤알을 열 때 낮은 확률로 포켓몬 대신 이 알이 나온다. 상점에서도 비싸게 판다. 알 후보는 아직 얻지 않은 종이다. 알 행동 조건은 보지 않는다. 진화형 7종은 진화로 얻는다. 확률과 가격은 [밸런스 수치](specs/balance.md#확률과-알)를 따르고, 입수처는 `data/eggs.json` 에서 바꾼다. 사용자 발언: "나중에 도입처 바꿀 수 있으면은 우선은 랜덤알에서 랜덤준전설알, 랜덤울트라비스트알, 랜덤환상알, 랜덤전설알 이런거 낮은확률로 나오게 하자", "울비2, 준전1.5, 환상2, 전설0.5로 하자. 상점에도 비싸게 추가하자". 근거는 [단일 포켓몬 알](work/game-runtime/record.md#단일-포켓몬-알)을 따른다.

2026-09-27 결정: 패러독스 20종도 단일 포켓몬 알로 얻는다. 알은 랜덤패러독스알이다. 가격·확률·구조는 랜덤울트라비스트알과 같다. 화석 15종과 패러독스 20종은 처음부터 해금하지 않는다. 알에서 나와야 해금된다. 옛 저장은 얻지 않은 종의 해금을 한 번 지운다. 사용자 발언: "전용알이 있는데? 알에서 나오면 해금.", "울트랑비스트랑 가격, 확률 등 구조 동일하게." 근거는 [플레이 버그 3건](work/play-bugs/record.md)을 따른다.
조건부 입수 종은 조건 충족 시 도감 해금과 허용 입수처 활성화를 진행한다. 실제 획득은 해당 입수 경로를 이용했을 때 일어난다. 알 전용 종도 조건 충족 시 해금한 뒤 알 후보에 포함한다.
도감 해금 수는 보유 여부와 관계없이 해금된 서로 다른 종의 수다. 초기 후보와 레벨 조건으로 해금한 미진화 종도 포함한다. 중복 개체 획득은 종 수를 늘리지 않는다. 근거는 [해금과 입수처 활성화](work/s5-design-system-v2/plan.md#조건-충족에-따른-해금과-입수처-활성화)를 따른다.
일반 폼과 리전폼은 기본 도감번호가 같아도 별도 종으로 취급하는 독립 도감 항목이다. 일반 대검귀는 `503`, 히스이 대검귀는 `503-1`로 구분한다. 각 항목은 독립적으로 해금한다. 둘 다 해금하면 2종으로 센다. 근거는 [리전폼 도감 항목과 집계](work/s5-design-system-v2/plan.md#리전폼의-독립-도감-항목과-집계)를 따른다.
도감에서 구매·알·진화의 입수 조건은 명확히 표시한다. 특수 기믹은 발견 전에는 힌트만 표시한다. 발견 후에는 정확한 방법을 공개한다. 발견을 판정하는 시점은 미정이다.
알의 기본 입수 조건과 행동으로 결과를 정하는 숨겨진 조건은 구분한다. 발견 전에는 정답 행동이나 충족한 포켓몬 목록을 직접 보여주지 않는다. 알의 반응과 작은 힌트로 탐색하게 한다. 실제 힌트는 미정이다. 근거는 [발견 전 알의 반응과 힌트](work/s5-design-system-v2/plan.md#발견-전-알의-반응과-힌트)를 따른다.
행동 조건을 실제로 충족하고 대응 종이 부화하면 해당 조건을 발견으로 기록한다. 조건 없이 일반 무작위 부화로 얻으면 발견으로 처리하지 않는다. 여러 종의 조건 중 A가 부화했으면 A 조건만 새로 발견한다. 발견한 조건은 도감에 정확히 기록한다. 근거는 [발견 판정과 기록](work/s5-design-system-v2/plan.md#알-행동-조건의-발견-판정과-기록)을 따른다.
공개 정책의 근거는 [도감 입수 방법 공개](work/s5-design-system-v2/plan.md#도감-입수-방법-공개)를 따른다.
기존 에이전트 작업량 기반 부화를 자동 채택하지 않는다. 상세 계약은 [활동에 따른 부화 대기시간 단축](specs/s5.md#활동에-따른-부화-대기시간-단축)을 따른다.
민트는 2026-09-22에 채택했다. 상점에서 사서 가방에 보관한다. 확인하면 성격이 바뀌고 민트 1개를 소비한다. 현재와 같은 성격으로는 바꿀 수 없다. 파티와 박스의 개체 모두에 사용할 수 있다. 근거는 [민트 유지](work/s5-design-system-v2/plan.md#민트-유지)를 따른다. 2026-09-25 결정: 민트는 성격별 21종이다. 보정 있는 성격 20개마다 하나, 그리고 보정 없는 성격 5개(노력·온순·수줍음·변덕·성실)를 함께 맡는 성실민트 하나다. 성실민트를 쓰면 그 5개 중 하나를 고른다. 성격 변경의 입구는 포켓몬 상세의 `성격 변경` 이다. 창은 왼쪽에 지금, 오른쪽에 바꾼 후를 둔다. 오른쪽에서 성격을 고르면 필요한 민트를 보인다. 가방에서 민트를 쓰면 대상을 고른 뒤 같은 창이 열린다. 근거는 [성격별 민트](work/game-runtime/record.md#관리-창--성격별-민트의-설계)를 따른다. 진화의돌은 2026-09-22에 채택했다. 원작에서 돌로 진화하는 종의 진화 조건이다. 상점에서 사서 가방에서 사용하면 진화 확인 화면으로 이어진다. 확인하면 돌 1개를 소비하고 진화한다. 근거는 [진화의돌 채택](work/s5-design-system-v2/plan.md#진화의돌-채택)을 따른다. 무료 밥 주기는 기존 구현과 구분해서 유지한다.
이로치는 해당 도감 항목의 획득 여부로 기록한다. 별도 종 수는 늘리지 않는다. 낮은 확률의 알 부화 또는 상점 아이템 사용으로 얻는다. 단일 종은 약으로 이로치가 된다. 비싼 `모습이 바뀌는 약`으로 기존 개체를 이로치로 바꾼다. 0원인 `돌아오는 약`으로 일반색으로 되돌린다. 상품명은 가칭이다. `1/1000`은 확률 후보이며 실제 확률과 변경 약 가격은 미정이다. 근거는 [이로치 기록과 획득 경로](work/s5-design-system-v2/plan.md#이로치-기록과-알-및-약-획득-경로)를 따른다.
일반 개체는 최초 획득 시 일반색으로 시작한다. 알에서 이로치로 태어났거나 약으로 바꾼 개체는 숨김 해제·박스 복귀 후에도 이로치를 유지한다.
이로치 개체는 진화 후에도 이로치를 유지한다. 돌아오는 약으로 일반색으로 바꿔도 도감의 이로치 획득 기록은 남는다. 근거는 [이로치 유지와 획득 기록 보존](work/s5-design-system-v2/plan.md#진화-이로치-유지와-도감-획득-기록-보존)을 따른다.
알 행동 조건은 결과 종에만 영향을 준다. 이로치 여부는 별도의 동일한 낮은 확률로 추첨한다. 행동 조건으로 정해진 종도 이로치가 될 수 있다. 돌봄으로 이로치 확률을 높이지 않는다. 근거는 [알 행동과 이로치 추첨 분리](work/s5-design-system-v2/plan.md#알-행동-조건과-이로치-추첨-분리)를 따른다.
[스펙 미확정] 상품 효과·가격·부화량과 기존 구매 권리의 이식은 [S5 계획](specs/s5.md)을 따른다. 현재 S4 코드와 재고를 먼저 삭제하지 않는다.

## 커맨드 처리기

현재 계약은 [공유 타입](../src/shared/types.ts)과 [등록 처리기](../src/main/commands.ts)를 따른다. 메뉴·CLI·mailbox는 같은 명령 처리 경로를 사용한다.
현재 명령은 [공유 타입](../src/shared/types.ts)의 `CommandName`이다(2026-09-27 확인). `feed`, `play`, `poke`, `evolve`, `party.show`, `party.hide`, `party.remove`, `party.place`, `party.swap`, `party.keep`, `box.sort`, `box.move`, `box.rename`, `egg.care`, `egg.open`, `bag.use`, `achievement.claim`, `tutorial.skip`, `tutorial.done`, `pet.set`, `pet.look`, `pet.form`, `starter.pick`, `agent.connect`, `agent.disconnect`, `settings.set`, `shop.buy`, `snapshot`, `quit`이다. 설정창이 쓰는 이름은 [명령 다리](../src/tx/bridge.ts)가 푼다.
옛 제안 `party.summon`, `party.dismiss`, `settings.open`은 쓰지 않는다. 파티 배치는 `party.place`·`party.swap`·`party.keep`이 맡는다.

`companion`은 포켓몬 인자를 받지 않는다. 빈 파티이면 선택창을 연다. 선택 취소와 저장 실패를 구분한다.
`pet.set`의 위치 변경은 저장에 성공한 뒤 성공으로 응답한다. 마우스 위치 변경도 같은 명령을 사용한다.
2026-09-21 확인: `pet.set size=3`은 `not-yet`으로 응답했다. 2026-09-25 크기 변경을 구현했다. 2026-09-27 부터 `size`는 크기 단계 번호(1~5)다([소리 크기와 그림 크기 단계](work/sound-size/record.md)).
명령과 실제 앱을 연결한 검사 범위는 [실행 흐름 검수](work/runtime-e2e/record.md)를 따른다.

## 저장 v2와 S5 전환

현재 저장 계약은 [저장 v3 타입](../src/shared/save-v3.ts)에 있다. 개체(`pets`)와 파티 칸(`party.slots`)이 나뉜다. 저장·복원 규칙은 [저장 모듈](../src/save/store.ts)과 [저장 규칙](../src/save/rules.ts)을 따른다. 옛 `SaveV2`(`party` 가 `Pet[]`)는 [옛 저장 읽기](../src/save/legacy.ts)가 읽어 v3 로 옮긴다.
`species`는 실제 종이다. `look`은 표시 그림이다. 개체 `id`는 진화 후에도 유지한다. writer 잠금과 mailbox를 유지한다.
S5는 도감 등록, 개체별 육성 기록, 파티 배치, 도구 재고, 알 상태를 나눈다. 파티 밖 개체는 박스에 보관한다. 2026-09-24 저장 v3 로 확정해 구현했다. 처음 열 때 v2 를 v3 으로 옮기고 원본을 `save.json.v2.bak` 에 남긴다([S5 기능 계약](specs/s5.md), [실제 앱을 저장 v3 으로](work/game-runtime/record.md#실제-앱을-저장-v3-으로)).
새 화면에서 별명·모습을 제거해도 기존 `nick`, `look`과 재고를 임의로 지우지 않는다. 원본 백업과 실패 복원을 먼저 설계한다.

## S5 설정창과 메뉴

설정창의 탭은 파티 / 박스 / 도감 / 상점 / 가방이다. 헤더에는 보유 포인트와 창 조작 단추 자리를 둔다. 업적창 아이콘과 설정 아이콘은 탭 줄 오른쪽에 둔다. 2026-09-25 결정이며 근거는 [헤더와 폭 다시 그리기](work/game-runtime/record.md#관리-창--헤더와-폭-다시-그리기의-설계)를 따른다. 미수령 보상이 있으면 업적창 아이콘에 dot를 표시한다. 업적창과 설정은 보던 탭 위에 여는 모달이다. 닫으면 보던 탭으로 돌아간다. 근거는 [업적창과 설정의 모달](work/s5-design-system-v2/plan.md#업적창과-설정의-모달)을 따른다. 파티 탭에는 파티 칸만 둔다. 박스는 별도 메뉴이며 돌보미집을 그 안에 둔다. 근거는 [설정창 구성](work/s5-design-system-v2/plan.md#관리-창의-탭과-헤더-구성)과 [박스 메뉴 분리](work/s5-design-system-v2/plan.md#박스-메뉴-분리)를 따른다.
파티는 2열×3행이다. 빈 칸과 잠긴 칸을 구분한다. 상세에서 숨기기·다시 표시와 소환 해제를 구분한다.
별명과 모습 선택은 제공하지 않는 기존 S5 설계다. 연결 설정은 설정 탭 안에 둔다.
성격 변경은 가방에서 민트를 사용하는 방식으로 채택했다. 근거는 [민트 유지](work/s5-design-system-v2/plan.md#민트-유지)를 따른다. 이로치 색상 변경 약은 후속 결정으로 채택했다. 이전 명칭과 기능 출처는 [명칭 검수](work/s5-terminology/review.md)를 따른다.
우클릭 메뉴는 포켓몬 위에서 우클릭할 때만 연다. 메뉴는 OS 기본 메뉴가 아니라 앱이 직접 그린다. 근거는 [앱이 그리는 우클릭 메뉴](work/s5-design-system-v2/plan.md#앱이-그리는-우클릭-메뉴)를 따른다. 포켓몬이 없는 놀이공간 영역의 우클릭은 가로채지 않고 뒤의 앱으로 넘긴다. 메뉴는 이름·상태 / 밥 주기·놀아주기 / 설정의 세 묶음이며 구분선으로 나눈다. 우클릭 메뉴에는 종료를 두지 않는다. 메뉴 첫 줄의 상태는 만복도 구간 이름과 기분 구간 이름으로 보여준다. 설정창은 같은 정보를 수치 막대로 보여준다. 만복도 구간은 배고픔 말풍선의 구간과 같다. 구간 수와 경계는 밸런스 설계에서 정한다. 근거는 [검수 P2 결정](work/s5-design-system-v2/plan.md#검수-p2-결정-항목)을 따른다. 트레이 메뉴는 설정과 종료를 제공하는 것으로 설계한다. 근거는 [포켓몬 위 우클릭 메뉴](work/s5-design-system-v2/plan.md#포켓몬-위-우클릭-메뉴)를 따른다. 현재 S4 메뉴의 구현 완료 상태와 구분한다.
전용 preload, contextIsolation, sandbox, IPC sender·최상위 frame 검사를 유지한다. 상세 수용 조건은 [S5 계획](specs/s5.md)을 따른다.

## 교환

2026-09-26 사용자 결정: 친구끼리만 포켓몬을 교환한다. 한 사람이 일회성 공유 채널의 링크를 보내면 그 채널에서만 교환한다. 서버는 Supabase를 쓰는 방향으로 설계한다.
교환에는 로그인이 필요 없다. 단일 포켓몬은 교환할 수 없다. 첫 선택 포켓몬은 제한 없이 교환할 수 있다. 교환해도 진화하지 않으며 교환 진화 종은 `연결의끈` 규칙을 유지한다(2026-09-27 이름 변경 — 원작 이름이 연결의끈이다. [가상 도구 도트 그림](work/item-art/record.md)).
같은 날 두 번째 파티 칸 업적의 조건을 "최초로 포켓몬 50레벨 달성"으로 바꿨다. 받은 개체는 인정하지 않고 레벨업으로만 달성한다. [S5 기능 계약](specs/s5.md#파티-칸-확장과-박스-수용)을 따른다.
교환 화면은 설정창의 `가방` 탭 옆에 둔다. 서버 연결에는 `@supabase/supabase-js`를 쓴다.
배틀은 이번 설계에서 제외한다.
2026-09-27 사용자 결정: 로그인을 선택 기능으로 더한다. 방법은 아이디+비밀번호(중복검사)와 GitHub다. 같은 날 이메일 로그인과 Google은 뺐다. 아이디는 영어만 받고, 가입할 때 이름도 받는다. 본인인증은 하지 않는다. 로그인하지 않아도 교환은 된다.
같은 날 사용자 결정: 로그인하면 저장 사본을 서버에 둔다(클라우드 저장). 게임은 계속 로컬에서 돌고 `save.json`이 정본이다. 같은 계정은 나중에 켜진 PC 하나만 활성이며, 먼저 켜진 PC는 로그아웃되고 서버에 저장하지 못한다. 온라인이면 자동 저장하고, 오프라인에서 한 진행은 다시 연결된 뒤 저장 버튼을 눌러야 올라간다. 채널 규칙·서버·복구의 제안과 구현 상태는 [친구 교환 기록](work/trade/record.md)을 따른다.
