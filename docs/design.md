# pokebuddy 설계

이 문서는 제품 구조와 지금 적용하는 설계 규칙을 적는다.
앱은 S5 게임 규칙을 저장 v3 로 실행한다. 번호의 뜻은 [번호 체계](terms.md#번호-체계)를 따른다.
기능의 상세 계약은 [게임 규칙](specs/game.md)을 따른다. 수치는 [밸런스 수치](specs/balance.md)를 따른다. 사용 흐름은 [사용자 시나리오](specs/scenarios.md)를 따른다.
화면 명칭은 [용어사전](terms.md)을 따른다. 모듈 경계와 저장 구조는 [모듈 계약](specs/modules.md)을 따른다.

## 제품 목적

- 사용자는 컴퓨터를 켠 직후 앱을 켠다.
- 사용자는 PC에서 자유롭게 노는 포켓몬을 구경한다.
- 게임은 눈에 보이는 방치형 게임의 느낌을 제공한다.
- 사용자는 포켓몬을 조금씩 직접 돌본다.
- 게임은 일하는 중 잠깐 쉬어 가는 경험을 제공한다.
- 돌보지 않는 동안 배고픔 같은 상태가 변한다. 사용자는 나중에 조금 챙겨준다.

고정 작업 타이머, 돌봄 주기, 플레이 시간은 정하지 않았다.
상태 변화의 속도는 [밸런스 수치](specs/balance.md)를 따른다.
앱을 다시 켜면 종료한 상태에서 이어간다. 종료 중에는 게임 상태를 진행하지 않는다.
PC 잠금·절전·앱 종료 중에는 배고픔·친밀도·포인트·버프 시간·알 준비 시간·먹이 쿨타임을 멈춘다. 값과 부분 진행을 보존하고 복귀 후 이어간다.
설정창만 닫거나 포켓몬을 숨긴 상태에서는 파티·박스 규칙대로 진행한다. 상세 기준은 [실행 상태별 시간](specs/game.md#실행-상태별-시간)을 따른다.

### 돌봄을 알리는 원칙

화면에 보이는 포켓몬은 배고픔을 작은 말풍선으로 표현한다. 사용자는 돌봄 시점을 선택한다. 알림은 돌봄을 강제하지 않는다.
숨겨진 포켓몬의 배고픔은 파티창의 상태 표시로만 확인한다. 배고픔 때문에 숨김을 해제하거나 창을 자동으로 열지 않는다.
만복도는 네 구간으로 나눈다. 말풍선은 배고픔 구간과 매우 배고픔 구간에서만 표시한다. 나머지 구간에서는 사용자가 구경하다가 자발적으로 돌본다.
보이는 포켓몬이 배고픔 구간에 들어가면 말풍선을 표시한다. 매우 배고픔 구간에 들어가면 말풍선을 다시 표시한다.
같은 구간에 머무르면 말풍선을 되풀이한다. 간격은 배고픔 10분, 매우 배고픔 5분이다.
배고플 때 움직임은 바꾸지 않는다.
구간 경계는 [만복도와 돌봄](specs/balance.md#만복도와-돌봄)을 따른다. 표시 규칙은 [배고픔 상태 표시](specs/game.md#배고픔-상태-표시)를 따른다.
여러 포켓몬이 동시에 말풍선을 띄울 때의 표현은 정하지 않았다.

### 상태 알림 배너

부화 준비 완료는 알별로 알린다. 진화 가능은 개체별로 알린다. 업적 달성은 업적별로 알린다. 같은 종류의 알림도 묶지 않는다.
배너는 한 번에 하나씩 순차 표시한다. 상세 계약은 [알림 배너의 개별 표시](specs/game.md#알림-배너의-개별-표시)를 따른다.
배너 알림 소리는 기본으로 켠다. 사용자는 설정에서 무음으로 전환할 수 있다. 소리는 사용하는 OS의 기본 시스템 알림음이다.
한 번 표시한 부화·진화·업적 배너는 같은 미처리 상태를 다시 알리지 않는다. 앱을 다시 켜도 반복하지 않는다. 해당 메뉴의 부화 가능·진화 가능·업적 미수령 상태는 유지한다.
기다리는 동안 대상이 더 이상 미처리 상태가 아니면 그 배너를 표시하지 않는다.
표시 전에 앱이 종료된 배너는 재실행 후 이어서 표시한다. 표시 중에 앱이 종료된 배너는 표시한 것으로 처리한다.
여러 배너가 기다리면 먼저 생긴 배너부터 표시한다. 같은 순간이면 부화 → 진화 → 업적 순서를 따른다. 같은 종류는 화면의 목록 순서를 따른다.

### 배고픔 상태 디버프

배고픔 상태 디버프는 새로 얻는 친밀도 증가량을 줄인다. 이미 쌓인 친밀도는 줄이지 않는다.
디버프는 배고픔 구간과 매우 배고픔 구간에 적용한다.
배율은 [만복도와 돌봄](specs/balance.md#만복도와-돌봄)을 따른다.

### 친밀도 획득과 확장 후보

포켓몬은 함께 켜 두는 시간에 친밀도를 얻는다. 밥 주기와 놀아주기는 추가 친밀도를 제공한다.
에이전트 사용은 별도의 추가 이득을 준다. 기본 보상과 에이전트 보상은 보너스 한도를 공유하지 않는다.
보상 한도를 채운 뒤 앱을 끄게 만드는 구조를 피한다. 친밀도와 포인트에는 하루 상한이 없다.
에이전트 보상의 계산은 [버프와 친밀도](specs/balance.md#버프와-친밀도)를 따른다.
던전 탐험은 향후 확장 후보다. 추가하면 경험사탕 5종·이상한사탕·경험치를 얻는 경로로 쓴다. 탐험 규칙과 구현 시점은 정하지 않았다.

게임은 자동기능을 두지 않는다. 자동기능은 게임 진행을 대신 해 주는 기능이다.
자동 먹이, 자동 부화, 자동 진화, 자동 보상 수령, 자동 교체를 제공하지 않는다.
로그인 시 시작 같은 앱 실행 편의 기능은 자동기능이 아니다.
설정 `일반`의 `로그인 시 시작` 기본값은 켜짐이다. 사용자는 설정에서 끌 수 있다.

## 놀이공간과 직접 돌봄

포켓몬은 화면 전체에서 자유롭게 활동한다. 사용자는 활동 영역을 지정할 수도 있다.
화면 용어는 `놀이공간`이다. 내부 식별자는 `stage`를 유지한다.
첫 사용은 화면 전체에서 시작한다. 놀이공간 영역은 드래그로 지정한다. 조작은 [일상 사용 계약](specs/game.md#일상-사용-계약)을 따른다.

### 튜토리얼

튜토리얼은 기능별 단계로 나눈다. 사용자가 해당 행동을 했을 때 관련 튜토리얼을 시작한다.
첫 돌봄 튜토리얼에서 밥 주기와 놀아주기를 직접 해본다.
놀이공간 튜토리얼은 첫 돌봄 튜토리얼을 마치거나 스킵하면 시작한다. 놀이공간 변경은 화면 설명으로 알려준다. 튜토리얼에서 실제 영역 변경을 요구하지 않는다.
상점 튜토리얼은 시작 포인트로 랜덤알을 구매하도록 알려준다.
파티에 새로 들어온 포켓몬은 꺼낸 상태로 화면에 나온다.
파티 튜토리얼은 두지 않는다. 가르칠 꺼내기 조작이 없다. 정의는 코드에 꺼진 상태로 남아 있다(`src/tutorial/core.ts`).
업적 튜토리얼은 받지 않은 업적이 처음 생기면 시작한다. 헤더의 업적 아이콘을 밝혀 업적창으로 이어 준다. 업적 보상을 한 번 받으면 끝난다(`src/tutorial/core.ts` `achievement`). 업적 배너의 `바로가기`도 업적창을 연다.
시작 포인트는 다른 상품에도 쓸 수 있다. 랜덤알 구매를 강제하지 않는다. 다른 곳에 써도 일반 게임 진행을 막지 않는다.
시작 포인트를 다른 곳에 썼다가 나중에 알을 구매하면 그때 부화 튜토리얼을 시작한다.
한 단계가 늦어져도 다른 기능의 사용을 막지 않는다. 단계별 진행과 재개 규칙은 [행동에 따른 단계별 튜토리얼](specs/game.md#행동에-따른-단계별-튜토리얼)을 따른다.
튜토리얼을 건너뛰어도 같은 시작 포인트를 한 번 지급한다. 가이드북 열람으로는 포인트를 지급하지 않는다. 지급량은 [가격](specs/balance.md#가격)을 따른다.
여러 튜토리얼은 하나씩 보여준다. 진행 중인 튜토리얼을 마치거나 건너뛰면 다음 튜토리얼을 보여준다. 화면을 강제로 전환하지 않는다.
닫기는 해당 튜토리얼의 스킵으로 처리한다. 스킵하거나 닫은 튜토리얼은 다시 보여주지 않는다. 튜토리얼 다시보기는 제공하지 않는다. 이후 사용법은 가이드북에서 확인한다.
진행 중인 튜토리얼이 앱 종료로 끊기면 스킵으로 처리하지 않는다. 재실행 후 그 튜토리얼을 처음부터 다시 보여준다.
여러 튜토리얼 조건이 생기면 먼저 생긴 조건부터 보여준다. 같은 순간이면 첫 돌봄 → 상점 → 부화 → 파티 → 놀이공간 순서를 따른다.
표시 전에 앱이 종료된 대기 튜토리얼은 재실행 후 같은 규칙으로 보여준다.
튜토리얼 구매와 업적 수령의 상세 흐름은 [첫 구매와 업적 보상 수령](specs/game.md#첫-구매와-업적-보상-수령)을 따른다.

### 업적

업적은 조건 달성과 보상 수령을 구분한다. 사용자가 업적창에서 보상을 받아야 칸을 연다. 칸을 자동으로 열지 않는다.
각 업적의 보상은 한 번만 받는다. 받지 않은 보상은 창 닫기와 앱 재실행 후에도 미수령 상태로 남는다. 수령 기한은 두지 않는다.
반복형 업적이 필요하면 별도 종류로 설계한다.

### 첫 포켓몬과 이후 획득

첫 선택 후보는 별도 목록으로 지정한다. 후보는 `data/unlocks.json`에서 `starter: true`인 종이다.
사용자는 후보 중 원하는 진화 전 포켓몬을 고른다. 예를 들어 리자몽을 원하면 파이리부터 시작한다.
첫 선택 후보는 모두 처음부터 도감에 해금한다. 해금만으로 개체를 지급하지 않는다.
모든 해금 종을 첫 선택 후보로 자동 포함하지 않는다.
초기 랜덤알은 첫 선택 후보 중 알 입수가 허용된 종을 대상으로 한다. 종별 전용 입수처는 유지한다.
시작 포인트는 랜덤알 하나를 구매할 수 있는 금액이다.
이후 획득은 랜덤·구매·해금 경로를 쓴다. 경로별 조건은 [개체 레벨과 입수처](specs/game.md#개체-레벨과-입수처)를 따른다.

### 돌봄

돌봄은 클릭 한 번으로 시작한다. 사용자는 반응을 구경한다. 원하면 더 놀아줄 수 있다.
놀아주면 놀아주기 상태가 20분 붙는다. 이 상태 자체에는 효과가 없다.
놀아주기 쿨타임은 10분이다. 쿨타임이 지난 뒤 상태가 남아 있는 동안 다시 놀아주면 중첩이 오른다.
3중첩이 되면 오래 놀아주기 버프가 켜진다. 상태가 끝나면 중첩은 0으로 돌아간다.
오래 놀아주기 버프는 놀아준 한 마리의 친밀도 증가량을 일정 시간 높인다. 효과는 프리미엄먹이 버프보다 낮다.
장난감은 1회성이다. 사용자는 가방에서 장난감을 드래그해 포켓몬 위에 드롭한다. 한 번 놀아주면 1개를 소비한다.
장난감은 오래 놀아주기 버프와 같은 버프를 준다. 장난감 놀이는 일반 놀아주기와 같은 반응 애니메이션에 파티클 같은 효과를 더한다.
기본먹이는 무료이며 무제한이다. 기본먹이는 만복도를 일정량 회복한다. 회복 효율은 낮다.
상점에서 구매하는 프리미엄먹이는 만복도를 최대까지 채운다. 프리미엄먹이는 일정 시간 친밀도 증가량을 높인다. 버프는 먹이를 준 한 마리에게만 적용한다.
같은 먹이를 다시 주면 버프 시간을 기본 지속시간으로 갱신한다. 남은 시간을 더하지 않는다.
밥 주기에는 쿨타임이 있다. 만복도가 최대이거나 쿨타임 중이면 먹일 수 없다.
쿨타임은 개체별로 적용한다. 같은 개체의 기본먹이와 프리미엄먹이는 쿨타임을 공유한다. 다른 개체의 밥 주기는 막지 않는다.
쿨타임은 파티의 숨김 상태에서도 진행한다. 박스 보관 중에는 남은 시간을 보존한다. 복귀하면 남은 시간부터 이어간다.
기본먹이를 여러 번 주면 배고픔에서 서서히 회복할 수 있다. 쿨타임과 자연 감소를 고려해 회복 가능한 수치로 설계한다.
만복도는 높을수록 배부른 수치다. 배고픔 상태와 별개의 자원을 추가하지 않는다.
돌봄 수치는 [만복도와 돌봄](specs/balance.md#만복도와-돌봄)과 [버프와 친밀도](specs/balance.md#버프와-친밀도)를 따른다. 상세 계약은 [일상 사용 계약](specs/game.md#일상-사용-계약)을 따른다.

## 성격과 육성

원작 25개 성격을 사용한다. 성격은 다섯 축으로 움직임과 상태에 영향을 준다. 값과 명칭은 [성격 자료](../data/natures.json)를 따른다. 움직임 배율은 [params.ts](../src/motion/params.ts)를 따른다.
육성은 S5 규칙을 따른다.
친밀도는 감소하지 않는다. 만복도와 기분은 변한다. 숨긴 파티 포켓몬도 육성을 유지한다.
에이전트 보상은 토큰량이 아니라 에이전트의 작업 시간으로 계산한다. 작업 시간에는 적립 속도가 2배다.
수치는 [밸런스 수치](specs/balance.md)를 따른다. 계산은 [시간 처리](../src/state/time.ts), [상태 규칙](../src/state/rules.ts), [저장 규칙표](../src/save/rules.ts)에 있다.

## 도감 · 해금

### 진화

진화 조건을 충족하면 진화 가능 상태를 알린다. 사용자가 원할 때 직접 진화시킨다.
진화는 한 번에 다음 한 단계로만 진행한다. 다음 단계 조건도 이미 충족했다면 사용자가 다시 선택해 진화할 수 있다. 중간 단계를 건너뛰거나 자동으로 연속 진화하지 않는다. 현재 단계에 머무를 수 있다.
여러 진화 분기가 가능하면 사용자가 후보 중에서 선택한다.
리전폼 진화 조건을 충족하면 해당 경로에서는 지정한 리전폼으로 진화한다. 해당 조건이 없고 일반 조건을 충족하면 일반 폼으로 진화한다. 같은 경로의 폼을 임의로 선택하지 않는다.
진화 결과는 실제 진화 실행 시점의 조건으로 판단한다. 알림 시점에 결과를 고정하지 않는다. 실행 전에 결과 종과 폼을 보여주고 사용자 확인을 받는다.
진화 가능과 업적 달성은 화면 한쪽의 작은 배너로 잠깐 알린다. 클릭하지 않으면 배너는 사라진다. 진화 배너는 해당 개체의 상세 화면으로 연결한다.
업적 배너는 `업적 달성` 제목, 업적 표시와 이름, `바로가기` 버튼으로 구성한다. `바로가기`를 누르면 해당 업적의 보상 수령 화면으로 이동한다.
업적 배너는 화면 우측 아래에 한 번 표시한다. 미수령 보상이 있으면 헤더의 업적창 아이콘에 dot를 표시한다.
진화와 보상 수령은 사용자가 별도로 직접 진행한다.
친밀도는 개체별로 관리한다. 일반 개체의 완료한 진화는 이전 단계로 되돌리지 않는다. 지정한 단일 포켓몬 진화 계열은 아래 공유 `sid` 예외를 따른다.
진화하면 종만 바뀐다. 개체 식별자·레벨·누적 경험치·친밀도·성격·이로치·버프는 그대로다. 만복도와 남은 먹이 쿨타임도 그대로다. 파티·박스 위치와 숨김 상태도 그대로다.
진화 기록(`evolved`·`stage`)은 한 단계 늘어난다(`src/dex/evolve.ts` `evolve`).
이미 가진 종으로 진화하는 것을 막지 않는다. 이 진화에 따로 주는 보상은 없다.
박스에서 다시 꺼내거나 같은 종을 다시 얻어도 따로 주는 보상은 없다.

### 공유 `sid` 계열

전설·환상·준전설 등 지정한 진화 계열은 같은 `sid`의 한 개체로 관리한다. 친밀도·레벨 등 진행 상태를 공유한다.
선택 가능한 종 중 하나만 꺼낼 수 있다. 스탯은 현재 선택한 종의 기준을 적용한다. 단일 포켓몬 전용 재획득 불가 경고는 두지 않는다. 일반 진화는 되돌릴 수 없다.
코스모움에서 한 번 진화하면 솔가레오와 루나아라를 함께 제공한다. 둘 다 같은 `sid`의 교체 가능한 종으로 열린다. 각 종을 얻으려고 진화를 반복하지 않는다. 동시에 꺼낼 수 있는 종은 하나다.
진화 시점의 게임 시간이 낮이면 현재 종은 솔가레오가 된다. 밤이면 루나아라가 된다. 사용자는 진화할 종을 따로 선택하지 않는다. 낮과 밤의 기준은 [확률과 알](specs/balance.md#확률과-알)의 게임 시간을 따른다.
네크로즈마는 이 공유 `sid` 계열과 별개인 포켓몬이다.
솔가레오와 루나아라를 함께 제공하는 순간 도감에 두 종 모두 획득으로 기록한다. 아직 꺼내지 않은 종도 포함한다. 공유 `sid` 하나와 도감의 두 종 기록은 서로 다르다.
해당 계열의 종 선택은 박스에서 교체하는 흐름으로 제공한다. 상세 화면에서는 종을 선택하지 않는다.
파티에 같은 `sid`가 있으면 기존 칸의 종을 교체한다. 빈칸이 있어도 추가 칸을 차지하지 않는다. 교체해도 칸의 표시 상태는 바꾸지 않는다(`src/dex/forms.ts` `setForm`).

### 레벨과 사탕

도감 해금에는 개별 포켓몬의 레벨을 사용한다. 종마다 입수처를 구분한다. 구매 가능한 종은 해금 후 상점 구매 항목에 추가한다. 진화 전용 종은 상점에 추가하지 않는다.
예: 파이리 레벨 16에서 리자드를 해금한다. 리자드는 파이리를 진화시켜서만 얻는다.
종별 해금 조건은 [해금 자료](../data/unlocks.json)에 있다. 종 프로필은 [종 자료](../data/species.defaults.json)에 있다.
친밀도와 경험치는 별도로 관리한다. 경험치로 개체의 레벨이 오른다. 친밀도로 포인트를 얻고, 상점에서 경험사탕을 사서 레벨을 올린다.
경험사탕은 XS·S·M·L·XL 5종이다. 별도 도구인 이상한사탕은 개체 레벨을 1 올린다. 새 레벨의 경험치 진행은 0부터 시작한다.
개체의 최대 레벨은 100이다. 최대 레벨에서도 친밀도 성장과 포인트 적립은 계속한다.
100레벨에서는 이상한사탕을 사용할 수 없고 소비하지 않는다.
경험사탕 5종과 이상한사탕은 상점 구매, 업적 보상, 탐험 보상으로 얻는다. 탐험은 향후 확장이다.
사탕 6종은 처음부터 상점에서 판매한다. 별도 해금 조건을 두지 않는다. 가격으로 구매 시점을 조절한다. 가격과 경험치량은 [가격](specs/balance.md#가격)과 [성장](specs/balance.md#성장)을 따른다.
경험사탕과 이상한사탕은 파티와 박스의 보유 개체 모두에게 직접 사용할 수 있다. 숨김 여부로 제한하지 않는다. 사용으로 배치·표시 상태를 바꾸지 않는다. 박스의 시간에 따른 성장 정지는 유지한다.
사용자는 대상 한 개체와 사용 수량을 선택한다. 여러 개를 한 번에 사용할 수 있다. 경험사탕은 획득 경험치와 예상 레벨을 확인한 뒤 사용한다. 이상한사탕은 예상 레벨을 확인한 뒤 사용한다.
이상한사탕의 최대 선택 수량은 보유량과 `100 - 현재 레벨` 중 작은 값이다.
100레벨인 개체에는 경험사탕을 사용할 수 없다. 그 전에는 100레벨 도달에 필요한 사탕 개수까지만 선택한다. 마지막 사탕의 초과 경험치는 소멸한다. 소멸할 양은 사용 전에 표시한다.

### 포인트 적립

친밀도는 포인트 적립으로 소모하지 않는다. 현재 친밀도가 높을수록 포인트 적립 간격이 짧아진다. 친밀도가 새로 증가하지 않아도 시간에 따라 포인트를 얻는다.
적립 간격은 [기준점](specs/balance.md#기준점)을 따른다.
파티에 배치한 개체가 각자의 친밀도에 따라 포인트를 적립한다. 개체별 적립 결과를 보유 포인트에 합산한다. 숨긴 파티 개체도 적립을 유지한다. 파티 밖의 개체는 적립하지 않는다.
포인트의 부분 진행은 계정에 하나로 모은다. 박스 개체는 부분 진행에 더하지 않는다.
친밀도가 올라 적립 간격이 바뀌어도 이전 경과 시간에 새 속도를 소급 적용하지 않는다.
앱 종료 중에는 적립하지 않는다.
해금은 개체의 즉시 지급이나 무료 재소환을 뜻하지 않는다.

### 파티와 박스

숨김은 화면 표시만 끈다. 숨긴 파티 개체도 친밀도 성장, 배고픔 변화와 버프 시간 경과를 유지한다.
박스 보관은 파티에서 개체를 빼는 것이다. 보관 중에는 포인트를 적립하지 않는다. 친밀도·배고픔·남은 버프 시간을 보존한다. 다시 배치하면 보존한 상태에서 이어간다.
상세 상태 표는 [파티 표시와 박스 보관](specs/game.md#파티-표시와-박스-보관)을 따른다.
모두 숨기거나 박스에 보관했으면 트레이에서 관리 화면을 열고 파티로 이동한다. 숨긴 개체는 다시 표시한다. 파티가 비었으면 박스에서 보유 개체를 골라 배치한다.
도감 해금, 개체 획득, 보유 개체 배치는 서로 다른 상태다.
같은 종을 여러 개체 보유할 수 있다. 같은 종의 개체들을 동시에 파티에 배치할 수 있다.
새 개체는 사용할 수 있는 빈 파티 칸에 배치한다. 빈 칸이 없으면 박스에 보관한다. 교체는 선택한 파티 개체와 박스 개체를 한 번에 맞바꾼다.
새 개체가 파티에 배치되면 꺼낸 상태로 시작한다. 구매·부화·특수 획득에 같은 규칙을 적용한다.
박스 개체를 빈 칸에 배치하거나 파티 개체와 맞바꿔도 들어온 개체는 꺼낸 상태다.
상세 계약은 [개체 획득과 파티 교체](specs/game.md#개체-획득과-파티-교체)를 따른다.
새 게임의 파티는 2칸으로 시작한다. 상점에서 포인트로 2칸을 추가 구매한다. 업적으로 나머지 2칸을 해금한다. 최대 파티는 6칸이다.
구매와 업적에 공통된 필수 해금 순서를 두지 않는다. 칸 가격은 [가격](specs/balance.md#가격)을 따른다.
박스에는 게임 규칙상 보유 개체 수 제한을 두지 않는다. 박스는 원작처럼 30칸(6열×5행) 박스 여러 개로 나누고 넘겨 본다. 박스가 모두 차면 새 박스를 자동으로 추가한다. 검색은 모든 박스를 대상으로 한다.
첫 번째 칸 업적은 파티의 두 마리를 실제로 화면에 꺼내면 달성한다. 숨긴 채 두 칸에 배치한 것만으로는 달성하지 않는다. 달성 후 다시 숨겨도 달성을 유지한다. 업적창에서 보상을 받으면 한 칸을 추가한다.
같은 종의 서로 다른 두 개체도 첫 번째 칸 업적에서 인정한다. 파이리 두 마리를 꺼내도 달성한다.
두 번째 칸 업적의 조건은 "최초로 포켓몬 50레벨 달성"이다. 교환으로 받은 개체는 인정하지 않는다. 이 저장에서 개체가 레벨업으로 50레벨에 도달해야 달성한다.
규칙은 [파티 칸 확장과 박스 수용](specs/game.md#파티-칸-확장과-박스-수용)을 따른다.

## 상점

상품 가격은 [가격](specs/balance.md#가격)을 따른다. 기존 구매 권리의 이식은 [V2 → V3 변환 규칙](specs/modules.md#v2--v3-변환-규칙)을 따른다.
가방은 칸 수와 종류별 보유 수량을 제한하지 않는다. 보관 제한 없음은 사탕의 사용 수량 한도를 바꾸지 않는다.
상점 구매로는 도구 한 종류를 999개까지만 채운다. 한 번에 살 수량은 포인트와 이 상한을 따른다. 규칙은 [상점 구매 창](specs/game.md#상점-구매-창)을 따른다.

### 거래

구매·사용·보상 수령은 관련 상태 변경을 하나의 거래로 처리한다. 성공하면 전부 반영한다. 실패하면 전부 이전 상태를 유지한다.
완료된 거래를 재시도해도 중복 지급하거나 비용을 다시 차감하지 않는다.
거래 실패 후에는 실패 처리만 제공한다. 실패 복구용 선택값 보존, 다시 시도 버튼, 자동 재시도를 두지 않는다.
부화·진화·교체에도 같은 거래 원칙과 실패 처리를 적용한다. 부화 저장에 실패하면 알은 부화 가능 상태로 남는다. 다시 열면 그 시점의 조건으로 결과를 새로 정한다.
진화·교체를 확정 전에 취소하면 아무 상태도 바꾸지 않는다. 공유 `sid` 종 교체, 첫 선택, 놀이공간 적용도 실패하면 이전 상태를 유지한다.
첫 선택을 확정하기 전에 닫으면 다음 실행 때 선택 화면을 다시 연다.

### 가방과 먹이

S5는 획득과 사용을 분리한다. 사탕 6종은 획득 경로와 관계없이 공통 가방에 종류별로 보관한다.
사용자는 가방에서 사탕, 대상 개체, 수량을 순서대로 선택한다. 결과를 확인한 뒤 직접 사용한다.
상점은 무료 기본먹이와 별도로 프리미엄먹이를 판매한다.

### 알과 돌보미집

알은 구매 직후 돌보미집에 배치한다. 구매가 완료되면 준비 타이머를 바로 시작한다. 별도 부화 시작 조작은 요구하지 않는다.
랜덤알은 준비 시간이 지나면 부화 가능 상태가 된다. 돌봄 같은 활동은 대기시간을 단축한다. 사용자가 직접 열어야 부화한다.
알별로 준비 진행도를 관리한다. 알 돌봄 행동은 쓰다듬기와 노래 들려주기다. 상점은 부화시간 단축 도구를 팔지 않는다.
준비 시간과 단축량은 [확률과 알](specs/balance.md#확률과-알)을 따른다.
돌보미집은 메뉴로 구성한다. 돌보미집은 박스 메뉴 안에 둔다. 알은 데스크톱 놀이공간에 배치하지 않는다.
돌보미집에는 알을 최대 6개 배치한다. 배치한 알은 각자의 타이머로 동시에 진행한다. 돌봄은 선택한 알에 개별 적용한다. 파티 칸과 돌보미집의 알 칸은 별개다.
알의 부화 준비가 완료되는 순간 작은 알림을 한 번 제공한다. 알림은 화면 한쪽의 작은 배너로 잠깐 표시한다.
배너의 `바로가기`를 누르면 돌보미집을 연다. 누르지 않으면 배너는 사라진다. 부화·진화·업적 배너는 모두 `바로가기` 버튼을 쓴다. 알은 직접 부화할 때까지 유지한다.
돌보미집이 6개의 알로 가득 차면 추가 알 구매를 막는다. 부화 가능한 알도 직접 열기 전까지 칸을 차지한다. 직접 부화해 칸이 비면 다시 구매할 수 있다. 구매한 초과 알을 따로 보관하지 않는다.

### 알 결과

랜덤알의 결과는 해금한 종 중 알 입수처가 허용된 종으로 제한한다. 진화 전용 종은 해금해도 제외한다.
랜덤알은 무작위 결과와 부화 과정을 제공한다. 종 지정 구매는 원하는 종을 확정해서 얻는 대신 더 비싸다.
구매 시 해당 알의 개체 식별자(sid)에 가능한 종 범위를 저장한다. 구매 후 새로 해금한 종은 이미 구매한 알에서 나오지 않는다.
알 구매부터 직접 열기 직전까지 행동 조건을 쌓을 수 있다. 준비 완료 뒤에도 돌봄과 탐색을 이어간다. 직접 열 때까지 충족한 조건으로 결과를 결정한다.
일반 알에서 행동 조건을 충족하면 그 조건에 대응한 포켓몬으로 부화한다. 미충족이면 저장한 범위에서 무작위로 부화한다. 행동을 하지 않아도 부화는 가능하다.
알 행동 조건을 지정하는 종에는 조건을 하나만 둔다. 같은 종에 여러 대체 조건을 두지 않는다. 서로 다른 종의 조건을 한 알에서 여러 개 충족하는 것은 가능하다.
여러 행동 조건을 충족해 대응 종이 여러 개이면 그 종들 중 수집 난이도 가중치로 추첨한다. 후보가 한 종이면 그 종으로 부화한다. 충족하지 않은 종을 섞지 않는다.
사용자가 시도하며 조건을 알아가는 경험을 지향한다.
행동 조건을 충족하지 않은 일반 무작위 부화는 종별 수집 난이도 1~5에 따른 공통 가중치를 사용한다. 종마다 상세 확률을 직접 입력하지 않는다. 1은 얻기 쉬운 쪽, 5는 얻기 어려운 쪽이다.
확률과 가중치는 [확률과 알](specs/balance.md#확률과-알)을 따른다.

### 입수처

입수처는 종마다 지정한다. 알 전용 종과 특수 기믹 전용 종도 둔다. 특수 기믹 전용 종은 구매나 알에서 나오지 않는다. 해금됐다는 이유로 모든 입수처에 자동 포함하지 않는다.
[스펙 미확정] 종별 특수 기믹의 내용은 정하지 않았다. 보류한다.
특수 기믹 전용 종은 선행 도감 해금을 요구하지 않는다. 해당 기믹을 수행하면 도감 해금과 개체 획득이 함께 일어난다.
해금 후 입수처와 획득 제한은 종마다 지정한다. 기믹으로 처음 얻은 뒤 상점이나 알에서 추가 획득하는 종도 둔다. 계속 기믹으로만 얻는 종과 단일 포켓몬도 따로 지정한다. 최초 획득이 기믹이었다는 이유로 후속 상점·알 입수를 일괄 금지하지 않는다.
알 전용 종에도 도감 해금 수 같은 후보 진입 조건을 지정할 수 있다. 예: 도감 100종 이상 해금. 조건 달성은 무작위 획득 기회를 열며 즉시 개체를 지급하지 않는다.
조건부 입수 종은 조건 충족 시 도감 해금과 허용 입수처 활성화를 진행한다. 실제 획득은 해당 입수 경로를 이용했을 때 일어난다. 알 전용 종도 조건 충족 시 해금한 뒤 알 후보에 포함한다.

### 단일 포켓몬

단일 포켓몬으로 지정한 종은 한 저장에서 딱 한 번만 획득할 수 있다.
단일 포켓몬은 일반 알에서 획득할 수 없다. 일반 무작위 결과와 행동 조건 결과에서 모두 제외한다.
전설·준전설·환상·울트라비스트 98종(진화 전 기본형)을 단일 포켓몬으로 지정한다. 이 종은 단일 포켓몬 알에서만 나온다. 진화형 7종은 진화로 얻는다.
단일 포켓몬 알은 랜덤준전설알·랜덤울트라비스트알·랜덤패러독스알·랜덤환상알·랜덤전설알이다. 랜덤패러독스알은 패러독스 20종을 담는다.
랜덤알을 열 때 낮은 확률로 포켓몬 대신 단일 포켓몬 알이 나온다. 상점에서도 단일 포켓몬 알을 비싸게 판다.
단일 포켓몬 알의 후보는 아직 얻지 않은 종이다. 알 행동 조건은 보지 않는다.
랜덤패러독스알의 가격·확률·구조는 랜덤울트라비스트알과 같다.
확률과 가격은 [확률과 알](specs/balance.md#확률과-알)과 [가격](specs/balance.md#가격)을 따른다. 입수처는 `data/eggs.json` 에서 바꾼다.
화석 15종과 패러독스 20종은 처음부터 해금하지 않는다. 알에서 나와야 해금된다. 옛 저장을 읽을 때 얻지 않은 이 종들의 해금을 한 번 지운다.

### 도감 집계와 공개

도감 해금 수는 보유 여부와 관계없이 해금된 서로 다른 종의 수다. 초기 후보와 레벨 조건으로 해금한 미진화 종도 포함한다. 중복 개체 획득은 종 수를 늘리지 않는다.
일반 폼과 리전폼은 기본 도감번호가 같아도 별도 종으로 취급하는 독립 도감 항목이다. 일반 대검귀는 `503`, 히스이 대검귀는 `503-1`이다. 각 항목은 독립적으로 해금한다. 둘 다 해금하면 2종으로 센다.
도감에서 구매·알·진화의 입수 조건은 명확히 표시한다. 특수 기믹은 발견 전에는 힌트만 표시한다. 발견 후에는 정확한 방법을 공개한다.
[스펙 미확정] 특수 기믹의 발견 판정 시점은 정하지 않았다. 보류한다.
알의 기본 입수 조건과 행동으로 결과를 정하는 숨겨진 조건은 서로 다르다. 발견 전에는 정답 행동이나 충족한 포켓몬 목록을 직접 보여주지 않는다. 알의 반응과 작은 힌트로 탐색하게 한다.
[스펙 미확정] 실제 힌트·반응 표현은 정하지 않았다. 보류한다.
행동 조건을 실제로 충족하고 대응 종이 부화하면 해당 조건을 발견으로 기록한다. 조건 없이 일반 무작위 부화로 얻으면 발견으로 처리하지 않는다.
여러 종의 조건 중 A가 부화했으면 A 조건만 새로 발견한다. 발견한 조건은 도감에 정확히 기록한다.
에이전트 작업량으로 부화하는 방식은 채택하지 않았다. 상세 계약은 [활동에 따른 부화 대기시간 단축](specs/game.md#활동에-따른-부화-대기시간-단축)을 따른다.

### 민트와 진화의돌

민트는 상점에서 사서 가방에 보관한다. 확인하면 성격이 바뀌고 민트 1개를 소비한다. 현재와 같은 성격으로는 바꿀 수 없다. 파티와 박스의 개체 모두에 사용할 수 있다.
민트는 성격별 21종이다. 보정 있는 성격 20개마다 하나를 둔다. 보정 없는 성격 5개(노력·온순·수줍음·변덕·성실)는 성실민트 하나가 함께 맡는다. 성실민트를 쓰면 그 5개 중 하나를 고른다.
성격 변경의 입구는 포켓몬 상세의 `성격 변경` 이다. 창은 왼쪽에 지금, 오른쪽에 바꾼 후를 둔다. 오른쪽에서 성격을 고르면 필요한 민트를 보인다. 가방에서 민트를 쓰면 대상을 고른 뒤 같은 창이 열린다.
진화의돌은 원작에서 돌로 진화하는 종의 진화 조건이다. 상점에서 사서 가방에서 사용하면 진화 확인 화면으로 이어진다. 확인하면 돌 1개를 소비하고 진화한다.

### 이로치

이로치는 해당 도감 항목의 획득 여부로 기록한다. 별도 종 수는 늘리지 않는다.
이로치는 낮은 확률의 알 부화 또는 상점 아이템 사용으로 얻는다. 단일 종은 약으로 이로치가 된다.
비싼 `모습이 바뀌는 약`으로 기존 개체를 이로치로 바꾼다. 0원인 `돌아오는 약`으로 일반색으로 되돌린다. 상품명은 가칭이다. 확률과 가격은 [밸런스 수치](specs/balance.md)를 따른다.
일반 개체는 최초 획득 시 일반색으로 시작한다. 알에서 이로치로 태어났거나 약으로 바꾼 개체는 숨김 해제·박스 복귀 후에도 이로치를 유지한다.
이로치 개체는 진화 후에도 이로치를 유지한다. 돌아오는 약으로 일반색으로 바꿔도 도감의 이로치 획득 기록은 남는다.
알 행동 조건은 결과 종에만 영향을 준다. 이로치 여부는 별도의 동일한 낮은 확률로 추첨한다. 행동 조건으로 정해진 종도 이로치가 될 수 있다. 돌봄으로 이로치 확률을 높이지 않는다.

## 커맨드 처리기

명령 계약은 [공유 타입](../src/shared/types.ts)과 [등록 처리기](../src/main/commands.ts)를 따른다. 메뉴·CLI·mailbox는 같은 명령 처리 경로를 사용한다.
명령 이름은 [공유 타입](../src/shared/types.ts)의 `CommandName`이다. `feed`, `play`, `poke`, `evolve`, `party.show`, `party.hide`, `party.remove`, `party.place`, `party.swap`, `party.keep`, `box.sort`, `box.move`, `box.rename`, `egg.care`, `egg.open`, `bag.use`, `achievement.claim`, `tutorial.skip`, `tutorial.done`, `pet.set`, `pet.look`, `pet.form`, `starter.pick`, `agent.connect`, `agent.disconnect`, `settings.set`, `shop.buy`, `snapshot`, `quit`이다.
설정창이 쓰는 이름은 [명령 다리](../src/tx/bridge.ts)가 푼다. 파티 배치는 `party.place`·`party.swap`·`party.keep`이 맡는다.

`companion`은 포켓몬 인자를 받지 않는다. 빈 파티이면 선택창을 연다. 선택 취소와 저장 실패를 구분한다.
`pet.set`의 위치 변경은 저장에 성공한 뒤 성공으로 응답한다. 마우스 위치 변경도 같은 명령을 사용한다.
`pet.set`의 `size`는 그림 크기 단계 번호(1~5)다. 단계표는 [저장 규칙표](../src/save/rules.ts)의 `SIZE_STEPS`다.

## 저장 v2와 S5 전환

저장 계약은 [저장 v3 타입](../src/shared/save-v3.ts)에 있다. 개체(`pets`)와 파티 칸(`party.slots`)이 나뉜다. 저장·복원 규칙은 [저장 모듈](../src/save/store.ts)과 [저장 규칙](../src/save/rules.ts)을 따른다.
옛 `SaveV2`(`party` 가 `Pet[]`)는 [옛 저장 읽기](../src/save/legacy.ts)가 읽어 v3 로 옮긴다. 이식은 `SaveV2`를 `SaveV3`로 한 번 변환한다.
처음 열 때 v2 를 v3 으로 옮기고 원본을 `save.json.v2.bak` 에 남긴다.
`species`는 실제 종이다. `look`은 표시 그림이다. 개체 `id`는 진화 후에도 유지한다. writer 잠금과 mailbox를 유지한다.
S5는 도감 등록, 개체별 육성 기록, 파티 배치, 도구 재고, 알 상태를 나눈다. 파티 밖 개체는 박스에 보관한다.
새 화면에 별명·모습이 없어도 기존 `nick`, `look`과 재고를 지우지 않는다.

## S5 설정창과 메뉴

설정창의 탭은 파티 / 박스 / 도감 / 상점 / 가방이다. 헤더에는 보유 포인트와 창 조작 단추 자리를 둔다.
업적창 아이콘과 설정 아이콘은 탭 줄 오른쪽에 둔다. 미수령 보상이 있으면 업적창 아이콘에 dot를 표시한다.
업적창과 설정은 보던 탭 위에 여는 모달이다. 닫으면 보던 탭으로 돌아간다.
파티 탭에는 파티 칸만 둔다. 박스는 별도 메뉴이며 돌보미집을 그 안에 둔다.
파티는 2열×3행이다. 빈 칸과 잠긴 칸을 구분한다. 상세에서 숨기기·다시 표시와 소환 해제를 구분한다.
설정창은 별명과 모습 선택을 제공하지 않는다. 연결 설정은 설정 모달 안에 둔다.
성격 변경은 가방에서 민트를 사용하는 방식이다. 이로치 색상 변경은 약을 사용한다.
우클릭 메뉴는 포켓몬 위에서 우클릭할 때만 연다. 메뉴는 OS 기본 메뉴가 아니라 앱이 직접 그린다. 포켓몬이 없는 놀이공간 영역의 우클릭은 가로채지 않고 뒤의 앱으로 넘긴다.
메뉴는 이름·상태 / 밥 주기·놀아주기 / 설정의 세 묶음이며 구분선으로 나눈다. 우클릭 메뉴에는 종료를 두지 않는다.
메뉴 첫 줄의 상태는 만복도 구간 이름과 기분 구간 이름으로 보여준다. 설정창은 같은 정보를 수치 막대로 보여준다. 만복도 구간은 배고픔 말풍선의 구간과 같다. 구간은 [밸런스 수치](specs/balance.md)를 따른다.
트레이 메뉴는 설정과 종료를 제공한다.
전용 preload, contextIsolation, sandbox, IPC sender·최상위 frame 검사를 유지한다. 상세 수용 조건은 [게임 규칙](specs/game.md)을 따른다.

## 교환

이 절은 교환과 계정의 설계 규칙이다.
친구끼리만 포켓몬을 교환한다. 한 사람이 일회성 공유 채널의 링크를 보내면 그 채널에서만 교환한다.
서버는 Supabase를 쓴다. 서버 연결에는 `@supabase/supabase-js`를 쓴다.
교환에는 로그인이 필요 없다. 단일 포켓몬은 교환할 수 없다. 첫 선택 포켓몬은 제한 없이 교환할 수 있다.
교환해도 진화하지 않는다. 교환 진화 종은 `연결의끈` 도구로 진화한다.
교환으로 받은 개체는 두 번째 파티 칸 업적에 인정하지 않는다. 규칙은 [파티 칸 확장과 박스 수용](specs/game.md#파티-칸-확장과-박스-수용)을 따른다.
교환 화면은 설정창의 `가방` 탭 옆에 둔다.
배틀은 설계에서 제외한다.
로그인은 선택 기능이다. 방법은 아이디+비밀번호(중복검사)와 GitHub다. 이메일 로그인과 Google 로그인은 없다.
아이디는 영어만 받는다. 가입할 때 이름도 받는다. 본인인증은 하지 않는다. 로그인하지 않아도 교환은 된다.
로그인하면 저장 사본을 서버에 둔다(클라우드 저장). 게임은 계속 로컬에서 돈다. 정본은 `save.json`이다.
같은 계정은 나중에 켜진 PC 하나만 활성이다. 먼저 켜진 PC는 로그아웃되고 서버에 저장하지 못한다.
온라인이면 자동 저장한다. 오프라인에서 한 진행은 다시 연결된 뒤 사용자가 저장 버튼을 눌러야 올라간다.
