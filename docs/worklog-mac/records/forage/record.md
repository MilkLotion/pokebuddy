# 줍기 — 돌아다니다 포인트·도구·포켓몬을 주워 옴 (2026-09-29, 맥)

## 설계

### 사용자 요청과 결정 (2026-09-29)

- 요청: "포켓몬들이 움직이다가 낮은확률로 아이템/포켓몬 획득."
- 결정 1: 주울 수 있는 것은 포인트, 도구, 진화용 도구, 포켓몬이다.
- 결정 2: 자주 나오는 순서는 포인트 > 도구 > 진화용 도구 > 포켓몬이다.
- 결정 3: 빈도는 도구 하루 5번, 포켓몬 3일에 1번이다.

### 제안값 (Claude 제안, 사용자 확인 전)

- 활동 시간: 앱이 켜져 있고, 무대에 보이는 파티 포켓몬 중 깨어 있는 마리가 하나 이상일 때만 흐른다. 하루는 활동 8시간으로 어림한다.
- 판정: 활동 시간 10분마다 한 번(하루 48번). 한 번에 결과는 하나다.

| 결과 | 판정당 확률 | 하루 어림 | 양 |
|---|---|---|---|
| 포인트 | 약 16.7% | 약 8번 | 10~30P 균등 |
| 도구 | 약 10.4% | 5번 (결정) | 1개 |
| 진화용 도구 | 약 2.1% | 약 1번 | 1개 |
| 포켓몬 | 1/144 (약 0.7%) | 3일에 1번 (결정) | 1마리 |
| 없음 | 나머지 | — | — |

- 도구 후보: 상점가가 1~200P인 가방 도구다. 기본먹이, 돌아오는 약, 모습이 바뀌는 약은 뺀다. 가중치는 1/가격이다. 민트(21종, 설계 당시 25종으로 잘못 적음)는 묶어서 후보 하나(1/100)로 보고, 뽑히면 그중 하나를 균등으로 고른다. 가방 상한 999에 닿은 도구면 그 판정은 없음이다.
- 진화용 도구: 24종 균등.
- 포켓몬: 랜덤알과 같은 후보와 같은 추첨(난이도 가중치, 이로치 1/1000)이다. 빈 파티 칸이 있으면 파티에, 없으면 박스에 넣는다. 둘 곳이 없으면 그 판정은 없음이다.
- 주운 마리: 조건을 만족하는 마리 중 무작위 하나다. 알림 문구에 그 이름을 쓴다.
- 알림: 기존 알림 배너 체계를 쓴다.

### 수용 조건

- 활동 시간이 아닐 때(전부 숨김, 전부 잠, 앱 꺼짐)는 판정하지 않는다.
- 네 결과가 저장에 반영되고 배너가 한 번 뜬다.
- 저장이 실패하면 부분 반영하지 않는다.
- 판정은 고정 난수로 시험할 수 있다.

## 작업

- 새 모듈 `src/find/`를 만들었다.
  - `src/find/rules.ts` `FIND_RULES`: 수치를 한 곳에 모았다. 주석에 사용자 결정과 제안값을 구분했다.
  - `src/find/core.ts`: 순수 함수다(now·rand 입력). `applyFind`가 활동 시간을 쌓고, 10분마다 `rollOnce`를 부른다.
- 호출: `src/main/game.ts` `tick`이 `applyTime` 뒤에 줍기를 부른다. 시간 적용과 줍기를 writer 잠금의 `write` 한 번으로 쓴다. 쓰기가 실패하면 줍기도 반영하지 않는다.
- 활동 시간: `src/main/app.ts` `stateTick`이 폴링마다 쌓는다. 무대에 `awakeIds()`를 새로 두었다(`src/main/stage.ts`, `src/main/stage-group.ts`). writer가 아니거나, 화면 잠금이거나, 직접 숨김이거나, 깨어 있는 마리가 없으면 쌓지 않는다.
- 저장: 선택 필드 `find`(`activeMs`, `seq`, 최근 20건 `log[]`)를 더했다. 저장 형식 번호는 3 그대로다. 정규화는 `src/save/v3.ts` `normalizeFind`다. 재시작해도 활동 시간이 이어진다.
- 알림 배너: 키 `find:<id>`. 같은 순간이면 부화 → 진화 → 업적 → 줍기 순서다(`src/notify/queue.ts`). 제목 `줍기`, 본문 "피카츄가 경험사탕S를 주웠어요" / "피카츄가 120P를 주웠어요" / "피카츄가 이브이를 데려왔어요". `바로가기`는 도구 → 가방, 포인트 → 상점, 포켓몬 → 그 개체 상세다. 이를 위해 `ManageRoute`에 `bag`·`shop`을 더했다.
- 무대 연출: `stages.say`를 재사용했다. 주운 마리 위에 말풍선 "경험사탕S를 주웠어" / "이브이를 데려왔어"를 5초 띄운다.
- 문자열: `lib/i18n/ko.json`, `lib/i18n/en.json`.
- 문서: `docs/specs/game.md` "줍기" 절, `docs/specs/balance.md` "줍기" 절, `docs/terms.md` `줍기` 행, `docs/specs/modules.md` `src/find` 행.
- 개발용: `POKEBUDDY_FIND_ROLL_MS=1000 npm start`로 판정 주기를 1초로 줄인다(개발 실행에서만). 대체됨: 아래 "마리별 초당 판정으로 변경"의 `POKEBUDDY_FIND_RATE`.

### 설계와 달라진 점 (관찰)

- 민트는 21종이다(설계에는 25종으로 적었다). 묶음 가중치 1/100은 그대로다.
- 도구 후보: 프리미엄먹이, 장난감, 경험사탕XS·S·M·L, 이상한사탕, 민트 묶음. 경험사탕XL(320P)은 200P 상한으로 빠진다.
- 박스는 가득 차면 자동으로 늘어난다. 그래서 "둘 곳 없음"은 생기지 않는다. 판정 없음은 후보가 없을 때와 가방이 999개일 때만이다.
- 한 틱에 최대 20번 판정한다. 넘는 활동 시간은 버린다.

## 피드백과 수정

### 확률 재조정 (2026-09-29)

- 사용자 원문: "30분동안 한포켓몬이 1개 발견할까말까 할 정도로 확률을 생각하긴했거든? 항목별 가중치는 크게 생각안하긴했는데 얼추 포켓몬 희귀도처럼 하면 될거같기도하고?"
- Claude가 두 안(포켓몬 가중치 5 또는 1)과 포인트 양 세 안을 보였다. 사용자는 "포켓몬 가중치 1"과 "5~10P"를 골랐다.
- 결정: 판정은 마리마다 한다. 한 마리의 한 번 판정에서 주울 확률은 20%다(30분에 약 49%). 항목 가중치는 포인트 100, 도구 50, 진화용 도구 20, 포켓몬 1이다. 포인트는 5~10P 균등이다.
- 이 결정이 앞의 "도구 하루 5번, 포켓몬 3일 1번"을 대신한다. 위 설계 표는 대체된 값이다.
- 참고(하루 활동 8시간): 1마리 하루 포인트 5.6, 도구 2.8, 진화용 도구 1.1번, 포켓몬 약 18일에 1번. 6마리면 포켓몬 약 3일에 1번.
- 수정: `src/find/rules.ts`, `src/find/core.ts`(`rollOnce(save, petId, …)` 마리별), `docs/specs/balance.md`, `docs/specs/game.md`, `src/tools/selftest-find.ts`. 한 틱 최대 10차례(6마리면 60번)는 제안값이다.
- 검수: selftest-find 포함 25개 통과, `npm run check` 통과.

### 마리별 초당 판정으로 변경 (2026-09-29)

- 사용자 원문: "너무 한번에 다같이 줍는느낌인데 POKEBUDDY_FIND_ROLL_MS=1000 커맨드때문에 그런거야? 모든 포켓몬들이 개별확률로 돌아야해. 30분에 한개 주을까말까하게 확률을 하면 음 대충 매초 1/2000 의 확률로 주워야해."
- 원인(Claude 분석): (1) 앱 전체 활동 시간 10분마다 모든 마리가 같은 순간에 판정했다. (2) 개발 변수로 주기를 1초로 두면 15초 틱마다 밀린 판정을 몰아서 했다.
- 결정: 마리마다, 그 마리가 조건을 만족한 1초마다 1/2000 확률로 줍는다. 마리끼리 독립이다. "10분마다 20%" 결정을 대신한다.
- 참고(하루 활동 8시간): 1마리 하루 기대 약 14.4건. 포인트 약 8.4, 도구 4.2, 진화용 도구 1.7, 포켓몬 약 12일에 1번. 6마리면 포켓몬 약 2일에 1번. 30분에 한 마리가 무언가를 주울 확률 약 59%.
- 작업
  - `src/main/app.ts`: 폴링마다 마리별 조건 만족 시간을 메모리 맵(petId → ms)에 쌓는다. 조건은 무대에 나옴, 직접 숨기지 않음, 깨어 있음이다. 게임 틱에 맵을 넘기고 비운다. 저장 쓰기가 실패하면 비우지 않는다.
  - `src/main/game.ts` `capEach`: 마리마다 흐른 시간을 넘는 몫을 자른다.
  - `src/find/core.ts` `applyFind`: 마리마다 1 − (1 − 1/2000)^(초)로 한 번 굴린다. 한 틱에 마리당 최대 1건이다. 마리당 60초분까지만 센다(`FIND_RULES.maxMsPerTick`, 제안값). 항목 고르기는 `findOne`(옛 `rollOnce`)이다.
  - 저장: 판정이 무기억이라 쌓인 시간을 저장하지 않는다. `FindV3`에서 `activeMs`를 뺐다. 옛 `find.activeMs`는 `normalizeFind`가 버린다. 남는 필드는 `seq`와 `log`다. 위 "작업" 절의 `activeMs` 설명은 대체됐다.
  - 개발 변수: `POKEBUDDY_FIND_ROLL_MS`를 없앴다. `POKEBUDDY_FIND_RATE=<양의 정수>`로 초당 확률을 배율 × 1/2000로 올린다(상한 1, 개발 실행만). 예: `POKEBUDDY_FIND_RATE=100 npm start`는 마리당 초당 5%다.
  - 문서: `docs/specs/game.md`, `docs/specs/balance.md`, `docs/specs/modules.md`, `docs/terms.md`.
- 검수: `npm run build`, `npm run check` 통과. selftest find, save, notify, manage, play, stage, screens, commands, bag, snapshot, mail, flow 통과. `git diff --check` 통과.
- 실기 확인: 여러 마리가 다른 틱에 흩어져 줍는다. 같은 틱이면 배너가 하나씩 뜬다. 잠든 마리와 숨긴 마리는 줍지 않는다.

### 실기 피드백: 아직 한꺼번에 줍는다 (2026-09-29)

- 사용자 원문: "아직도 한번에 주워온다. 개별로 안줍고"
- 원인(Claude 분석): 확률은 마리별이지만 굴림을 저장 주기(`STATE_RULES.saveMs`, 약 15초)의 게임 틱에서 한꺼번에 한다. 그 사이에 주운 것이 같은 순간에 말풍선·배너로 뜬다. 배율 100이면 15초에 마리당 54%라 거의 매번 겹친다.
- 수정 방향: `stateTick` 폴링(0.5초)마다 마리별로 굴리고, 주우면 그 자리에서 한 건만 저장에 쓰고 말풍선과 배너를 바로 띄운다. 대체됨: 사용자 지시로 전역 1초 시계의 틱마다 판정한다(`records/timer-tick/record.md`). 진행 중.

### 사용자 확인 대기

- 제안값: 도구 후보 200P 이하·가중치 1/가격, 마리당 한 틱 최대 60초분·1건.
- 배너 배치: 제목 `줍기`, 문구는 본문.

### 실기 확인 항목

1. 배너 두 줄 문구가 잘리지 않는다.
2. `바로가기`가 가방·상점·상세로 간다.
3. 말풍선이 뜬다.
4. 데려온 포켓몬이 빈 칸에 나와 무대에 바로 보인다.
5. 모두 잠들었을 때, 직접 숨겼을 때, 화면을 잠갔을 때 줍기가 멈춘다.
6. 재시작 뒤에도 쌓인 활동 시간이 이어진다.
