# 관리·상세 창 시간 표시를 1초마다 (2026-09-29, 맥)

## 설계

- 사용자 실기 피드백(2026-09-29): "초가 5초에 한번씩 타이머 되는거같은데? 알이나 배고픔 그런게 5초에 한틱으로 줄더라고."
- 원인(Claude 분석): 관리 창(`src/renderer/manage.ts`)이 5초마다 스냅샷을 다시 읽고 전체를 다시 그린다. 알 남은 시간, 쿨타임, 배고픔 표시가 그때만 바뀐다.
- 방향(Claude 제안): 전체 다시 그리기 주기는 그대로 둔다. 스냅샷에 기준 시각과 목표 시각(또는 초당 감소량)을 담고, 렌더러가 1초 타이머로 해당 글자와 게이지만 갱신한다. 5초 새로 읽기 때 실제 값으로 맞춘다. 보간값이 실제보다 앞서지 않게 한다.
- 범위: 관리 창, 파티 상세 기기 창(`src/renderer/pet.ts`), 도감 기기 창에 같은 표시가 있으면 함께.

### 방향 변경: 전역 1초 시계 (2026-09-29)

- 사용자 원문: "전체는 지금처럼 5초마다 실제 값으로 맞춥니다 << 이것도 1초. 줍기판정도 1초. 앱 자체의 전역으로 타이머 기능 만들고, 그게 1초마다 갱신. 확률이나 시간 등등은 그 시간값 보게 해"
- 결정 1: 앱 전역 시계를 만든다. 1초마다 틱을 낸다.
- 결정 2: 시간·확률 계산은 그 틱의 시각값을 본다.
- 결정 3: 화면 전체 갱신과 줍기 판정도 1초마다 한다. 위 "보간" 제안은 대체됐다.
- 나눔(Claude): 메인 쪽(시계 모듈, 게임 시간 적용, 줍기, 배너, IPC 이벤트)은 줍기 에이전트가 맡는다. 렌더러 쪽(관리 창·기기 창 갱신)은 상점 에이전트가 맡는다.
- 계약: 메인이 1초마다 관리 창과 기기 창에 IPC 이벤트 `manage:clock`(인자 `{ now }`)을 보낸다. 렌더러는 이 이벤트마다 스냅샷을 다시 읽는다.
- 열린 판단: 디스크 쓰기를 1초마다 할지, 메모리만 1초마다 갱신하고 디스크는 15초와 이벤트 때 쓸지. 측정값을 받아 정한다.
- 예외(Claude 판단): 무대 애니메이션 40ms 틱과 훅 상태 폴링 500ms는 화면·입력용이라 전역 시계에 묶지 않는다.

## 작업

### 렌더러 쪽 (상점 에이전트)

- `src/renderer/manage.ts`: 5초 `setInterval` refresh를 지웠다. `clockTick()`이 스냅샷을 다시 읽고, JSON이 마지막으로 그린 것과 같으면 다시 그리지 않는다.
- 쉬는 조건: 끌기(`dragFrom`), 박스 이름 입력(`boxRenaming`), 눌렀다 떼기 사이, 입력 칸 포커스. 이때는 그리지 않고 다음 틱으로 넘긴다.
- 연결: `window.pokebuddyManage.onClock`이 있으면 구독한다. 없으면 `[임시]` 창 자체 1초 `setInterval`을 쓴다.
- `src/shared/manage.d.ts`: `ManageBridge.onClock?` 선택 필드.
- `src/renderer/pet.ts`: 관리 창이 값이 바뀌면 다시 보낸다(`syncPetDevice`). 누르는 중에 온 보기는 뗀 뒤 그린다.
- 도감 기기 창은 시간 표시가 없어 바꾸지 않았다.
- `docs/specs/ui-components.md` C-07: 1초 주기와 쉬는 조건.
- 검수: 렌더러 tsc 오류 0, selftest-manage·screens·snapshot 통과, `git diff --check` 통과. 임시 Electron 스모크에서 알 남은 시간이 1초마다 줄고, 스크롤 위치와 검색 칸 포커스가 유지됐다.
- 남은 점: 쿨타임 도는 개체가 있으면 매초 다시 그려 `title` 툴팁이 사라질 수 있다.

### 메인 쪽 (줍기 에이전트)

- `src/main/clock.ts`(새 파일): 1초마다 `{ now, gap, seq }`를 낸다. `src/tools/selftest-clock.ts`를 더했다.
- 1초 틱(`src/main/app.ts` clockTick): 작업 시간 적립, 줍기, 게임 시간 적용, 배고픔 말풍선, 알림 배너, 바탕화면 튜토리얼, 관리 창에 `manage:clock` 보내기.
- 15초 주기로 남긴 일: 저장 다시 읽기, hookUpkeep, 놀이공간·점프 목록·트레이(OS 호출 포함).
- 무대 40ms와 상태 폴링 500ms는 시계에서 뺐다.
- 측정(58KB 저장 사본): 게임 틱 0.93ms, 파일 쓰기 0.42ms, 스냅샷 약 5ms.
- 디스크 쓰기 판단: 1초마다 쓰면 8시간에 약 1.7GB를 쓰고 저장 감시와 cloud.json 쓰기도 1초마다 돈다. 그래서 게임 값은 1초마다 메모리에 적용하고, 파일은 15초마다·명령·줍기 저장·앱 끄기·화면 잠금 직전(`game.flush`)에 쓴다.
- 메모리 값: 명령과 스냅샷은 사본을 읽는다. 다른 곳이 파일을 바꾸면 메모리 값을 버리고 파일을 따른다. writer가 아니면 메모리 값을 들지 않는다. 자체 확인 기본값은 틱마다 쓰기다.
- preload가 `onClock`을 내준다. 렌더러의 `[임시]` 자체 타이머를 지웠다.
- 문서: `docs/specs/game.md`, `docs/specs/modules.md`(전역 시계 절, 저장 시점), `docs/specs/balance.md`.
- 검수: build, check 통과. selftest 31개와 `scripts/selftest-cli.cjs` 통과. `git diff --check` 통과. smoke-renderer의 튜토리얼 검사 "어두운 막 위는 아래 창으로 통과한다"가 실패한다. 서브 에이전트는 이전부터 있던 실패로 본다. 확인하지 않았다.

## 피드백과 수정

### 한글 입력이 씹힌다 (2026-09-29)

- 사용자 실기 피드백: "인풋 입력이 이상하던데? 계속 씹히더라. 어래곤 검색했는데, 나오지도 않고, 어곤 이렇게 래 씹힌다던지 ㅇㅐ곤 이ㅏ렇게 된다던지 하더라."
- 원인 추정(Claude, 확인 전): `src/renderer/manage.ts` `searchBox`는 입력마다 `draw()`로 검색 칸을 새로 만들고 포커스만 옮긴다. macOS 한글 IME는 앞 글자 조합이 끝날 때 다음 글자 조합을 옛 칸에서 시작한다. 그 순간 칸을 바꾸면 진행 중 조합이 사라진다.
- 1초 다시 그리기 때문인지, 전부터 있던 문제인지 확인 전이다.
- 수정 방향: 다시 그릴 때 같은 input 요소를 유지하고 결과 영역만 갱신한다. 다른 텍스트 입력도 점검한다. "어래곤"이 안 나온 것이 검색 문제인지, 미해금이라 목록에 없는 것인지 구분한다.
- 사용자 결정(2026-09-29): "검색해야 그때 한번에 검색되게 하고싶은데. 지금은 입력할때마다 바뀌잖아. 그렇게 하지말고, 검색해야 그때 검색되게." 입력 중에는 결과를 바꾸지 않는다. Enter 또는 검색 단추를 눌렀을 때만 거른다. 조합 중 Enter는 조합 확정으로만 쓴다(Claude 판단).
- 수정 결과
  - 원인 확인: 옛 검색 칸은 입력(조합 끝)마다 `draw()`로 칸을 새로 만들었다. 그 순간 다음 글자 조합이 끊겼다.
  - `src/renderer/manage.ts` `searchBox`: 입력 칸 옆에 `검색` 단추를 둔다(박스·도감·상점 포켓몬 탭·박스에서 고르기). 입력 중에는 초안(`searchDraft`)에만 담는다. Enter 또는 `검색` 단추로 거른다. 지우기(×)로 비우면 바로 전체로 돌린다(Claude 판단, 흔한 관례).
  - 입력 요소 유지: 창이 앞에 있고 검색 칸이나 박스 이름 칸에 입력하는 동안에는 `draw()`·`drawDialog()`를 미루고, 칸을 떠나면 그린다. `editing()`에 `document.hasFocus()`를 더했다.
  - 계정·교환 링크 입력은 `liveInput`으로 나눴다. 계정 화면 이벤트로 다시 그릴 때 한글 조합이 끊길 수 있다(드문 경우, 남김).
  - `src/renderer/manage.html`: `.search-field`, `.search-go`(32px).
  - `src/tools/smoke-manage.ts`(새 파일): input 요소 동일성, 조합 중 Enter, Enter·단추 검색, 지우기 검사.
  - `docs/specs/ui-components.md` C-07.
  - "어래곤이 안 나옴": 이름 비교는 한글에서 맞다. 어래곤(#882)은 화석이라 태고의돌에서 나오기 전에는 미해금이다. 도감은 미해금 종을 이름으로 찾지 않는다(의도된 규칙 `matchesDex`, 번호 882로만 찾음). 상점에는 해금 뒤에만 나온다.
  - 검수: 렌더러·메인 tsc 오류 0. selftest-manage·screens·snapshot, smoke-manage 통과. `git diff --check` 통과.
- 후속(Claude 판단): 조합 중 마지막 글자가 있으면 Enter를 두 번 눌러야 검색된다. Enter 한 번으로 확정과 검색이 되도록 화면 쪽 수정에 넣었다.
