# 놀이공간 — 여러 화면

- 날짜: 2026-09-28 (Mac)
- 상태: 구현·검수 완료(미커밋). 0.9.0 에 넣는다(사용자 "버전릴리즈하기전에", "지금 작업한것들다 0.9.0 릴리스로").

## 설계

**요청(2026-09-28).** "포켓몬 영역이 전체화면/영역그리기 로 되어있잖아. 전체화면일때, 어떤화면에 뜨게할지 고를수있게 추가. 듀얼모니터에서 모든화면 다 뛰어놀게할건지, 특정화면에만 할건지, 특정영역에만 할 건지 해야할거같아."

**지금 동작(코드 확인).**

- `화면 전체` 는 주 화면의 작업 영역이다(`src/main/layout.ts` `playAreaRect`).
- 무대 창은 하나다. 무대 사각형은 놀이공간과 한 디스플레이의 교집합이다(`src/main/app.ts` `onAnchorUpdate`).
- 영역 그리기는 커서가 있는 디스플레이에 뜬다(`src/main/region-window.ts`).
- 명세 `docs/specs/game.md` 놀이공간 줄의 미정 항목이 "여러 화면 선택"이다.

**사용자 결정(2026-09-28, 선택지 응답).**

| 질문 | 답 |
|---|---|
| 모든 화면일 때 움직임 | 화면마다 살고 드래그로 이사한다. 화면 경계를 넘어 걸어가지 않는다 |
| 특정 화면 고르는 방법 | "1+2" — 설정 목록에서 고르기와 화면 위에서 클릭해 고르기를 둘 다 둔다 |
| 기본값 | 주 화면. 새 설치와 기존 `화면 전체` 사용자 모두 |

**설계(제안, 위 결정에서 이끈 것).**

- 놀이공간 모드는 세 개다: `모든 화면`(all) · `한 화면`(display) · `영역 지정`(region). 설정 `화면` 탭의 전환을 세 칸으로 한다.
- 저장: `settings.playArea` 에 `display`(고른 화면의 식별 정보, 없으면 주 화면)를 더한다. 옛 `full` 은 `display` + 주 화면으로 읽는다. 알 수 없는 모드는 주 화면이다.
- 화면 식별: Electron `Display.id` 와 그 화면의 사각형을 함께 저장한다. id 가 없으면 사각형이 가장 가까운 화면, 그것도 없으면 주 화면이다. 저장된 값은 지우지 않는다(모니터를 다시 꽂으면 돌아온다).
- 한 화면: 설정의 목록 항목은 `화면 N · 주 화면 · 가로×세로` 모양이다. 목록이 열린 동안 모든 모니터에 큰 번호를 띄운다. `화면에서 고르기` 는 모든 모니터에 번호 덮개를 띄우고, 누른 화면을 고른다. Esc 는 취소다(영역 그리기와 같은 규칙).
- 모든 화면: 디스플레이마다 무대 창을 하나씩 둔다. 개체마다 사는 화면을 저장한다. 사는 화면이 없는 개체는 개체 수가 가장 적은 화면에 둔다. 드래그로 다른 화면에 놓으면 그 화면으로 옮기고 놓은 자리가 새 집이다. 화면이 빠지면 그 화면의 개체는 주 화면으로 임시로 옮긴다(저장된 화면은 유지).
- 무대 창이 여럿이 되어도 튜토리얼 말풍선·배고픔 말풍선·우클릭 메뉴는 그 개체의 창을 기준으로 한다.

**위험.**

- 무대 창이 여럿이면 앵커·가림 판정·클릭 통과·창 추적 헬퍼 결과를 창마다 나눠야 한다.
- 드래그 중 커서가 다른 화면으로 넘어가면 원래 창 밖이라 그림이 잘린다. 놓는 순간 옮기는 것으로 충분한지 실기로 본다.
- 클라우드 저장을 옛 버전이 읽으면 새 모드를 모른다. 옛 버전은 주 화면으로 대신한다(`src/save/v3.ts` 정규화 확인 필요).
- Figma 반영은 Mac 계정 권한 문제로 집 PC 에서 한다(`records/user-modal/record.md` "Figma 반영 — 남은 일"에 더한다).

**수용 조건.**

1. 설정 `화면` 탭에 `모든 화면 | 한 화면 | 영역 지정` 이 있다.
2. 한 화면: 목록과 화면 클릭 두 방법으로 고를 수 있고, 고른 화면에만 포켓몬이 논다.
3. 모든 화면: 두 모니터에 포켓몬이 나뉘어 놀고, 드래그로 다른 화면에 옮기면 그 화면에 남는다. 다시 켜도 유지된다.
4. 옛 저장(`full`)은 주 화면으로 동작한다.
5. 모니터를 빼면 포켓몬이 사라지지 않고 주 화면에 온다.
6. 자체 시험과 실기(이 Mac 의 모니터 구성) 확인.

## 작업

서브 에이전트가 구현했다. 설계와 다른 점: 모드 이름 `display` 대신 `screen`(기존 `settings.display` 와 겹침 회피).

- 저장: `settings.playArea = { mode: all|screen|region, rect, screen }`, 개체 선택 필드 `screen`(사는 화면). 새 저장·옛 `full`·모르는 값 → `screen`(주 화면). 설정 명령 `playScreen` 추가, `playArea` 는 `full` 을 거절한다. 옛 앱이 새 저장을 읽으면 `region` 이 아닌 값은 `full`(주 화면)이고, 옛 앱이 다시 쓰면 `screen` 필드는 사라진다.
- 새 파일: `src/main/stage-group.ts`(화면마다 무대 창+무대, app 에는 하나처럼), `src/main/screen-picker.ts`(번호 덮개·고르기), `src/renderer/screens.html`·`screens.ts`, `src/tools/selftest-screens.ts`.
- 바꾼 파일: `app.ts`(무대 묶음, display-added/removed/metrics-changed 재배치), `layout.ts`(`screenOrder`·`resolveScreen`·`playLanes`·`assignScreens`), `stage.ts`, 저장·명령 경로(`save-party.ts`·`commands.ts`·`tx/*`·`party/home.ts`·`save/v3.ts`·`shared/save-v3.ts`·`state/settings.ts`), 설정 화면(`manage.ts`·`manage.html`·`manage.d.ts`·`manage-window.ts`·`preload.ts`·`bridge.d.ts`), i18n `coach.area.*`, `dev-manage.cjs`, 시험 데이터.
- 문서(부모): `docs/specs/game.md`(놀이공간 줄·설정 절), `docs/terms.md`, `docs/design.md`, `docs/guide.md`.

## 검수

- 이 Mac: 주 화면 id 3(2560×1440), 보조 id 1(1728×1117, 왼쪽).
- 세 작업(Mac 업데이트·훅 정리·여러 화면)을 합친 상태에서 `npm run selftest` 종료 코드 0(부모).
- 설정 `화면` 탭 캡처(부모, `dev-manage`): 세 칸 전환, `한 화면` 의 목록과 `화면에서 고르기` 같은 높이, `모든 화면` 설명.
- 실기(서브 에이전트, 임시 홈): 모든 화면에서 무대 창 두 개·네 마리 배분(주 p1·p3, 보조 p2·p4), `playScreen` 보조 화면 전환 시 창 하나·네 마리 이동, 다시 `all` 에서 배분 복원. 목록을 여는 동안 두 모니터에 번호 덮개.

## 피드백

- 실기로 못 본 것: 모니터 사이 드래그 이사(합성 입력 권한 없음), 화면 빼기·다시 꽂기, `화면에서 고르기` 클릭 선택, 포켓몬 모습 캡처(화면 기록 권한 없음). 사용자 실기 필요.
- 위험: 끄는 동안 그림이 원래 창 가장자리에서 잘린다. Mac 덮개는 메뉴 막대 아래로 밀려 번호가 약간 아래에 보인다. Esc 는 포커스를 받은 덮개 한 장에서만 먹는다. 한 번도 끌어다 놓지 않은 마리는 파티가 바뀌면 화면이 바뀔 수 있다. Windows 실기 전.
- Figma 반영은 `records/user-modal/record.md` 할 일 7번.
