기본먹이의 제공 방식과 효율은 [사용자 결정](../work/s5-design-system-v2/plan.md#기본먹이-무제한-제공과-낮은-회복-효율)을 따른다.
쿨타임을 지키며 기본먹이를 여러 번 주면 배고픔에서 서서히 회복할 수 있다. 자연적인 만복도 감소를 포함해도 배고픔 구간에서 벗어날 수 있도록 수치를 정한다. 근거는 [기본먹이만으로 점진적 회복](../work/s5-design-system-v2/plan.md#기본먹이만으로-점진적-회복)을 따른다.
2026-09-23 확정: 수치는 [밸런스 수치](balance.md)을 따른다. 기본먹이는 20을 회복하고 쿨타임은 10분이며 만복도는 시간당 30 줄어든다. 배고픔 구간(40 아래)에서 쿨타임마다 기본먹이를 주면 한 번에 순증 15다. 기본먹이만으로 최대 만복도까지 올릴 수 있다.
`규토리`는 프리미엄먹이의 이름 후보다. `1.1배`는 효과 예시다. 둘 다 확정 값으로 사용하지 않는다.
프리미엄먹이 버프는 친밀도 증가량에 적용한다. 이미 쌓인 친밀도에 배율을 곱하지 않는다.
먹이 사용은 만복도를 기준으로 한다. 만복도가 최대이면 기본먹이와 프리미엄먹이를 모두 사용할 수 없다. 이때 먹이를 소비하거나 버프만 갱신하지 않는다.
기본먹이는 만복도를 일정량 회복한다. 밥 주기 자체에 쿨타임을 적용한다. 쿨타임 중에는 먹이를 사용할 수 없다. 사용을 거부하면 먹이와 만복도·버프를 바꾸지 않는다. 근거는 [기본먹이 회복과 쿨타임](../work/s5-design-system-v2/plan.md#기본먹이-일정량-회복과-밥-주기-쿨타임)을 따른다.
쿨타임은 개체별로 적용한다. 같은 개체의 기본먹이와 프리미엄먹이가 쿨타임을 공유한다. 다른 개체의 밥 주기는 막지 않는다. 근거는 [개체별 먹이 공통 쿨타임](../work/s5-design-system-v2/plan.md#개체별-먹이-공통-쿨타임)을 따른다.
먹이 쿨타임은 [실행 상태별 시간](#실행-상태별-시간)을 따른다. 박스 보관 중에는 남은 시간을 보존한다. 파티로 복귀하면 보존한 시간부터 이어간다.
2026-09-24 확정: 쿨타임은 10분이며 기본먹이와 프리미엄먹이가 함께 쓴다. 쿨타임은 사용이 성공한 순간부터 센다. 수치는 [밸런스 수치](balance.md)을 따른다. 사용 실패 시에는 거래 원칙에 따라 기존 상태를 유지한다.
프리미엄먹이를 사용하면 대상 개체의 만복도를 최대까지 채운다. 같은 프리미엄먹이의 버프가 남아 있으면 해당 먹이의 기본 지속시간으로 갱신한다. 이전 잔여 시간을 더하지 않는다. 효과 배율을 누적하지 않는다.
만복도는 높을수록 배부른 수치다. 이전 배고픔 표현과 같은 돌봄 상태를 다루며 별도 자원을 추가하는 것은 아니다. 기존 시간 진행·정지 원칙을 그대로 적용한다. 실제 상한·감소 속도와 기존 런타임 저장 변환은 미정이다.
근거는 [만복도와 프리미엄먹이 버프 갱신](../work/s5-design-system-v2/plan.md#만복도와-프리미엄먹이-버프-갱신)을 따른다.
PC 잠금·절전·앱 종료 중에는 배고픔과 친밀도가 변하지 않는다. 포인트 적립과 버프 시간 및 알 준비 시간도 멈춘다. 남은 시간과 적립 중인 진행량을 유지한다. 복귀할 때 중단 기간을 소급 진행하지 않는다.
기존 S4 먹이 재고와 효과의 이식은 별도로 설계한다. 기존 재고를 삭제하지 않는다.
2026-09-22 결정: 오래 놀아주기 버프와 장난감을 채택한다. 근거는 [오래 놀아주기와 장난감](../work/s5-design-system-v2/plan.md#오래-놀아주기-버프와-장난감-채택)을 따른다.
2026-09-24 결정: 놀아주면 놀아주기 상태가 20분 붙는다. 이 상태 자체에는 효과가 없다. 놀아주기 쿨타임은 10분이다. 쿨타임이 지난 뒤 상태가 남은 10분 안에 다시 놀아주면 중첩이 오른다. 3중첩이 되면 오래 놀아주기 버프가 켜진다. 상태가 끝나면 중첩은 0으로 돌아간다. 쿨타임 안의 클릭은 반응만 보이고 중첩을 올리지 않는다. 수치는 [밸런스 수치](balance.md#버프와-친밀도)를 따른다. 근거는 [돌봄 명령](../work/s5-design-system-v2/plan.md#돌봄-명령)을 따른다. 이 결정은 2026-09-22 의 "10초 안에 이어 약 30초" 규칙을 대신한다.
장난감으로 놀아줄 때의 반응 애니메이션은 일반 놀아주기 반응과 같다. 파티클 같은 효과만 추가로 표시한다.
오래 놀아주기 버프는 프리미엄먹이 버프와 같은 방식으로 놀아준 한 마리의 친밀도 증가량을 일정 시간 높인다. 효과는 프리미엄먹이 버프보다 낮다. 버프가 남아 있을 때 다시 달성하면 기본 지속시간으로 갱신한다. 남은 시간을 더하지 않는다.
장난감은 1회성이다. 장난감으로 한 번 놀아주면 1개를 소비한다. 장난감이 없어도 일반 놀아주기는 쓸 수 있다. 장난감은 가방에 보관한다. 가방에서 장난감을 드래그해 포켓몬 위에 드롭하면 사용한다. 장난감을 사용하면 오래 놀아주기 버프와 같은 버프를 준다. 버프가 남아 있으면 기본 지속시간으로 갱신한다. 드롭을 취소하거나 포켓몬이 아닌 곳에 놓으면 장난감을 소비하지 않는다. 근거는 [장난감의 드래그 사용](../work/s5-design-system-v2/plan.md#장난감의-드래그-사용과-같은-버프)을 따른다. 근거는 [버프 효과와 1회성 장난감](../work/s5-design-system-v2/plan.md#오래-놀아주기-버프-효과와-1회성-장난감)을 따른다.
2026-09-23 확정: 오래 놀아주기와 장난감 버프는 친밀도 증가량 ×1.5이며 30분이다. 프리미엄먹이 버프는 ×2이며 2시간이다. 장난감은 상점에서 40P에 판다. 수치는 [밸런스 수치](balance.md)을 따른다.

### 배고픔 상태 표시

화면에 보이는 포켓몬은 배고픔 알림 구간에서 작은 말풍선이나 행동으로 표현한다. 숨겨진 포켓몬의 배고픔은 파티창의 상태 표시로만 확인한다. 배고픔 때문에 숨김을 해제하거나 창을 자동으로 열지 않는다. 숨김 상태에서도 만복도는 기존 시간 규칙대로 감소한다.
근거는 [숨김 개체의 배고픔 상태 표시](../work/s5-design-system-v2/plan.md#숨김-개체의-배고픔-상태-표시)를 따른다.
보이는 포켓몬이 배고픔 알림 구간에 진입하면 말풍선을 한 번 표시한다. 같은 구간에 머무르면 말풍선을 반복하지 않는다. 이후에는 가끔 배고픈 행동을 한다. 더 심한 구간에 진입하면 말풍선을 다시 한 번 표시한다. 근거는 [배고픔 표현 반복 정책](../work/s5-design-system-v2/plan.md#배고픔-말풍선과-행동의-반복-정책)을 따른다.
`[스펙 미확정]` 행동 간격, 말풍선 표시 시간, 여러 개체의 동시 표현은 후속 설계에서 정한다. 회복 후 재진입과 숨김 해제·재실행 때의 알림 이력 처리도 미정이다. 부화·진화·업적 알림에는 이 결정을 자동 적용하지 않는다.

### 알림 배너의 개별 표시

부화 준비 완료는 알별로 별도 배너를 만든다. 진화 가능은 개체별로 별도 배너를 만든다. 업적 달성은 업적별로 별도 배너를 만든다. 같은 종류도 개수 요약으로 묶지 않는다. 배너는 한 번에 하나씩 순차 표시한다. 다른 배너가 표시 중이면 새 알림은 대기한다.
세 배너는 모두 제목, 대상 표시와 이름, `바로가기` 버튼으로 구성한다. 부화 배너의 `바로가기`는 돌보미집을 연다. 진화 배너의 `바로가기`는 해당 개체의 상세 화면을 연다. 부화 배너는 결과 포켓몬을, 진화 배너는 결과 종을 보여주지 않는다. 배너 본문 클릭 동작은 두지 않는다. 근거는 [빈 화면 제안 검토](../work/s5-design-system-v2/plan.md#빈-화면-제안-검토)를 따른다. 업적 배너의 `바로가기`를 누르면 해당 업적의 보상 수령 화면을 연다. 업적 배너는 `업적 달성` 제목, 업적 표시와 이름, `바로가기` 버튼으로 구성한다. 근거는 [업적 배너의 바로가기](../work/s5-design-system-v2/plan.md#업적-배너의-바로가기와-업적-안내-제거)를 따른다. 업적 배너는 화면 우측 아래에 한 번 표시한다. 미수령 보상이 있으면 헤더의 업적창 아이콘에 dot를 표시한다. 근거는 [우측 아래 표시와 dot](../work/s5-design-system-v2/plan.md#업적-알림의-우측-아래-표시와-업적창-dot)를 따른다. 각 행동은 이동 후 사용자가 직접 실행한다.
근거는 [개별 표시 정정](../work/s5-design-system-v2/plan.md#알림-배너-개별-표시-정정)을 따른다. 배고픔 말풍선은 이 배너 정책의 대상이 아니다.
배너 알림 소리는 기본으로 켠다. 설정에서 무음으로 바꿀 수 있다. 사용하는 OS의 기본 시스템 알림음을 사용한다. 무음 설정에서도 배너 표시와 클릭 이동은 유지한다. 근거는 [알림 소리 정정](../work/s5-design-system-v2/plan.md#기본-알림-소리와-os-시스템-알림음)을 따른다.
같은 부화·진화·업적 상태를 한 번 배너로 표시했으면 미처리 상태여도 반복하지 않는다. 클릭하지 않았어도 다시 표시하지 않는다. 앱 재실행 후에도 이 원칙을 유지한다. 해당 메뉴에서는 부화 가능·진화 가능·업적 미수령 상태를 계속 확인할 수 있다. 다른 대상의 새 알림까지 차단하지 않는다. 근거는 [상태 알림 반복 금지](../work/s5-design-system-v2/plan.md#표시한-상태-알림의-반복-금지)를 따른다.
배너가 기다리는 동안 대상이 더 이상 부화 가능·진화 가능·업적 미수령 상태가 아니면 그 배너를 표시하지 않는다. 대기열에서 제거한다. 아직 표시하지 않은 배너가 있는 상태에서 앱이 종료되면 재실행 후 이어서 표시한다. 대상이 여전히 해당 미처리 상태일 때만 표시한다. 배너를 표시하는 중에 앱이 종료되면 표시한 것으로 처리한다. 배너 폐기는 대상의 게임 상태를 바꾸지 않는다. 근거는 [대기 배너 처리](../work/s5-design-system-v2/plan.md#대기-배너의-무효화와-재실행-처리)를 따른다.
여러 배너가 기다리면 먼저 생긴 배너부터 표시한다. 같은 순간에 생긴 배너의 종류가 다르면 부화 → 진화 → 업적 순서로 표시한다. 같은 종류이면 화면의 목록 순서를 따른다. 부화 배너는 돌보미집 칸 순서를 따른다. 진화 배너는 파티 칸 순서를 먼저 따르고 그다음 박스 순서를 따른다. 업적 배너는 업적창 목록 순서를 따른다. 근거는 [배너 표시 순서](../work/s5-design-system-v2/plan.md#배너-동시-발생의-표시-순서)를 따른다.
2026-09-25 구현에서 정한 값: 배너는 8초 보인다. 커서가 배너 위에 있으면 멈춘다. 주 화면 작업 영역 오른쪽 아래에 띄운다. 배너 상태는 게임 저장이 아니라 같은 폴더의 `notify.json` 에 둔다. 쓰기에 실패해도 배너는 보이고 다음 틱에 다시 쓴다. 기능을 처음 켤 때 이미 미처리인 상태는 표시한 것으로 둔다. 소리는 배너를 띄울 때 한 번 낸다(Electron `shell.beep`). 근거와 사용자 승인은 [알림 배너의 설계](../work/game-runtime/record.md#알림-배너의-설계)를 따른다.
`[스펙 미확정]` 박스 안 정렬 기준은 별도로 정한다. OS 무음·집중 모드 연동, 소리 재생 실패 처리, 다중 화면 선택은 정하지 않았다.

## 3. 도감 등록과 파티 소환

### 개체 레벨과 입수처

2026-09-21 후속 결정: 첫 선택 후보는 모두 초기 도감에 해금한다. 실제로 지급하는 첫 개체는 사용자가 선택한 한 마리다. 초기 랜덤알 후보는 첫 선택 후보 중 알 입수가 허용된 종이다. 종별 전용 입수처를 유지한다.
시작 포인트는 랜덤알 하나를 구매할 수 있는 금액이다. 시작 포인트의 사용처는 제한하지 않는다. 실제 종 목록·확률·가격은 미정이다. 근거는 [초기 해금과 첫 알 구매](../work/s5-design-system-v2/plan.md#초기-해금과-첫-알-구매)를 따른다.
데이터를 정할 때 초기 알 후보가 하나 이상인지 확인한다. 이후 새로 해금한 종에는 기존 해금·입수처 계약을 적용한다. 초기 후보 규칙을 영구적인 알 결과 제한으로 사용하지 않는다.

| 구분 | 해금 후 가능한 행동 | 실제 획득 |
|---|---|---|
| 상점 구매 종 | 상점 구매 항목에 추가된다. | 사용자가 구매한다. |
| 진화 전용 종 | 조건을 충족한 개체에서 진화를 선택한다. | 사용자가 해당 개체를 진화시킨다. 상점에서 구매하지 않는다. |
| 랜덤알 | 해금한 종 중 알 입수처가 허용된 종을 대상으로 한다. | 직접 부화해서 획득한다. 진화 전용 종은 제외한다. |

2026-09-21 후속 결정: 입수처는 종마다 지정한다. 구매·알 양쪽에서 입수 가능한 종 외에 알 전용 종과 특수 기믹 전용 종도 둔다. 모든 종을 일반 구매나 알에 포함하지 않는다.
알 전용 종은 상점에서 종을 지정해 구매하지 않는다. 특수 기믹 전용 종은 알에서도 나오지 않는다. 진화 전용 계약은 유지한다.
랜덤알은 더 저렴한 무작위 획득 경로다. 종 지정 구매는 더 비싼 확정 획득 경로다. 가격과 종별 예외는 아직 정하지 않았다.
근거는 [종별 입수처 지정](../work/s5-design-system-v2/plan.md#종별-입수처-지정)을 따른다.
`[스펙 미확정]` 종별 계약은 해금 조건, 허용 입수처, 입수처별 실행 조건, 안내 문구를 분리하는 안을 제안한다. 선행 해금 검사를 모든 입수처에 공통 적용하지 않는다.
특수 기믹 획득은 선행 도감 해금을 요구하지 않는다. 해당 기믹을 수행하면 도감 해금과 개체 획득이 함께 일어난다. 근거는 [특수 기믹의 선행 해금 제외](../work/s5-design-system-v2/plan.md#특수-기믹의-선행-해금-제외)를 따른다.
후속 정정: 해금 후의 입수처와 획득 제한도 종별로 지정한다. 기믹으로 처음 얻었어도 이후 상점이나 알에서 얻을 수 있는 종을 둔다. 계속 기믹으로만 얻는 종과 단일 포켓몬도 따로 지정한다. ‘특수 기믹 전용’은 이후에도 다른 입수처를 허용하지 않는 종에만 사용한다. 근거는 [종별 후속 입수처와 조건부 알 후보](../work/s5-design-system-v2/plan.md#종별-후속-입수처와-조건부-알-후보)를 따른다.
알 전용 종도 도감 해금 수 같은 조건을 만족해야 무작위 획득 후보에 들어가도록 지정할 수 있다. 사용자 예시인 도감 100종 이상 해금은 확정 수치가 아니다. 조건 달성만으로 개체를 지급하지 않는다. 개체 레벨만을 모든 종의 해금·입수 조건으로 사용하지 않는다.

### 친밀도와 경험치의 역할

2026-09-21 사용자 결정: 친밀도와 경험치를 분리한다. 친밀도를 통해 포인트를 얻는다. 포인트로 상점에서 경험사탕을 구매한다. 경험사탕으로 경험치를 얻어 레벨을 올린다.
던전 탐험을 추가할 때 경험사탕과 경험치를 얻는 경로를 제공한다. 탐험은 향후 확장이다. 현재 기능 범위에 자동 포함하지 않는다.
출처는 [친밀도와 경험치 분리](../work/s5-design-system-v2/plan.md#친밀도와-경험치-분리)를 따른다.

| 값 또는 상품 | 역할 | 미정 계약 |
|---|---|---|
| 친밀도 | 개체와 함께한 시간과 돌봄으로 쌓는다. 현재 값이 높을수록 포인트 적립 간격이 짧아진다. 포인트 적립으로 소모하지 않는다. | 적립 간격 계산식 |
| 포인트 | 파티 개체가 각자의 친밀도에 따라 적립한 결과를 합산한다. 경험사탕 등 상점 상품을 구매한다. | 부분 진행 저장 구현, 기존 에이전트 보상과의 관계 |
| 경험사탕 | XS·S·M·L·XL 5종이다. 포인트로 구매해 파티와 박스의 보유 개체를 성장시킨다. 한 대상과 사용 수량을 선택하고 결과를 미리 확인한다. | 가격, 경험치 지급량, 화면 구성 |
| 이상한사탕 | 사용한 개체의 레벨을 1 올린다. 새 레벨의 경험치 진행은 0부터 시작한다. 100레벨에서는 사용할 수 없고 소비하지 않는다. | 가격, 개별 보상표, 수량 조작 화면 |
| 경험치 | 친밀도와 별도로 개체의 레벨을 최대 100까지 올린다. 진화 후에도 레벨과 누적 경험치를 유지한다. | 레벨별 필요량, 종별 곡선 호환, 향후 획득 경로의 초과 처리 |

기존 배고픔 디버프와 프리미엄먹이 버프의 확정 대상은 친밀도 증가량이다. 경험사탕의 경험치에도 적용하는 것으로 확대하지 않는다.
경험사탕XS·S·M·L·XL과 이상한사탕의 공통 입수 경로는 상점 구매, 업적 보상, 탐험 보상이다. 탐험은 향후 확장으로 유지한다. 실제 가격과 업적·탐험별 보상 종류 및 수량은 미정이다. 모든 업적과 탐험이 사탕 전종을 지급하는 뜻이 아니다. 근거는 [공통 입수 경로 결정](../work/s5-design-system-v2/plan.md#사탕-공통-입수-경로)을 따른다.
사탕 6종은 처음부터 상점에서 판매한다. 별도 해금 조건을 두지 않는다. 가격으로 구매 시점을 조절한다. 근거는 [초기 상점 판매 결정](../work/s5-design-system-v2/plan.md#사탕-전종의-초기-상점-판매)을 따른다.
사탕 구성의 근거는 [사용자 결정과 이미지 조사](../work/s5-design-system-v2/plan.md#경험사탕-5종과-이상한사탕-및-이미지-조사)를 따른다. 공개 자료의 효과량과 가격은 게임의 확정 수치가 아니다.

### 개체 획득과 파티 교체

2026-09-21 사용자 결정: 같은 종을 여러 개체 보유할 수 있다. 같은 종을 동시에 파티에 배치할 수 있다.

일곱 조건은 서로 겹치지 않는다. 어디에도 맞지 않는 조합은 일반 추첨으로 간다. 예를 들어 쓰다듬기 10회와 노래 4회는 어떤 조건도 아니다. 대상은 수집 난이도 3·4등급 58종이다. 조건마다 8종이고 가장 어려운 각각 8회 이상에만 세대별 종족값 600 계열 10종을 모은다. 단일 포켓몬은 넣지 않는다. 전설·환상·울트라비스트는 알에서 얻을 수 없다는 위 규칙을 따른다. 한 진화 계열에서는 한 종만 배정한다. 이브이처럼 진화 전이 하나로 모이는 계열에 여러 조건을 걸지 않는다. 첫 선택 후보 29종의 계열도 넣지 않는다. 스타터는 첫 선택과 상점으로 평범하게 얻는다. 화석 포켓몬도 넣지 않는다. 화석은 태고의돌로만 얻는다.

2026-09-24 결정: 알은 두 종류다. 랜덤알과 태고의돌이다. 태고의돌은 화석 전용 알이며 상점의 알 분류에 둔다. 겉모습은 돌이지만 돌보미집에 넣고 준비 시간과 돌봄은 랜덤알과 같다. 태고의돌에서는 화석 포켓몬 15종만 나온다. 진화 전 10종(암나이트·투구·릴링·아노딥스·두개도스·방패톱스·프로토가·아켄·티고라스·아마루스)과 진화하지 않는 5종(프테라·파치래곤·파치르돈·어래곤·어치르돈)이다. 암스타·투구푸스 같은 화석 진화형 10종은 키워서 진화로 얻는다. 화석 25종은 랜덤알 후보와 행동 조건 대상에서 모두 뺀다. 태고의돌에도 이로치 확률을 랜덤알과 같게 적용한다. 목록은 `data/eggs.json`을 따른다. 근거는 [태고의돌 화석 전용 알](../work/s5-design-system-v2/plan.md#태고의돌-화석-전용-알)을 따른다. 표는 `data/egg-conditions.json`을 따른다. 발견한 조건은 도감 상세에 문구 그대로 적는다.
`[스펙 미확정]` 행동·열기 동시 요청 처리 순서와 결과 저장 구현은 정하지 않았다. 실제 힌트·반응·도감 표현을 별도로 정한다. 동일 종의 복수 조건은 종별 단일 지정으로 발생하지 않는다. 단일 종을 먼저 획득해 알 후보가 소진되는 경우는 단일 종의 알 제외로 발생하지 않는다.

2026-09-21 사용자 결정: 부화 준비에 최대 5분을 잡는다. 돌봄 같은 활동으로 시간을 단축한다. 시간이 다 지나면 사용자가 직접 열어야 부화한다.

부화 완료를 사용자가 놓치지 않도록 자동 부화를 하지 않는다. 출처는 [부화 준비와 직접 열기](../work/s5-design-system-v2/plan.md#부화-준비와-직접-열기)를 따른다.

| 상태 | 진행 | 다음 상태 |

| 부화 완료 | 새 개체를 얻는다. | 기존 파티·박스 배치 계약 적용 |

최대 5분은 부화 가능 상태까지의 대기 기준이다. 사용자가 직접 열기까지 기다리는 시간은 포함하지 않는다.
PC 잠금·절전·앱 종료 중에는 부화 준비를 진행하지 않는다. 남은 시간을 보존하고 복귀 후 이어간다. 관리 창만 닫으면 준비 시간은 계속 진행한다.
2026-09-23 확정: 인정된 돌봄 한 번이 남은 시간에서 30초를 뺀다. 돌봄 쿨타임은 1분이라 버튼을 계속 눌러도 반복 차감하지 않는다. 남은 시간은 0 아래로 내려가지 않는다. 수치는 [밸런스 수치](balance.md)을 따른다.
돌보미집에는 알을 최대 6개 배치한다. 각 알은 개별 타이머로 동시에 진행한다. 전체 알의 진행도를 하나로 합치지 않는다.
알 돌봄 행동은 쓰다듬기와 노래 들려주기다. 포켓몬에게 밥 주기·놀아주기를 하는 것과 구분한다. 상점의 부화시간 단축 도구는 채택하지 않는다. 기본 대기 시간을 늘리면 다시 검토한다. 근거는 [알 돌봄 행동](../work/s5-design-system-v2/plan.md#알-돌봄-행동의-채택)을 따른다. 2026-09-23 확정: 두 행동의 단축량은 30초로 같고 반복 인정 간격은 1분이다. 수치는 [밸런스 수치](balance.md)을 따른다. 2026-09-24 확정: 조건표는 두 행동의 인정 횟수를 각각 세어 구간으로 나눈다. 위 행동 조건 표를 따른다.
선택한 알을 돌보면 그 알의 남은 시간만 단축한다. 다른 알은 자기 타이머에 따라 진행한다.
알의 부화 준비가 완료되는 순간 작은 알림을 한 번 제공한다. 돌보미집 메뉴를 열지 않았어도 완료를 알 수 있어야 한다. 알림만으로 부화시키거나 결과 포켓몬을 공개하지 않는다. 근거는 [메뉴형 돌보미집과 알림](../work/s5-design-system-v2/plan.md#메뉴형-돌보미집과-부화-준비-완료-알림)을 따른다.
알림은 화면 한쪽의 작은 배너로 잠깐 표시한다. 배너의 `바로가기`를 누르면 돌보미집을 연다. 누르지 않으면 배너는 사라진다. 배너가 사라져도 준비된 알은 직접 부화할 때까지 유지한다. 근거는 [배너와 클릭 이동](../work/s5-design-system-v2/plan.md#부화-준비-완료-배너와-클릭-이동)을 따른다.
여러 알이 동시에 준비되면 알별 배너를 하나씩 순차 표시한다. 알림이 대기하는 동안에도 알은 부화 가능한 상태로 유지한다.
미정: 활동별 단축량, 최소 대기 여부. 배너의 정확한 위치·다중 화면 기준·표시 시간도 별도로 정한다. 동시 완료 순서는 [알림 배너의 개별 표시](#알림-배너의-개별-표시)를 따른다. 소리는 알림 배너 공통 계약을 따른다. 메뉴 진입 버튼의 준비된 알 개수 표시는 제안이다.
돌보미집의 알 칸과 포켓몬 파티 칸은 별개다. 파티 칸 구매·업적으로 돌보미집 칸이 늘어나는 것으로 해석하지 않는다.
돌보미집에 빈 칸이 있으면 구매한 알을 바로 배치하고 타이머를 시작한다. 6개가 차면 추가 알 구매를 막고 돌보미집을 안내한다.
부화 가능한 알도 직접 열기 전까지 칸을 차지한다. 직접 부화하면 칸이 비고 추가 구매가 가능해진다. 부화 결과 창은 태어난 개체와 들어간 자리(파티의 숨김 칸 또는 박스)를 보여주고 `확인`만 둔다. 닫으면 돌보미집에 머문다. 근거는 [빈 화면 제안 검토](../work/s5-design-system-v2/plan.md#빈-화면-제안-검토)를 따른다. 2026-09-26 구현: 랜덤알에서 단일 포켓몬 알이 나오면 같은 창이 "알에서 새 알이 나왔어요"와 그 알 이름을 보인다. [기록](../work/game-runtime/record.md#부화-결과-창) 초과 구매한 알을 별도로 보관하는 경로는 제공하지 않는다.
구매 제한 시 포인트를 차감하지 않는다. 만석이라는 이유로 준비 중인 알을 자동 부화시키지 않는다. 근거는 [돌보미집 만석 처리](../work/s5-design-system-v2/plan.md#돌보미집-만석-처리)를 따른다.
후속 결정은 [돌보미집과 알 6개](../work/s5-design-system-v2/plan.md#돌보미집과-알-6개)를 따른다. 돌보미집은 메뉴로 구성한다. 알 배치는 메뉴 내부의 알 칸을 뜻한다. 데스크톱 놀이공간에는 알을 배치하지 않는다. 돌보미집은 박스 메뉴 안에 둔다. 박스 메뉴 안의 세부 배치는 아직 정하지 않았다.

### 재검토할 기존 종 등록 기반 계약

아래 내용은 이전 계약을 보존한 것이다. 위의 개체별 육성·종별 입수처와 충돌하는 내용을 새 구현에 적용하지 않는다. 개체 획득과 보유 개체 배치를 나누는 후속 설계가 필요하다.

도감 전체 목록에는 등록·미등록 종을 모두 표시한다. 목록에 보인다는 이유로 소환할 수 있지는 않다.

2026-09-27 결정: 미해금 종은 칸과 상세에 검은 실루엣을 보인다. 이름·분류·타입·키·몸무게는 "???"다. 칸을 누르면 관리 창 옆에 도감 기기 창이 붙어 뜬다. 관리 창 격자 아래의 상세 패널은 없앴다. 기기 창 높이는 내용에 맞춘다. 사용자 발언: "설정창 옆에 도감같은 디자인이 뜨고, 그위에 상세설명뜨게.", "모든 미해금에 다 하자", "도감이 굳이 창이랑 높이 안맞아도 돼." 근거는 [플레이 버그 3건](../work/play-bugs/record.md)을 따른다.
'등록'은 해당 종을 획득하여 소환할 수 있는 상태다. 스타터 선택, 구매, 부화, 진화로 등록한다.
상점 구매 조건 충족과 도감 등록은 별개다. 조건 충족만으로 유료 상품을 무료 소환하지 않는다.
[스펙 미확정] 기존 해금 자료를 새 등록으로 옮기는 기준은 이식 설계에서 확정한다.

빈 칸을 누르면 해당 칸을 지정한 도감을 연다. 기본 필터는 '등록'이다.
지방과 검색으로 종을 고른다. 'N번 칸에 소환'을 누른다. 완료하면 파티로 돌아간다.
상세의 '교체'도 해당 칸을 지정한 도감을 연다. 기존 포켓몬은 확정 전까지 유지한다.
취소, Escape, 다른 탭 이동은 파티를 변경하지 않는다. 취소하면 선택한 목적지를 해제한다.
일반 도감에서도 파티 칸을 선택해 등록된 종을 소환할 수 있다.
미등록 종은 획득 방법만 안내한다. 미등록 종의 소환은 막는다. 잠긴 칸은 대상 목록에서 제외한다.

| 동작 | 파티 칸 | 도감과 육성 기록 |
|---|---|---|
| 소환 | 등록된 종을 빈 칸에 배치 | 등록 유지 |
| 교체 | 선택한 종으로 배치 변경 | 이전 종 등록과 기록 유지 |
| 소환 해제 | 빈 칸으로 변경 | 등록과 기록 유지 |
| 숨기기 / 다시 표시 | 배치 유지, 표시만 변경 | 육성 유지 |

교체는 한 번의 저장 작업으로 처리한다. 그림이나 저장이 실패하면 이전 배치를 유지한다.
파티 칸은 최대 여섯 칸이다. 도감 등록 수와 독립적이다.
파티가 가득 차도 구매·부화·진화로 새 종을 등록한다. 소환은 이후에 할 수 있다.
진화 전 종도 등록을 유지하므로 외형 선택이나 별도 보관 화면 없이 다시 소환할 수 있다.
놓아주기와 영구 삭제는 제공하지 않는다.

종별 기록을 친밀도의 소유자로 삼는 기존 제안은 개체별 관리 방향으로 대체한다. 재소환 시 같은 개체를 복원하는 방식과 새 개체를 획득하는 방식은 구분해서 설계해야 한다.
후속 사용자 결정으로 동일 종의 여러 개체 보유와 동시 파티 배치를 허용한다. 기존 HTML의 중복 제한은 새 계약의 기준으로 사용하지 않는다.
박스 보관과 숨김의 상태 변화는 [파티 표시와 박스 보관](#파티-표시와-박스-보관)으로 확정했다. 이전의 미소환 중 육성 제안보다 이 계약이 우선한다.
[스펙 미확정] 종별 기록과 기존 중복 개체의 이식은 구현 전에 확정한다. 진화 시 유지할 개체 정보는 아래의 후속 결정을 따른다.
겹침과 소환 순서는 유지한다. 교체한 포켓몬은 새로 소환한 순서로 표시한다.

## 4. 상세와 진화

진화 조건을 충족하면 진화 가능 상태를 알린다. 사용자가 원할 때 직접 진화시킨다. 구체적인 조건은 미정이다. 이미 알린 같은 진화 가능 상태는 반복해서 알리지 않는다.
선택 가능한 진화 분기의 조건을 둘 이상 충족하면 가능한 후보를 보여주고 사용자가 선택한다. 리전폼 진화 조건을 충족하면 해당 경로의 결과는 지정된 리전폼으로 정한다. 해당 조건이 없고 일반 진화 조건을 충족하면 일반 폼으로 정한다. 같은 경로에서 일반 폼과 리전폼을 자유 선택하게 하지 않는다. 조건 충족만으로 진화를 실행하지 않는다.
사용자 예시: 지정된 리전폼 조건에서는 히스이 대검귀로 진화한다. 일반 조건에서는 일반 대검귀로 진화한다. 구체적인 조건은 아직 정하지 않았다. 근거는 [분기 진화와 리전폼 조건](../work/s5-design-system-v2/plan.md#분기-진화-선택과-리전폼-조건)을 따른다.
가능한 진화 결과는 실제 실행 시점의 조건으로 판단한다. 진화 가능 알림 시점에 결과를 고정하지 않는다. 실행 전에 결과 종과 폼을 보여주고 사용자 확인을 받는다. 과거 알림만으로 현재 조건에 맞지 않는 진화를 실행하지 않는다. 근거는 [조건 판정과 결과 확인](../work/s5-design-system-v2/plan.md#진화-실행-시-조건-판정과-결과-확인)을 따른다.
진화 저장에 실패하면 진화 전 종과 도감 기록을 유지한다. 진화 완료로 표시하지 않는다. [거래 실패 원칙](#구매사용보상-거래의-실패-원칙)을 따른다.
`[스펙 미확정]` 결과 확인 중 조건이 바뀌는 경우, 여러 폼 조건의 중복 처리, 각 리전폼의 구체적인 도감 해금 조건은 별도로 정한다. 리전폼의 독립 항목과 별도 집계는 도감 해금 계약을 따른다.
한 번의 진화 선택은 다음 한 단계로만 진행한다. 여러 단계의 조건을 이미 충족했어도 중간 단계를 건너뛰지 않는다. 진화 후 다음 단계 조건도 충족했다면 다시 직접 선택해 진화할 수 있다. 다음 단계는 자동으로 실행하지 않는다. 사용자는 현재 단계에 머무를 수 있다. 근거는 [단계별 직접 진화](../work/s5-design-system-v2/plan.md#단계별-직접-진화)를 따른다.
진화 가능 알림은 화면 한쪽의 작은 배너로 잠깐 표시한다. `바로가기`를 누르면 해당 개체의 상세 화면으로 이동한다. 누르지 않으면 배너는 사라진다. 배너 표시와 `바로가기`만으로 진화시키지 않는다. 근거는 [진화와 업적의 배너 알림](../work/s5-design-system-v2/plan.md#진화와-업적의-배너-알림)을 따른다.

2026-09-25 구현: 관리 창의 진화 확인 창은 후보마다 결과 종과 상태(가능 / 모자란 조건)를 보인다. 가능한 후보가 둘 이상이면 사용자가 고른다. `취소` 는 아무것도 바꾸지 않는다. 가방의 진화의돌은 그 돌로 지금 진화할 수 있는 개체를 고른 뒤 같은 창으로 이어진다. 파티·박스 개체 모두 쓸 수 있다. 근거는 [진화 확인과 후보 고르기](../work/game-runtime/record.md#관리-창--진화-확인과-후보-고르기의-설계)를 따른다.
모든 진화에 돌이 필요하다고 가정하지 않는다. 조건과 실패 이유를 표시한다. 메인 프로세스가 최종 검사한다.

## 5. 전체 도감과 지방

전국도감 전체 종을 표시한다. 상점 해금 규칙이 있는 종만으로 제한하지 않는다.
지방 선택과 이름·번호 검색을 함께 적용한다. 검색과 선택을 유지한다.
[스펙 미확정] 지방은 전체, 관동, 성도, 호연, 신오, 하나, 칼로스, 알로라, 가라르, 히스이, 팔데아로 제안한다.
[스펙 미확정] 분류는 최초 등장 지방 기준으로 제안한다. 여러 지역도감의 중복 등재와 구분한다.
리전폼은 일반 폼과 별도 도감 항목으로 표시한다. 일반 대검귀 `503`과 히스이 대검귀 `503-1`처럼 구분한다. 지방 폼을 번호 범위만으로 판정하지 않는다. 리전폼 이외 형태의 표시와 집계는 미정이다.
지역 정보가 없는 종도 '전체'에서 누락하지 않는다.
[확인 필요] 실제 매핑과 출처는 구현 전에 검증한다.
전체 목록 표시, 획득 조건 충족, 도감 등록, 소환 중 상태를 구분한다.
등록 필터는 전체 / 등록 / 미등록이다. 지방과 검색을 함께 적용한다.
획득 규칙이 없는 종에는 '획득 방법 준비 중'을 표시한다.
그림이 없으면 공통 자리표시자를 쓴다. 다른 종의 그림으로 대신하지 않는다.
보이는 카드와 선택한 종의 그림만 요청한다. 저작자와 라이선스를 표시한다.
이전 HTML의 도감은 일부 종 예시였다. 현재 v2의 도감 본문은 미제작이다. 전체 도감 데이터 연결은 구현 단계에서 처리한다.

## 6. 상점과 가방

### 상점 구매 창

상품 카드에는 가격과 `›`만 둔다. 카드마다 `구매` 버튼을 두지 않는다. 카드를 누르면 구매 창을 연다.
여러 개 사는 상품은 구매 창에서 수량을 고르고 합계와 보유 포인트를 확인한 뒤 산다. 알·포켓몬·파티 칸처럼 하나씩 사는 상품은 수량 줄 없이 확인만 한다. 0P 상품의 버튼은 `받기`다.
구매할 수 없으면 카드는 그대로 누를 수 있다. 구매 창에서 이유를 한 줄로 보여주고 `구매`를 비활성으로 둔다. 돌보미집이 가득 찼으면 `돌보미집 보기`로 박스 메뉴의 돌보미집으로 이동한다. 포인트는 차감하지 않는다. 근거는 [검수 P2 결정](../work/s5-design-system-v2/plan.md#검수-p2-결정-항목)을 따른다.
`[스펙 미확정]` 한 번에 살 수 있는 최대 수량과 구매 창 문구는 정하지 않았다.

### 구매·사용·보상 거래의 실패 원칙

구매·사용·보상 수령은 관련 상태를 하나의 거래로 변경한다. 성공하면 전부 반영한다. 실패하면 관련 상태 전부를 이전 상태로 유지한다. 구매 실패 시 포인트와 상품 재고를 함께 유지한다. 사용 실패 시 재고와 개체 상태를 함께 유지한다. 보상 수령 실패 시 보상과 수령 상태를 함께 유지한다. 이미 완료된 거래의 재시도는 보상을 중복 지급하거나 비용을 다시 차감하지 않는다. 처리 결과가 불명확하면 저장된 결과를 확인한 뒤 재시도한다. 근거는 [사용자 결정](../work/s5-design-system-v2/plan.md#거래-실패-원자성과-코스모움-분리안-재검토)을 따른다.

실패한 거래는 실패로 처리하고 끝낸다. 실패 복구용 선택값 보존과 다시 시도 버튼은 제공하지 않는다. 자동 재시도도 하지 않는다. 관련 상태의 이전 값 유지와 완료 거래의 중복 방지는 유지한다. 정상 구매·사용·수령 조작을 이후에도 할 수 있다. 근거는 [실패 처리 범위](../work/s5-design-system-v2/plan.md#거래-실패-처리만-제공)를 따른다.
부화·진화·교체에도 같은 거래 원칙과 실패 처리를 적용한다. 근거는 [복합 동작의 거래 적용](../work/s5-design-system-v2/plan.md#부화진화교체의-트랜잭션-적용)을 따른다.

| 동작 | 하나의 거래로 처리할 상태 | 실패 시 유지할 상태 |
|---|---|---|
| 부화 | 알 소비, 개체 생성, 파티 또는 박스 배치, 돌보미집 칸 비우기, 도감 획득·발견 기록 | 부화 가능한 알과 돌보미집 칸. 개체와 도감 기록은 추가하지 않음 |
| 진화 | 종 변경, 도감 해금·획득 기록 | 진화 전 종과 도감 기록 |
| 교체 | 파티 개체와 박스 개체의 위치 | 두 개체의 원래 위치 |

부화 저장에 실패하면 결과를 저장하지 않는다. 사용자가 같은 알을 다시 열면 그 시점까지 충족한 조건으로 결과를 새로 정한다. 이 조작은 정상 열기이며 실패 전용 재시도가 아니다.
완료된 부화를 재시도해도 개체를 더 만들지 않는다. 완료된 진화를 재시도해도 다음 단계로 한 번 더 진화하지 않는다. 완료된 교체를 재시도해도 위치를 되돌리지 않는다.
진화나 교체의 결과 확인 단계에서 취소하면 아무 상태도 바꾸지 않는다. 공유 `sid` 종 교체는 일반 교체와 같은 거래로 처리한다. 실패하면 현재 종과 파티 칸을 유지한다.
첫 선택을 확정하기 전에 창을 닫으면 개체를 만들지 않는다. 다음 실행 때 선택 화면을 다시 연다. 첫 선택 저장에 실패하면 선택 화면에 남는다. 다시 고르는 조작은 정상 선택이다. 확정한 첫 개체와 시작 포인트는 재실행해도 중복 지급하지 않는다.
놀이공간 변경을 취소하거나 저장에 실패하면 적용 전 영역을 유지한다. 근거는 [취소와 남은 저장 실패](../work/s5-design-system-v2/plan.md#확정-전-취소와-남은-저장-실패의-처리)를 따른다.
`[스펙 미확정]` 실패 문구와 표시 위치, 거래 식별·저장 방식, 결과 불명 상태의 내부 판정은 후속 설계한다.

### 이로치와 색상 변경 약

이로치는 같은 개체의 색상 상태다. 별도 도감 항목이나 해금 종 수를 추가하지 않는다. 해당 도감 항목에 이로치 획득 여부를 기록한다. 일반 폼과 리전폼의 독립 항목은 유지한다.
알에서는 낮은 확률로 이로치 개체를 얻는다. 랜덤알과 태고의돌이 같다. 사용자 예시 `1/1000`은 후보 확률이다. 상점의 `모습이 바뀌는 약`을 사용해 기존 개체를 이로치로 바꿀 수도 있다. 약은 비싸게 판매한다. 실제 가격은 미정이다. 단일 종은 알에서 얻을 수 없으므로 약으로 이로치가 된다.
상점의 `돌아오는 약`은 0원이다. 대상 개체를 일반색으로 되돌린다. 두 상품명은 가칭이다. 약으로 색상을 변경해도 새 개체를 만들지 않는다. 근거는 [이로치 기록과 획득 경로](../work/s5-design-system-v2/plan.md#이로치-기록과-알-및-약-획득-경로)를 따른다.
일반 개체는 최초 획득 시 일반색으로 시작한다. 알에서 이로치로 태어났거나 약으로 바꾼 개체는 숨김 해제·박스 복귀 후에도 이로치를 유지한다. 재배치로 색상을 초기화하지 않는다.
이로치 개체는 진화 후에도 이로치를 유지한다. 돌아오는 약으로 일반색으로 바꿔도 도감의 이로치 획득 기록은 보존한다. 현재 일반색인 개체와 과거 이로치 획득 여부를 구분한다. 근거는 [이로치 유지와 획득 기록 보존](../work/s5-design-system-v2/plan.md#진화-이로치-유지와-도감-획득-기록-보존)을 따른다.
알 행동 조건은 태어날 종에만 영향을 준다. 이로치 여부는 종 결정과 별도로 동일한 낮은 확률로 추첨한다. 일반 무작위 부화와 행동 조건으로 정해진 부화 모두 같은 이로치 확률을 적용한다. 행동 조건을 여러 개 충족해도 추첨 기회나 확률을 늘리지 않는다. 준비 시간을 단축하는 기존 돌봄 효과는 유지한다. 근거는 [알 행동과 이로치 추첨 분리](../work/s5-design-system-v2/plan.md#알-행동-조건과-이로치-추첨-분리)를 따른다.
`[스펙 미확정]` 알의 이로치 추첨 시점과 실제 확률, 아이템 소모 단위·대상 범위·실패 처리, 기존 구매 권리 이식은 별도로 정한다.

### 기존 상점과 가방 제안

후속 결정: 랜덤알 구매와 부화는 첫 구매 튜토리얼에 채택했다. 아래의 기존 상품·작업 부화 제안 전체를 채택한 것은 아니다. 최신 계약은 [첫 구매와 업적 보상 수령](#첫-구매와-업적-보상-수령)을 따른다.

[스펙 미확정] 아래 상품·효과·작업 부화는 기존 제안이다. 사용자 채택 근거를 확인하기 전까지 구현 지시와 인수 조건으로 사용하지 않는다. 상점·가방 탭의 존재는 개별 상품의 채택 근거가 아니다.

| 분류 | 구매 결과 | 대상 선택 |
|---|---|---|
| 포켓몬 | 도감에 해당 종 등록 | 없음 |
| 랜덤알 | 가방에 알 추가 | 없음 |
| 도구 | 가방 재고 증가 | 없음 |
| 파티 칸 | 다음 칸 해금 | 다음 칸 자동 지정 |

민트와 진화의돌은 채택했으며 상세와 진화 계약을 따른다. 현재 S4의 민트는 구매 즉시 적용된다. 새 설계는 가방에 보관한 뒤 사용한다. 이로치 약은 위의 후속 계약을 따른다. 프리미엄먹이 판매는 후속 사용자 결정이며 [일상 사용 계약](#일상-사용-계약)을 따른다.
상점에서는 사용할 포켓몬을 고르지 않는다. 대상과 옵션은 가방에서 고른다.
민트는 가방에서 대상을 고른다. 성실민트만 보정 없는 성격 5개 중 하나를 더 고른다(2026-09-25). 이로치 도구도 가방에서 대상을 고른다.
[스펙 미확정] 현재 소환한 포켓몬만 대상으로 삼는 기존 도구 제안은 상품별로 재검토한다. 경험사탕은 후속 결정에 따라 파티와 박스의 보유 개체 모두에게 사용할 수 있다. 파티가 비었다는 이유로 경험사탕 사용을 막지 않는다.
2026-09-23 결정: 모습이 바뀌는 약은 1회 소모품이다. 쓰면 없어진다. 돌아오는 약으로 일반색으로 되돌린 개체를 다시 이로치로 바꾸려면 약을 다시 산다. 일반색 전환은 0원 돌아오는 약을 사용한다. 근거는 [저장과 거래의 남은 값 확정](../work/s5-design-system-v2/plan.md#저장과-거래의-남은-값-확정)을 따른다.
가격이 정해지지 않았으면 화면에 '미정'으로 표시한다. 이 경우 구매를 막는다. 기존 가격 예시는 새 경제 규칙 확정이 아니다.
파티가 비어 있어도 도구를 구매할 수 있다. 가방이 비면 상점 이동을 제공한다.
사용 시 소유, 수량, 대상, 적용 가능 여부를 검사한다.
성공한 경우에만 수량을 차감한다. 저장이 실패하면 수량과 개체 상태를 함께 복원한다.

[스펙 미확정] 기존 랜덤알 제안은 구매 → 가방 → 부화 시작 → 작업 → 도감 등록 흐름이다. 작업 부화 자체를 확정 기능으로 취급하지 않는다.
[스펙 미확정] 이미 등록된 종의 재구매는 막는 것으로 제안한다. 이전 HTML의 동작이며 현재 Figma나 런타임 구현 완료 항목이 아니다.
[스펙 미확정] 알 중복 결과의 보상·대체 정책은 별도로 확정한다.

## 7. 설정과 연결

배너 알림 소리는 기본으로 켠다. 설정에서 무음으로 전환할 수 있다. 음원과 적용 범위는 [알림 배너 계약](#알림-배너의-개별-표시)을 따른다.

## 9. 창과 보안

런타임마다 설정창 하나를 둔다. 재요청은 기존 창을 앞으로 가져온다.
우클릭 메뉴는 개체 상세를 연다. 우클릭 메뉴는 포켓몬 위에서만 연다. 메뉴는 앱이 직접 그리며 구현 조건은 [UI 컴포넌트 계약](ui-components.md#c-21-포켓몬-위-우클릭-메뉴)을 따른다. 포켓몬이 없는 놀이공간 영역의 우클릭은 가로채지 않고 뒤의 앱으로 넘긴다. 메뉴는 이름·상태 / 밥 주기·놀아주기 / 설정의 세 묶음이며 종료는 두지 않는다. 이름·상태 줄은 만복도 구간 이름과 기분 구간 이름을 문구로 보여준다. 만복도 구간은 배고픔 말풍선의 구간과 같다. 근거는 [검수 P2 결정](../work/s5-design-system-v2/plan.md#검수-p2-결정-항목)을 따른다. 근거는 [포켓몬 위 우클릭 메뉴](../work/s5-design-system-v2/plan.md#포켓몬-위-우클릭-메뉴)를 따른다. 트레이 아이콘은 마지막 탭을 연다. `pokebuddy settings`는 실행 중인 앱의 창을 연다.
앱이 없으면 `pokebuddy companion` 실행을 안내한다. 임의로 새 게임을 만들지 않는다.
VS Code 확장 명령은 해당 창으로 요청한다. 숨김·클릭 통과에서도 복구 경로를 유지한다.
설정창을 닫아도 포켓몬과 육성은 계속 실행한다.
포켓몬 표시 창과 설정창은 별개다. 설정창은 클릭 통과와 항상 위 설정을 물려받지 않는다.
contextIsolation과 sandbox, 전용 preload, IPC sender·최상위 frame 검사를 유지한다.
키·값·명령을 검증한다. 그림 요청은 종·폼 키만 받는다. 임의 경로나 URL은 받지 않는다.
원격 탐색과 새 창을 막는다. 저작자 링크는 허용 목록에 있는 것만 외부로 연다.
보이는 동안 최대 초당 한 번 상태를 갱신한다. 성공 직후에는 즉시 갱신한다.
닫거나 숨기면 구독·타이머를 해제한다. 탭·검색·선택·스크롤·포커스를 유지한다.

## 11. 인수 기준

2026-09-21 후속 설계: 최신 개체별 육성·박스·알·업적 흐름의 수용 조건은 [시나리오별 수용 확인](s5-scenarios.md)을 따른다. 아래 기존 항목 중 종 등록만으로 소환하는 계약과 종별 기록 계약은 재검토 대상이다. 충돌하는 과거 항목을 새 구현의 통과 기준으로 사용하지 않는다.

상품 사용·작업 부화 관련 기준은 해당 기능 채택 후에만 적용하는 기존 초안이다.

- 파티 0·1·6마리, 빈 칸·잠긴 칸·숨김을 구분한다. 숨김 마커와 표시 조작에 접근성 이름이 있다.
- 빈 칸에서 등록 도감을 연다. 해당 칸에 소환한다. 미등록 종·잠긴 칸의 소환을 막는다.
- 교체 취소와 저장 실패는 파티를 유지한다. 소환 해제와 재소환은 등록·육성 기록을 보존한다.
- 일반 도감 진입 시 이전에 취소한 목적지 칸을 재사용하지 않는다.
- 진화 전후 종을 모두 도감에서 소환한다. 반복 진화와 등록 보상 악용을 막는다.
- 파티가 가득 차도 구매·부화 결과를 도감에 등록한다.
- 별명, 모습, 독립 연결 탭이 없다. 박스 보관은 후속 계약에 따라 제공한다.
- 기본먹이와 프리미엄먹이를 구분한다. 프리미엄먹이의 확정하지 않은 수치를 구현 기준으로 사용하지 않는다.
- 지방과 검색을 함께 적용한다. 결과 0건을 안내한다. 없는 획득 규칙을 해금으로 표시하지 않는다.
- 구매 시 대상 선택이 없다. 사용 실패 시 재고와 개체 상태를 보존한다.
- [스펙 미확정] 작업 부화를 채택하면 재시도로 결과가 바뀌지 않는지 검사한다.
- 마이그레이션·실패 복원·writer 경합·중복 요청 검사를 통과한다.
- 키보드, 한영 문구, 720×780 기준 화면, 확정한 최소 창 크기, 100·125·150% 배율을 검사한다.
- 상세 하단의 성장·소환 해제에 스크롤로 도달한다. 모달에서 배경과 상태를 구분한다.
- 친밀도 값과 막대를 연결한다. 숫자별 variant를 만들지 않는다.
- 여섯 상태의 이동·복귀·실패 조작을 연결한다. 숨김 설명과 실제 종 타입을 일치시킨다.
- 실제 기능은 임시 HOME으로 검사한다. 실제 저장, 훅, 자동 시작은 변경하지 않는다.

## 12. 미정 사항과 검증 상태

[스펙 미확정] 종별 육성·재소환·보상 규칙, 진화 승계의 남은 항목, 진화의돌 종류·대상·가격, 알 경제·작업량, 이로치 약의 사용 세부 조건, 기존 권리 이식은 반드시 확정해야 한다. 확정한 개체 정보 유지 범위는 상세와 진화 계약을 따른다.
[스펙 미확정] 실행 환경 명칭과 지방 분류 기준은 제안 단계다. 동일 종의 동시 파티 배치와 박스 보관은 위의 계약을 따른다. 다섯 탭의 기존 시각 배치는 박스 UI 설계에서 재검토한다.
