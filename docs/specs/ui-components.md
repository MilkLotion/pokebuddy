# UI 컴포넌트 계약

Figma 원본: [0.2 · 와이어프레임(구 07)](https://www.figma.com/design/MA3K41Y6omAi5mRu6YDFly/pokebuddy?node-id=252-121)의 WF-01~WF-09와 상태 예시, Figma `00`~`04` 자산.

## 읽는 기준

이 문서는 화면에서 반복되는 UI의 계약이다. 게임 규칙은 [현재 설계](../design.md)와 [S5 기능 계약](game.md)을 따른다. 흐름은 [사용자 시나리오](scenarios.md)를 따른다.
각 계약의 동작은 확정 규칙에서 가져왔다. 크기·배치·문구는 와이어프레임의 제안이며 `[스펙 미확정]`이다.
판정은 기존 Figma 자산 기준이다. `재사용`은 그대로 쓴다. `수정`은 기존 자산에 변형이나 속성을 더한다. `신규`는 새로 만든다.

## 공통 규칙

| 규칙 | 내용 |
|---|---|
| 선택 표현 | 카드·목록 항목은 옅은 배경만 쓴다. 왼쪽 세로 막대는 쓰지 않는다. 메인 탭은 옅은 배경과 밑줄이다. 필터 칩은 진한 채움과 흰 글자다. 두 칸 전환은 회색 틀 안의 흰 칸이다. 헤더 아이콘은 모달이 열린 동안 진한 배경이다. 규칙은 [현재 설계](../design.md#s5-디자인-시스템-v2)를 따른다. |
| 강조 금지 | 둥근 모서리 요소를 컬러 테두리나 왼쪽 컬러 선으로 강조하지 않는다. 경계용 1px 중립 테두리는 쓴다. |
| 높이 통일 | 같은 줄의 버튼·칩·입력칸은 같은 시각 높이다. 테두리가 없는 쪽은 안쪽 여백을 축당 1px 늘린다. 같은 줄의 카드는 같은 높이다. |
| 숨김 표시 | 숨긴 개체는 초상 우측 위의 닫힌 몬스터볼 마커로 표시한다. 글자 태그를 쓰지 않는다. 규칙은 [S5 기능 계약](game.md#1-목표와-결정)을 따른다. |
| 비활성 | 비활성 버튼은 회색 면과 흐린 글자다. 이유는 가까운 곳에 한 줄로 쓴다. |
| 처리 중 | 조작의 답이 0.3초 안에 오지 않으면 누른 버튼이나 칸만 처리 중으로 바꾼다. 버튼은 폭과 색을 그대로 두고 글자 자리에 점 세 개가 차례로 밝아진다. 칸은 내용을 옅게 덮고 초상 가운데에 점 세 개를 둔다. 답이 올 때까지 다른 조작은 받지 않는다. Figma: `Button` `113:313`·`Box Slot` `333:231` 의 `State=Busy`. 기기 창도 같다. 파티 상세의 밥 주기·놀아주기(`Device Button` `1262:74948` `State=Busy`)·크기(`Size Step` `132:130` `State=Busy`)·볼 토글(`Visibility Marker` `330:143` `State=Busy`, 볼 그림 자리에 점 셋), 파티 기기 창의 칸(`Party Device Slot` `1262:99156` `State=Busy`)과 프리셋 칩(`Filter Chip` `331:130` `State=Busy`)이다(2026-10-04 사용자 결정). |
| 글꼴 | 모든 글자는 Galmuri다. 크기는 24·15·12·10px 네 단계만 쓴다. 카드의 이름·설명이 칸보다 길면 한 줄로 두고 끝을 말줄임한다. |
| 이로치 표시 | 이로치 개체는 이로치 아이콘으로 표시한다. 글자 `이로치`를 쓰지 않는다. 아이콘은 빨간 네 갈래 별 2개의 10×10 도트 그림이다. 이름이 한 줄로 나오는 곳은 이름 옆에 둔다. 칸은 왼쪽 위 구석에 둔다. 툴팁과 접근성 이름은 `이로치`다. Figma: `Shiny Mark` `1225:26525`. 구현: `src/renderer/ui/shiny-icon.ts` `shinyIcon`. (2026-10-02 사용자 결정 "E로 하자") |
| 빈 상태 | 빈 상태는 한 줄 문구만 둔다. 설명 문구를 덧붙이지 않는다. |
| 경고·안내 | 오류·주의·완료·안내는 `Alert` 로 보인다. 종류는 바탕 톤과 16px 픽셀 아이콘(`!`·`✓`·`i`)으로 구분한다. 테두리는 없고 모서리는 8px 이다. 내용 카드(흰 바탕, 중립 테두리, 12px)와 모양을 나눈다. 제목이 있으면 제목과 설명 두 줄(Banner)이다. 사용자가 닫는 배너에만 오른쪽 `✕` 를 둔다. `Alert` 는 그 상태가 이어지는 동안 늘 보이는 안내(저장 실패, 계정 분실·막힘, Node.js 없음)에만 쓴다. 누른 결과와 명령 실패는 새 줄을 끼웠다 빼지 않는다. 이미 있는 자리의 글자·색만 바꾼다(아래 `결과·실패 표시`). Figma: `Alert` `1040:279`(Tone=Error·Warning·Success·Info, Type=Banner·Inline). 구현: `src/renderer/manage/widgets.ts` `alertEl`, `src/renderer/styles/manage/widgets.css` `.alert`. (2026-09-30 사용자 결정 "시안 괜찮네") |
| 결과·실패 표시 | 누른 결과와 명령 실패는 레이아웃을 바꾸지 않는다. 가방 기기 창은 미리보기 상자가 결과면 초록(`total ok`), 실패면 빨강(`total bad`)으로 바뀐다. 첫 줄은 결과나 `쓰지 못했어요`·`팔지 못했어요`, 둘째 줄은 쓴 수나 이유다. 쓰면 손해가 있는 경우(가방에서 남은 버프를 덮어쓰기)는 같은 상자가 주황 경고(`total warn`, Figma `Result Box` `Tone=Warning`)로 바뀌고 단추는 그대로 눌린다. 상점·가방 기기 창의 미리보기·합계·결과 상자는 어느 상태든 두 줄 높이다. 둘째 줄이 없어도 자리를 둔다. 각 줄은 한 줄에서 말줄임하고, 전체는 title 이다(2026-10-05 사용자 결정 "고정시켜줘", 구현 `src/renderer/device/item-face.ts` `totalBoxEl`). 도구를 다 써서 판이 닫히면 결과를 따로 두지 않는다. 상점 기기 창(C-30)은 합계 상자가 빨강 `사지 못했어요` 로 바뀐다. 파티 기기 창은 머리 줄의 프리셋 이름 옆 자리에 빨간 글자를 둔다. 파티 상세 기기 창은 화면 첫 줄(`파티 1번 · 나와 있음`) 자리를 빨간 실패 문구로 바꾼다. 한 줄이고, 볼 토글 앞 8px 까지 쓰고, 넘치면 말줄임하고, 전체는 title 이다. 다음 조작에서 원래 글로 돌아온다(2026-10-04 사용자 결정, Figma 05 `Party / Detail Device · 실패 문구` 둘, 구현 `src/renderer/device/pet.ts` `.where.bad`). 그 밖의 대화상자는 바닥 단추 줄의 빈자리(보조 단추와 주 단추 사이의 `spacer` 안, 없으면 줄 끝)에 빨간 점과 한 줄 글자를 둔다(`footer-error`, 길면 말줄임, 전체는 title). 단추 자리는 그대로다. 바닥 단추 줄이 없는 대화상자만 예전처럼 본문 끝에 `Alert` Inline 을 둔다. 연결 탭은 그 CLI 줄의 상태 글자와 점 색으로 보인다. Figma: 결과·실패 상자는 `Result Box` `1315:47502`(`Tone=Success|Error`)다. 기기 창의 미리보기·합계 상자(`Info Box`) 자리를 이 변형으로 교체한다. 화면은 05 `Bag / Device / Use · 결과` `1315:47631`, `Bag / Device / Use · 실패` `1315:47635`, `Bag / Device / Sell · 실패` `1315:47639`, `Shop / Device / Tool · 실패` `1315:47627` 이다. 대화상자는 `Dialog` `299:3575` 의 `error-notice`(`Show Error`)이고 화면은 `Box / Sell Confirm · 실패` `1315:47608` 이다(2026-10-02 추가). 구현: 결과 상자는 상점·가방 공용 `src/renderer/device/item-face.ts` `totalBoxEl`, 가방 기기 창 `src/renderer/device/bag.ts`(`src/renderer/styles/bag.css` `.total.ok`·`.total.bad`), 상점 기기 창 `src/renderer/device/shop.ts`, 대화상자 `src/renderer/manage/dialog.ts` `drawDialog`(`src/renderer/styles/manage/dialog.css` `.footer-error`). | 모달 | 업적창·설정·개체 선택은 어두운 배경 위 대화상자다. 닫으면 보던 탭으로 돌아간다. |

## Figma 층 구성

2026-10-02 에 05 의 화면을 분해해 아래 층부터 다시 쌓았다(사용자 지시 "화면에서부터 분해단위 다 쪼개면서 다시 다 작업하고 다시 그거기반으로 조립"). 계층 규칙은 [현재 설계](../design.md#s5-디자인-시스템-v2)를 따른다.

상태: `획득`, `해금`, `미해금`(`???`), `선택`. 획득은 칸 왼쪽 위 구석의 닫힌 몬스터볼 아이콘이다. 메가진화하는 종의 해금·획득 칸은 볼 오른쪽에 메가스톤 표식이 있다. 메가스톤이 생긴 적이 있으면 진한 표식, 아니면 흐린 표식이다. 흐린 표식의 툴팁은 `메가진화`(원시회귀 종은 `원시회귀`), 진한 표식은 `메가스톤 획득`이다(2026-10-08 사용자 결정, [메가진화](game.md#메가진화)). 해금은 표시 없는 흰 칸, 미해금은 회색 바탕·실루엣·`???` 이다. 이로치 획득은 몬스터볼 옆의 이로치 아이콘으로 알린다(2026-10-02 사용자 결정 "초록점말고 몬스터볼아이콘으로 … 안2로"). 몬스터볼의 툴팁은 `획득`, 이로치 아이콘의 툴팁은 `이로치 획득`이다.

보는 방식: 도감 탭과 상점 포켓몬 탭은 `쪽` 방식과 `스크롤` 방식 가운데 고른다(2026-09-29 사용자 결정). `쪽` 방식은 위의 격자 넘김이다(도감 30칸, 상점 15칸, 상점 칸에는 가격 줄). `스크롤` 방식은 오늘 작업 전 화면 그대로다(2026-09-29 사용자 결정 "리스트형태는 작업하기 이전의 그 스크롤되는거로", "상점·도감 둘 다 작업 전 그대로"). 도감은 도감 칸 격자를 쪽 넘김 없이 전부 보인다. 상점도 `쪽` 방식과 같은 가격 줄 칸 격자를 쪽 넘김 없이 전부 보인다(2026-09-30 사용자 결정. 두 열 상품 줄 카드를 대체했다). 두 방식 모두 지방 고르기와 검색을 쓴다. `스크롤` 방식에는 넘김 줄이 없다. 초상은 보이는 것만 받는다. 1초 새로 그리기와 전체 다시 그리기에도 스크롤 위치는 그대로다. 칸이나 줄을 누르면 도감은 기기 창, 상점은 상점 기기 창이다. 고른 방식은 도감과 상점을 따로 기억하고 앱을 다시 켜도 유지한다(2026-09-29 사용자 결정). `쪽` 방식에서는 지방·검색이 바뀌면 첫 쪽이다. 도감 기기 창의 이전·다음은 `쪽` 방식에서는 다른 쪽 종이면 그 쪽으로 넘기고, `스크롤` 방식에서는 그 칸이 보이게 스크롤한다.
