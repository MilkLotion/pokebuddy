# S5 사용자 시나리오

목적: PC에서 노는 포켓몬을 구경하다가 잠깐 돌보며 쉬어 가는 경험을 설명한다.

## 읽는 기준

제품 결정은 [현재 설계](../design.md)를 따른다. 수치와 기능 규칙은 [S5 계약](game.md)과 [밸런스 수치](balance.md)를 따른다.
이 문서는 흐름과 수용 조건의 기준이다. 아직 정하지 않은 화면 배치와 예외 처리에는 `[스펙 미확정]`을 붙인다.
화면 이름은 역할을 나타낸다. 설정창의 탭과 헤더 구성은 [화면 구조](game.md#2-화면-구조)를 따른다.
포켓몬은 개체 ID로 구분한다. 같은 종 두 마리를 하나로 취급하지 않는다.
`확인:`으로 시작하는 줄은 수용 조건이다. 확정한 규칙을 검사한다. 값이 없어 검사할 수 없는 줄에는 `[스펙 미확정]`을 앞에 붙인다.

## 전체 사용 흐름

| 흐름 | 사용자 목적 | 다음 행동 |
|---|---|---|
| SC-01 첫 만남 | 함께할 포켓몬을 고른다. | SC-02 일상 사용. 시작 포인트로 SC-03 구매 가능 |
| SC-02 일상 돌봄 | 구경하다가 잠깐 돌본다. | 작업 복귀. 포인트를 모아 SC-03 또는 SC-06 이용 |
| SC-03 알 구매 | 새로운 포켓몬을 기다린다. | SC-04 돌보미집 |
| SC-04 직접 부화 | 부화 순간을 직접 본다. | 초반에는 SC-05 첫 업적 |
| SC-05 두 마리와 첫 업적 | 두 마리를 함께 보고 업적 이용을 익힌다. | 업적 배너의 `바로가기`로 업적창에 가서 보상 수령. 첫 칸 보상 수령 시 1칸 추가 |
| SC-06 성장·진화 | 경험사탕으로 키우고 원할 때 진화한다. | 도감 조건 확인 또는 일상 사용 |
| SC-07 파티·박스 | 함께할 개체를 바꾼다. | 바뀐 파티로 일상 사용 |
| SC-08 놀이공간 | 작업에 맞춰 활동 영역을 바꾼다. | 정한 공간에서 구경하기 |
| SC-09 획득·칸 확장 | 입수 조건을 확인하고 파티를 넓힌다. | 획득 개체 배치 또는 보관 |
| SC-10 종료·재개 | 이전 상태에서 다시 함께한다. | 중단한 행동 또는 일상 사용 |
| SC-11 에이전트 연결 | 선택적으로 추가 이득을 얻는다. | 기본 경험에 추가 보상 연결 |

튜토리얼은 이 흐름의 이용 조건이 아니다. 사용자가 관련 행동을 하면 해당 튜토리얼을 시작한다. SC-03을 미뤄도 SC-02를 계속 이용한다.
튜토리얼을 닫으면 해당 튜토리얼을 스킵한 것으로 처리한다. 스킵한 튜토리얼은 재진입이나 재실행 후에도 다시 표시하지 않는다. 튜토리얼 다시보기는 제공하지 않는다. 이후 사용법은 가이드북에서 확인한다.

## SC-01 첫 만남

진입: 새 게임이며 첫 개체를 아직 선택하지 않았다.
목적: 원하는 진화 전 포켓몬을 곁에 둔다.
근거: [일상 사용 계약](game.md#일상-사용-계약).

1. 별도로 지정한 첫 선택 후보를 본다. 후보는 `data/unlocks.json`에 `starter: true`로 표시한 29종이다. 후보 종은 모두 초기 도감에 해금되어 있다.
2. 원하는 진화 전 포켓몬을 고른다.
3. 첫 개체와 화면 전체에서 생활을 시작한다. 파티는 사용 가능한 2칸으로 시작한다.
4. 랜덤알 하나를 살 수 있는 시작 포인트를 한 번 받는다. 금액은 [밸런스 수치](balance.md#가격)를 따른다.
5. 첫 돌봄 튜토리얼에서 포켓몬을 우클릭하고 메뉴의 밥 주기나 놀아주기를 골라 짧게 반응을 본다. 그 뒤 설정창에서 상점 튜토리얼이 나온다. 놀이공간 변경은 설정 모달 `화면` 탭의 화면 튜토리얼에서 직접 해 본다.
6. 상점 튜토리얼을 보거나 바로 일상 사용으로 돌아간다.

분기: 튜토리얼을 건너뛰어도 시작 포인트는 같다. 가이드북 열람으로 시작 포인트를 추가 지급하지 않는다.
선택을 확정하기 전에 닫으면 개체를 만들지 않는다. 다음 실행 때 선택 화면을 다시 연다. 저장에 실패하면 선택 화면에 남는다. 사용자는 다시 고를 수 있다. 확정한 첫 개체와 시작 포인트를 재실행으로 중복 지급하지 않는다.
종료 상태: 첫 개체를 보유한다. 시작 포인트 지급 여부는 튜토리얼 완료 여부와 별도다.
수용 확인: 후보 밖의 종을 지급하지 않는다. 건너뛰어도 상점과 돌봄을 이용한다. 재실행·가이드북 열람에서 첫 개체나 시작 포인트가 늘어나지 않는다. 도감 해금만으로 선택하지 않은 개체를 지급하지 않는다.

## SC-02 일상 돌봄과 작업 복귀

진입: 파티에 개체가 있다. 사용자는 PC에서 일을 한다.
목적: 포켓몬을 구경하다가 짧게 쉬어 간다.
근거: [제품 목적](../design.md#제품-목적), [친밀도와 경험치의 역할](game.md#친밀도와-경험치의-역할).

1. 포켓몬이 놀이공간에서 자유롭게 활동한다.
2. 파티 개체의 만복도가 시간에 따라 줄어든다. 함께한 시간으로 친밀도를 얻는다.
3. 각 개체의 현재 친밀도에 따른 간격으로 포인트가 쌓인다.
4. 화면에 보이는 포켓몬이 배고픔 알림 구간에 들어가면 작은 말풍선을 표시한다. 그 구간에 머무르면 배고픔은 10분마다, 매우 배고픔은 5분마다 다시 표시한다.
5. 사용자가 원할 때 밥 주기 또는 놀아주기를 선택한다.
6. 한 번의 조작으로 반응을 구경한다. 원하면 더 놀아주고, 다시 작업으로 돌아간다.

들뜸·신남 분기: 놀아주면 놀아주기 상태가 20분 붙는다. 이 상태 자체에는 효과가 없다. 놀아주기 쿨타임은 10분이다. 쿨타임이 지난 뒤 상태가 남은 10분 안에 다시 놀아주면 중첩이 오른다. 2중첩이 되면 들뜸, 3중첩이 되면 신남 버프가 켜진다(2026-09-29 사용자 결정). 상태가 끝나면 중첩은 0으로 돌아간다. 쿨타임 안에 여러 번 눌러도 중첩은 오르지 않는다.
들뜸과 신남은 놀아준 한 마리의 친밀도 증가량을 일정 시간 높인다. 효과는 들뜸 < 신남 < 든든함(프리미엄먹이 버프)이다.
장난감 분기: 장난감으로 놀아주면 일반 놀아주기와 같은 반응에 파티클 같은 효과가 더해진다. 장난감은 1회성이며 한 번 놀아주면 1개를 소비한다. 가방에서 장난감을 드래그해 포켓몬 위에 드롭하면 사용한다. 신남 버프를 받는다.

표현 분기: 같은 배고픔 구간에서는 정한 간격으로 말풍선을 되풀이한다. 규칙은 [배고픔 상태 표시](game.md#배고픔-상태-표시)를 따른다. 배고플 때 움직임은 바꾸지 않는다. 더 심한 구간에 진입하면 말풍선을 바로 다시 표시한다. 여러 마리가 동시에 배고프면 각자 말풍선을 띄운다.
숨김 분기: 배고픔은 파티창의 상태 표시로만 확인한다. 배고픔 때문에 포켓몬이나 창을 자동으로 표시하지 않는다. 사용자가 파티창을 직접 열면 현재 상태를 확인할 수 있다.
분기: 표현을 지나쳐도 일을 계속할 수 있다. 배고픔 디버프는 새 친밀도 증가량을 줄인다. 누적 친밀도는 깎지 않는다.
프리미엄먹이를 사용하면 먹이를 준 한 마리의 친밀도 증가량에 기간형 버프를 적용한다. 경험치에는 같은 배율을 곱하지 않는다.
돌봄 보너스 분기: 친밀도가 100인 개체는 기분 단계와 버프가 포인트 적립을 올린다(2026-10-02 사용자 결정). 친밀도가 100 미만인 개체의 포인트 적립은 기분과 버프로 바뀌지 않는다. 수치는 [돌봄 보너스](balance.md#돌봄-보너스)를 따른다.
먹이 분기: 만복도가 최대이거나 밥 주기 쿨타임 중이면 먹이를 사용할 수 없다. 먹이를 소비하지 않고 만복도·버프도 바꾸지 않는다. 만복도가 최대 미만이고 쿨타임이 끝났으면 다른 사용 조건을 확인한 뒤 먹이를 준다.
기본먹이는 무료로 무제한 제공한다. 포인트와 먹이 재고는 필요하지 않다. 기본먹이는 만복도를 일정량 회복한다. 회복 효율은 매우 낮게 설정한다. 연속 사용은 밥 주기 쿨타임으로 제한한다. 쿨타임은 개체별로 적용한다. 같은 개체의 기본먹이와 프리미엄먹이는 쿨타임을 공유한다. 다른 개체에게는 별도로 먹이를 줄 수 있다.
앱 실행 중이고 PC를 사용할 수 있으면 파티 개체의 쿨타임이 진행한다. 숨김 상태에서도 진행한다. 박스 보관·PC 잠금·절전·앱 종료 중에는 남은 시간을 보존한다. 복귀 후 남은 시간부터 이어간다. 중단 기간은 소급 적용하지 않는다.
프리미엄먹이는 만복도를 최대까지 채운다. 같은 먹이를 다시 사용하면 버프의 남은 시간을 해당 먹이의 기본 지속시간으로 갱신한다. 이전 잔여 시간을 더하지 않는다. 버프가 끝났더라도 만복도가 최대이면 먹일 수 없다.
돌봄 실패는 화면의 포커스를 빼앗지 않는 방식으로 알린다. 포켓몬 메뉴는 할 수 없는 밥 주기·놀아주기 항목을 흐리게 둔다(`src/view/menus.ts`). 흐린 항목에 까닭 문구는 붙이지 않는다(2026-10-02 사용자 결정). 돌봄에 실패하면 아이템과 상태를 그대로 유지한다.
종료 상태: 포켓몬은 계속 활동한다. 사용자는 별도 완료 과제 없이 작업으로 복귀한다.
수용 확인: 돌봄하지 않아도 앱 이용이 막히지 않는다. 돌봄하지 않아도 포인트 적립이 기본 속도 아래로 내려가지 않는다. 친밀도 적립과 포인트 적립을 구분한다. 다른 개체에 든든함 버프가 복제되지 않는다.
먹이 확인: 최대 만복도에서 반복 조작해도 먹이나 버프 상태가 바뀌지 않는다. 프리미엄먹이는 대상 개체만 최대 만복도로 만든다. 기본 지속시간으로 갱신하며 시간이나 배율을 누적하지 않는다.
기본먹이 회복 확인: 쿨타임을 지키며 여러 번 먹이면 배고픔에서 서서히 회복할 수 있다. 자연적인 만복도 감소를 함께 계산한다. 포인트나 프리미엄먹이가 없어도 이 회복 경로를 사용할 수 있다. 수치는 [밸런스 수치](balance.md#만복도와-돌봄)를 따른다.
적립 속도 변경 확인: 친밀도 상승으로 적립 간격이 짧아져도 이미 쌓인 진행 비율은 유지한다. 남은 부분부터 새 속도를 적용한다. 50% 진행에서 간격이 100초에서 80초로 바뀌면 남은 시간은 40초다. 이 값은 추가 변화가 없을 때의 설명용 예시다.
기본먹이 회복량·밥 주기 쿨타임·만복도 감소와 구간·버프 배율과 지속시간·장난감 가격은 [밸런스 수치](balance.md#만복도와-돌봄)를 따른다.
`[스펙 미확정]` 버프와 배고픔 디버프를 함께 적용하는 순서.

## SC-03 시작 포인트와 알 구매

진입: 사용자가 상점을 연다. 시작 포인트 또는 모은 포인트가 있다.
목적: 상점 이용을 익히고 새로운 포켓몬을 얻을 알을 구매한다.
근거: [첫 구매와 업적 보상 수령](game.md#첫-구매와-업적-보상-수령).

1. 상점에서 랜덤알의 가격과 입수 가능한 종 범위를 본다.
2. 랜덤알 카드를 눌러 상점 기기 창을 열고 `구매`를 선택한다.
3. 구매가 완료되면 포인트를 차감하고 알을 돌보미집의 빈 칸에 배치한다. 가능한 종 범위를 해당 알의 개체 식별자(sid)에 연결해 저장한다.
4. 별도 시작 조작 없이 알의 준비 타이머가 진행된다.
5. 이 행동을 처음 했다면 부화 관련 튜토리얼을 시작한다.

분기: 다른 상품을 사도 된다. 포인트를 다시 모아 나중에 알을 구매하면 그때 부화 튜토리얼을 시작한다.
돌보미집이 6개로 차면 포인트 차감 없이 알 구매를 막는다. 부화 가능한 알도 점유 수에 포함한다.
알도 여러 개를 한 번에 살 수 있다. 최대는 돌보미집 빈 칸, 포인트로 살 수 있는 수, 단일 포켓몬 알의 남은 수 가운데 가장 작은 값이다. 하나라도 넣지 못하면 전부 되돌린다.
잔액이 부족하거나 돌보미집이 가득 차면 상점 기기 창의 `구매`가 비활성이다. 기기 창을 닫으면 알을 만들지 않는다. [상점 기기 창](game.md#상점-기기-창)을 따른다.
구매 저장 실패 시 포인트와 알을 함께 이전 상태로 유지한다. 응답이 불확실하면 저장된 구매 결과를 확인한 뒤 재시도한다. 완료된 구매를 재시도해도 알을 중복 지급하거나 포인트를 다시 차감하지 않는다.
종료 상태: 구매한 알과 진행 상태가 존재한다. 튜토리얼을 열어 두지 않아도 진행한다.
수용 확인: 시작 포인트의 사용처를 제한하지 않는다. 만석에서 추가 구매되지 않는다. 같은 구매 재시도로 포인트나 알이 중복 반영되지 않는다. 초기 알 후보는 하나 이상이다.
초기 알 후보는 첫 선택 후보 29종이다. 시작 포인트로 알 하나를 구매할 수 있다. 종별 전용 입수처는 유지한다. 알에서는 진화 전 종만 나온다. 진화 전 종이 있는 종은 랜덤알 후보에서 뺀다. 첫 선택 후보는 예외다.
구매 후 새로 해금한 종은 이미 산 알에서 나오지 않는다. 알별로 구매 당시 후보 범위를 유지한다. 최종 결과는 직접 열 때 정하고 부화 거래에서 함께 저장한다.
단일 포켓몬은 구매 시 알 후보 범위에서 제외한다.
알 가격과 확률은 [밸런스 수치](balance.md#확률과-알)를 따른다.

## SC-04 돌보미집과 직접 부화

진입: 돌보미집에 구매한 알이 있다. 돌보미집은 박스 탭 넘김 줄의 돌보미집 아이콘 단추로 여는 모달이다. 알은 데스크톱 놀이공간에 배치하지 않는다.
목적: 알의 준비를 기다리고 부화 순간을 직접 본다.
근거: [부화 계약](game.md#부화-준비와-결과).

1. 최대 6개의 알을 각자의 남은 시간과 함께 확인한다.
2. 각 알은 구매 직후부터 자기 타이머로 준비한다. 준비 시간은 5분이다.
3. 준비 시간을 줄이는 조작은 없다. 알 돌봄은 2026-09-28 삭제했다(사용자 결정).
4. 준비 시간이 끝나면 해당 알은 부화 가능 상태로 기다린다.
5. 사용자가 직접 열면 알에 저장한 후보 범위에서 수집 난이도 가중치로 결과 종을 추첨한다. 부화 결과 창은 태어난 개체를 보여주고 `확인`만 둔다. 돌보미집 모달 위에 겹쳐 뜨고 `확인` 뒤 돌보미집으로 돌아간다.
6. 파티에 빈 칸이 있으면 새 개체를 꺼낸 상태로 배치한다(`src/egg/open.ts`). 새 개체는 바로 놀이공간에 나타난다. 파티가 가득 차면 박스로 보낸다.
7. 알이 차지하던 칸이 비어 추가 구매가 가능해진다.

분기: 준비 시간 5분이 지나면 부화 가능 상태가 된다. 준비가 끝나도 자동으로 열리지 않는다. 앱 종료 중에는 준비 시간을 진행하지 않는다.
부화 저장에 실패하면 알을 부화 가능 상태로 유지한다. 개체를 지급하지 않는다. 돌보미집 칸과 도감 기록도 바꾸지 않는다. 사용자가 다시 열면 저장한 후보 범위에서 결과를 새로 추첨한다. 실패 전용 재시도 버튼은 제공하지 않는다. 완료한 부화를 재시도해도 개체를 더 만들지 않는다.
부화 연출을 중간에 닫거나 앱이 종료돼도 결과는 이미 저장돼 있다. 부화 결과 창을 다시 보여주지 않는다. 사용자는 도감·파티·박스에서 새 개체를 확인한다.
종료 상태: 알 하나가 개체 하나로 바뀐다. 새 개체는 파티 또는 박스 한 곳에만 존재한다.
수용 확인: 알마다 타이머가 따로 진행한다. 준비 완료와 직접 열기를 구분한다. 결과는 해금한 종 중 알 입수처와 경로별 조건을 만족한 종이다. 진화 전용과 이후에도 기믹 입수만 허용한 종은 제외한다. 기믹으로 해금한 뒤 알 입수를 허용한 종은 일괄 제외하지 않는다.
준비 완료 알림: 준비가 완료되는 순간 작은 알림을 한 번 제공한다. 돌보미집 메뉴를 열지 않은 상태에서도 알 수 있어야 한다. 알림만으로 부화하거나 결과 포켓몬을 공개하지 않는다. 사용자가 나중에 메뉴를 열어 직접 부화할 수 있다.
배너 분기: 화면 한쪽에 작은 배너를 잠깐 표시한다. `바로가기`를 누르면 돌보미집을 연다. 누르지 않으면 배너는 사라진다. 준비된 알은 유지한다. `바로가기`만으로 부화하지 않는다. 배너는 결과 포켓몬을 보여주지 않는다.
동시 완료 분기: 알별 배너를 하나씩 순차 표시한다. 여러 알을 하나의 개수 요약 배너로 묶지 않는다. 같은 순간에 준비된 알은 돌보미집 칸 순서로 표시한다. 진화·업적 배너와 같은 순간이면 부화 배너를 먼저 표시한다. 진화·업적 배너와 함께 생겨도 [개별 표시 계약](game.md#알림-배너의-개별-표시)을 따른다.
소리 확인: 배너를 띄울 때 알림음을 한 번 낸다. 알림음 크기는 설정의 소리 크기를 따른다. 음소거하면 알림음을 재생하지 않는다. 배너 표시와 클릭 이동은 유지한다. 진화·업적 배너도 같은 소리 계약을 따른다. 소리 규칙은 [알림 배너의 개별 표시](game.md#알림-배너의-개별-표시)를 따른다.
배너는 뜬 뒤 3초가 지나면 사라진다. 커서를 올려도 멈추지 않는다. 제목 줄 `✕`를 누르면 바로 닫히고 다음 배너가 뜬다. 주 화면 작업 영역 오른쪽 아래에 띄운다.
`[스펙 미확정]` OS 무음·집중 모드 연동, 메뉴 진입 버튼의 준비된 알 개수 표시. 보류한다.
결과 확인: 준비 시간이 끝나면 직접 열 수 있다. 결과는 알에 저장한 후보 범위에서만 정한다. 알별 범위를 서로 섞지 않는다.
진화형 확인: 진화 전 종이 있는 종은 랜덤알 결과로 나오지 않는다. 첫 선택 후보는 예외다.
일반 무작위 확인: 후보 종의 수집 난이도 1~5에 따른 공통 가중치로 추첨한다. 난이도는 원작 지표로 자동 계산하고 종별로 덮어쓸 수 있다. 종별 상세 확률을 직접 입력하지 않는다. 허용 범위 밖의 종은 포함하지 않는다. 가중치 값은 [밸런스 수치](balance.md#확률과-알)를 따른다.
이로치 확인: 종 결정과 별도로 1/1000 확률로 이로치 여부를 추첨한다. 확률은 [밸런스 수치](balance.md#확률과-알)를 따른다.
이로치 여부는 사용자가 알을 열 때 종과 함께 뽑는다(`src/egg/hatch.ts` `pickHatch`).
후보 고정 확인: 기다리는 동안 새로 해금된 종은 후보에 추가하지 않는다.
열기 요청은 들어온 순서대로 하나씩 처리한다.

## SC-05 두 마리와 첫 업적

진입: 첫 포켓몬과 다른 개체를 처음 획득했다.
목적: 두 마리가 함께 보이면 첫 업적을 달성한다. 업적 배너와 업적창으로 보상 수령을 익힌다.
근거: [첫 구매와 업적 보상 수령](game.md#첫-구매와-업적-보상-수령), [칸 확장](game.md#파티-칸-확장과-박스-수용).

아래는 알 부화 후 두 마리가 함께 보이는 대표 경로다.

1. 첫 포켓몬과 다른 개체를 처음 얻는다. 같은 종도 개체 식별자로 구분한다.
2. 파티에 빈 칸이 있으면 새 개체는 꺼낸 상태로 배치된다. 첫 포켓몬 이후 구매·부화·특수 획득 개체에 같은 배치 규칙을 적용한다(`src/party/create.ts` `addNewPet`, `src/egg/open.ts`).
3. 파티의 서로 다른 두 개체를 실제로 표시하면 첫 업적을 달성한다. 같은 종의 두 개체도 인정한다.
4. 화면 우측 아래에 업적 배너를 한 번 표시한다. 배너는 `업적 달성` 제목, 업적 표시와 이름, `바로가기` 버튼으로 구성한다.
5. 사용자가 `바로가기`를 누르면 업적창의 해당 업적 수령 화면으로 이동한다.
6. 사용자가 보상 받기를 선택하면 추가 한 칸이 열린다.

분기: 업적을 달성해도 수령하지 않으면 칸은 그대로다. 달성 후 다시 숨겨도 달성은 유지한다.
미수령 분기: 받지 않은 보상은 업적창을 닫거나 앱을 다시 실행해도 미수령 상태로 남는다. 수령 기한은 없다. 각 업적의 보상은 한 번만 받는다.
알림 분기: `바로가기`를 누르지 않으면 배너는 사라진다. 업적은 업적창에 미수령 상태로 남는다. 미수령 보상이 있으면 탭 줄의 업적창 아이콘에 dot를 표시한다. 배너 표시와 `바로가기`만으로 보상을 지급하지 않는다.
새 개체는 꺼낸 상태로 들어와 따로 가르칠 조작이 없다. 파티 튜토리얼은 없다.
남은 정의의 대상은 첫 개체가 아닌 개체 가운데 먼저 얻은 개체다. 대상이 이미 꺼내져 있거나 박스에 들어갔으면 완료로 기록한다. 첫 개체의 재배치나 진화는 새로운 개체 획득으로 세지 않는다. 알 구매는 개체 획득이 아니다.
업적 튜토리얼: 받지 않은 업적이 처음 생기면 시작한다. 헤더의 업적 아이콘을 밝히고 `업적 보기`로 업적창을 연다. 업적 보상을 한 번 받으면 끝난다(`src/tutorial/conditions.ts` `achievement`). 업적창에 들어간 것만으로는 시작하지 않는다.
수령 실패 시 칸과 미수령 상태를 함께 이전 상태로 유지한다. 이미 완료된 수령 처리를 재시도해도 보상을 중복 지급하지 않는다.
종료 상태: 첫 칸 업적 보상을 받았고 다른 확장이 없었다면 기본 2칸에서 3칸이 된다. 달성하지 않았거나 수령하지 않았으면 칸이 늘지 않는다. 숨긴 개체도 배고픔·적립·버프 시간이 진행된다는 원칙은 바뀌지 않는다.
수용 확인: 파티 두 칸 점유만으로 달성하지 않는다. 두 개체가 모두 보여야 달성한다. 알을 자동으로 표시하지 않는다. 업적창에 들어간 것만으로 보상을 지급하지 않는다.
동일 종 확인: 서로 다른 파이리 두 마리를 화면에 꺼내면 달성한다. 파이리 한 마리만 반복해서 숨기고 표시한 것으로는 두 개체 조건을 충족하지 않는다.
튜토리얼 확인: 새 개체를 얻어도 튜토리얼이 새로 나오지 않는다. 업적창 첫 진입은 튜토리얼을 시작하지 않는다. 받지 않은 업적이 처음 생기면 업적 튜토리얼이 나온다. 파티 개체를 파티 상세 기기 창에 처음 띄우면 개체 상세 튜토리얼 5단계가 나온다. 박스 개체를 띄우면 나오지 않는다. 설정 모달의 `화면` 탭을 처음 열면 화면 튜토리얼이 나온다.
첫 돌봄 확인: 말풍선이 떠 있는 동안 포켓몬 왼쪽 클릭은 놀아주기가 아니다. 대상 포켓몬 우클릭과 말풍선 단추만 받는다. 설정창에서 밥을 주어도 첫 돌봄은 끝나지 않는다. 우클릭 메뉴에서 밥 주기나 놀아주기를 고르면 끝난다.
튜토리얼이 겹치면 진행 중인 튜토리얼을 마치거나 건너뛴 뒤 다음 튜토리얼을 보여준다. 화면은 강제로 전환하지 않는다. 닫기도 해당 튜토리얼의 스킵으로 처리한다. 닫은 튜토리얼을 나중에 이어서 보여주지 않는다.
튜토리얼은 코치마크로 보여준다. 튜토리얼이 기다리는 동안 별도 표시를 두지 않는다.
수용 확인: 완료·스킵·닫기 후에는 다음 튜토리얼을 막지 않는다. 닫은 튜토리얼은 해당 화면을 다시 열어도 나오지 않는다. 다시보기 조작은 없으며 사용법은 가이드북에서 확인한다.
동시 조건 확인: 여러 튜토리얼 조건이 생기면 먼저 생긴 조건부터 보여준다. 같은 순간이면 첫 돌봄 → 상점 → 부화 → 업적 순서다. 바탕화면에 나온 포켓몬이 없으면 첫 돌봄은 차례를 넘긴다.
`[스펙 미확정]` 화면별 코치마크 말풍선 위치, 업적 표시 `[A]`의 형태.

## SC-06 경험사탕과 직접 진화

진입: 사용자가 포인트와 육성할 개체를 보유한다.
목적: 친밀도를 유지하면서 레벨을 높이고 원하는 때 진화한다.
근거: [성장 경로](game.md#친밀도와-경험치의-역할), [상세와 진화](game.md#4-상세와-진화).

1. 경험사탕XS·S·M·L·XL과 이상한사탕은 처음부터 상점에서 판매한다. 별도 해금 조건은 없다. 포인트로 원하는 경험사탕을 구매한다. 향후 탐험 보상으로도 얻는다.
2. 획득한 사탕은 공통 가방에 종류별로 보관한다. 가방 칸 수와 종류별 보유 수량은 제한하지 않는다. 가방에서 사용할 사탕을 선택한다. 대상 한 개체와 사용할 경험사탕 개수를 선택한다. 획득 경험치와 예상 레벨을 확인한 뒤 사용한다. 여러 개를 한 번에 사용할 수 있다. 파티·박스의 보유 개체와 숨긴 파티 개체도 선택할 수 있다.
3. 해당 개체가 경험치를 얻는다. 레벨 상승에 필요한 양을 채우면 레벨이 오른다. 친밀도와 경험치는 별도다.
4. 레벨 조건에 따라 도감이 해금된다. 진화 조건을 충족한 개체에는 가능 상태를 알린다.
5. 사용자가 원하면 직접 진화를 선택한다. 원하지 않으면 현재 종으로 지낸다.
6. 일반 개체의 완료한 진화는 되돌리지 않는다. 이전 종을 다시 원하면 별도 개체를 얻는다. 지정한 단일 포켓몬 진화 계열은 아래 공유 `sid` 예외를 따른다.

여러 단계 충족 분기: 한 번의 선택으로 다음 한 단계만 진화한다. 다음 단계의 조건도 충족했다면 사용자가 다시 선택할 수 있다. 중간 단계를 건너뛰거나 자동으로 연속 진화하지 않는다. 사용자는 현재 단계에 머무를 수 있다.
단계 확인: 여러 단계 조건을 충족한 파이리는 먼저 리자드로 진화한다. 리자몽으로 진화하려면 사용자가 별도로 다시 선택한다. 각 단계에서도 기존 개체 정보를 유지한다.
분기 선택: 가능한 진화 분기가 둘 이상이면 사용자가 후보 중에서 선택한다. 기본형에서 리전폼으로 가는 진화에는 `지도` 가 필요하다. 원래 조건이 도구이면 지도가 그 도구를 대신한다. 원래 조건이 레벨이나 친밀도이면 그 조건과 지도가 함께 필요하다. 지도가 없으면 그 경로는 일반 폼으로만 진화한다. 두 결과의 조건을 모두 채우면 일반 폼과 리전폼이 모두 후보다. 규칙은 [지도](game.md#지도)를 따른다.
폼 확인: 실제 진화 실행 시점의 조건으로 결과를 판단한다. 알림 시점에 결과를 고정하지 않는다.
지도 확인: 히스이 대검귀의 조건은 Lv.36 과 지도다. Lv.36 은 원작 값이고, 지도 규칙은 2026-09-30 사용자 결정이다. 쌍검자비가 Lv.36 이고 지도가 없으면 대검귀 후보만 진화할 수 있다. 히스이 대검귀 후보는 `지도 필요` 로 누를 수 없다. 지도가 있으면 대검귀와 히스이 대검귀 가운데 고른다. 히스이 대검귀를 고르면 지도 1개를 쓴다. 대검귀를 고르면 지도를 쓰지 않는다.
지도만 확인: 알로라 라이츄의 조건은 지도 하나다. 2026-09-30 사용자 결정: "그냥 라이츄와 알로라 라이츄 의 경우엔 천둥의돌이면 라이츄, 지도면 알로라라이츄로 진화하게 하자. 아이템1개만쓰는게 나을거같네."
- 피카츄가 지도만 가졌으면 알로라 라이츄 후보만 진화할 수 있다. 알로라 라이츄로 진화하면 지도 1개를 쓴다.
- 피카츄가 천둥의돌만 가졌으면 라이츄 후보만 진화할 수 있다. 알로라 라이츄 후보는 `지도 필요` 로 누를 수 없다.
- 피카츄가 천둥의돌과 지도를 모두 가졌으면 라이츄와 알로라 라이츄 가운데 고른다. 알로라 라이츄를 고르면 지도 1개만 쓰고 천둥의돌은 남는다. 라이츄를 고르면 천둥의돌 1개만 쓰고 지도는 남는다.
- 가방에서 천둥의돌로 진화 창을 열면 알로라 라이츄 후보는 보이지 않는다.
- 쓸 도구가 없으면 가방을 바꾸지 않고 거절한다.

알림 분기: 진화 가능 상태는 화면 한쪽의 작은 배너로 잠깐 알린다. `바로가기`를 누르면 설정창을 열고 해당 개체를 파티 상세 기기 창에 띄운다. 누르지 않으면 배너는 사라진다. 배너 표시와 `바로가기`만으로 진화시키지 않는다. 배너는 결과 종을 보여주지 않는다.

결과 확인: 실행 전에 결과 종과 폼을 보여주고 사용자 확인을 받는다. 알림 후 조건이 달라졌다면 실행 시점의 조건에 따른 결과를 확인한다.
진화 저장에 실패하면 진화 전 종과 도감 기록을 유지한다. 진화 완료로 표시하지 않는다. 완료한 진화를 재시도해도 다음 단계로 한 번 더 진화하지 않는다.
확정 전에 취소하면 현재 개체와 진화 가능 상태를 유지한다.
결과 확인 중 조건이 다시 바뀌면 사용자가 확인을 누르는 순간의 조건으로 판정한다.
진화 확인 창에 되돌릴 수 없다는 안내 한 줄을 둔다. 구현은 진화 확인 창(`src/renderer/manage/manage.ts` `drawEvolve`)이다.
사탕 사용 실패 시 재고와 개체 상태를 함께 이전 값으로 유지한다. 이미 완료된 사용을 재시도해도 사탕을 다시 차감하거나 효과를 중복 적용하지 않는다.
단일 포켓몬 진화 예외: 지정한 진화 계열은 같은 `sid`의 한 개체다. 별도 개체를 생성하지 않는다. 친밀도·레벨 등 진행 상태를 공유한다. 베베놈을 꺼낸 동안 아고용은 동시에 꺼낼 수 없다. 스탯은 현재 선택한 종의 기준을 적용한다. 종 전환으로 진행 상태를 초기화하거나 시간 진행·포인트를 중복 계산하지 않는다. 단일 포켓몬 전용 재획득 불가 경고는 추가하지 않는다. 종 선택은 박스에서 교체하는 흐름을 따른다. 상세 화면의 종 선택은 채택하지 않는다. 파티의 같은 `sid`가 있는 칸을 교체한다. 빈칸이 있어도 추가 배치하지 않는다. 코스모움에서 한 번 진화하면 솔가레오와 루나아라 모두 교체 가능해진다. 각 종을 얻기 위해 따로 진화하지 않는다. 같은 `sid`이므로 동시에 꺼낼 수는 없다. 진화 실행 시 게임 시간의 낮이면 솔가레오가 현재 종이 된다. 밤이면 루나아라가 된다. 현재 종을 따로 선택하지 않는다. 어느 쪽으로 진화해도 두 종 모두 박스 교체 대상으로 제공한다. 게임 시간 기능은 향후 구현한다. 네크로즈마는 이 공유 `sid` 계열과 별개다. 두 종을 함께 제공하는 순간 도감에도 솔가레오와 루나아라 모두 획득한 것으로 기록한다. 낮에 솔가레오로 진화해도 루나아라를 따로 꺼내야 기록되는 것은 아니다. 밤에 루나아라로 진화해도 같은 원칙을 따른다. 공유 개체는 하나이며 도감 획득 기록은 두 종이다. 게임 시간 세부 규칙, 박스 표시 방식, 다른 대상의 제공 묶음은 후속 설계한다.
일반 진화 상태 유지: 같은 개체 ID와 친밀도·성격·레벨·누적 경험치를 유지한다. 만복도와 남은 버프·먹이 쿨타임을 유지한다. 파티·박스 위치와 숨김 상태도 유지한다. 배고픈 개체를 진화해도 만복도가 회복되거나 쿨타임이 초기화되지 않는다.
종료 상태: 경험치와 도감 해금 및 실제 진화를 구분한다. 리자드 같은 진화 전용 종은 상점에 자동 추가하지 않는다.
수용 확인: 포인트를 얻었다고 친밀도가 차감되지 않는다. 도감 해금만으로 개체를 지급하지 않는다. 진화 가능한 상태와 진화 완료를 구분한다.
이로치 확인: 이로치 개체는 진화 후에도 이로치로 유지한다.
박스 사용 확인: 파티가 비어 있어도 박스 개체에게 경험사탕을 줄 수 있다. 경험치는 대상 개체에 적용한다. 파티·박스 위치와 숨김 상태는 바꾸지 않는다. 박스에서 자동 성장을 재개하지 않는다. 레벨이 올라 진화 조건을 충족해도 자동 진화하지 않는다.
미리보기 확인: 수량에 맞는 획득 경험치와 예상 레벨을 표시한다. 미리보기만으로 재고나 경험치를 바꾸지 않는다. 사용 결과는 선택한 개체 한 마리에 적용한다. 자동 진화하지 않는다.
레벨 상한 확인: 최대 레벨은 100이다. 레벨 101 이상으로 성장하지 않는다. 최대 레벨에서도 친밀도 성장과 포인트 적립은 기존 상태별 규칙을 따른다.
사탕 상한 확인: 이미 100레벨이면 사용할 수 없고 사탕을 소비하지 않는다. 100레벨 미만에서는 상한 도달에 필요한 최소 개수까지만 선택한다. 마지막 사탕의 초과 경험치는 소멸한다. 사용 전에 실제 적용 경험치와 소멸할 양을 구분해서 보여준다.
이상한사탕 분기: 상점 구매로 얻는다. 향후 탐험 보상으로도 얻는다. 공통 가방에 종류별로 보관한다. 가방에서 이상한사탕을 선택한 뒤 가방 기기 창에서 대상과 수량을 선택한다. 대상은 파티 개체만이다(2026-10-01). 숨긴 파티 개체도 대상이다. 파티가 비면 쓸 대상이 없다. 사용으로 배치·표시 상태를 바꾸지 않는다. 박스의 시간에 따른 성장 정지는 유지한다. 이상한사탕은 개체의 레벨을 1 올린다. 새 레벨의 경험치 진행은 0부터 시작한다. 15레벨의 진행이 70%인 개체는 사용 후 16레벨의 0%가 된다. 레벨 상한 100은 유지한다. 레벨 상승과 직접 진화는 구분한다. 99레벨에서는 한 개로 100레벨에 도달한다. 이미 100레벨이면 사용을 거부한다. 거부 시 개체 상태와 사탕 재고는 바뀌지 않는다. 한 개체와 수량을 선택한 뒤 예상 레벨을 확인하고 여러 개를 한 번에 사용할 수 있다. 최대 선택 수량은 보유량과 `100 - 현재 레벨` 중 작은 값이다. 98레벨에서 5개를 보유해도 최대 2개만 선택한다. 미리보기만으로 개체 상태와 재고를 바꾸지 않는다.
진화의돌 분기: 원작에서 돌로 진화하는 종은 파티 상세 기기 창의 진화 줄에서 진화의돌을 쓴다. 가방에서는 쓰지 않는다(2026-10-01). 진화 확인 화면으로 이어진다. 확인하면 진화하고 돌 1개를 소비한다. 취소하면 돌과 개체를 그대로 둔다. 돌을 가졌다는 이유로 자동 진화하지 않는다. 쓰지 않을 도구는 가방에서 구매가의 60% 로 팔 수 있다([가방 판매](game.md#가방-판매)). 진화용 도구 목록은 `data/evo-items.json`을 따른다.
성격민트 분기: 2026-09-30 부터 없다. 성격민트는 팔지 않고 쓰지 않는다([보류한 성격 변경](game.md#보류한-성격-변경)).
사탕·진화용 도구의 가격과 경험사탕 효과량, 경험치 곡선은 [밸런스 수치](balance.md)를 따른다. 기존 S4의 하루 상한은 승계하지 않는다.
`[스펙 미확정]` 사탕 종류별 보상표, 가방의 큰 수량 표시와 화면 배치, 사용 직전 상태 변경의 처리, 진화 연출 중 시간 처리, 종별 진화 조건.

## SC-07 숨김·보관·맞바꾸기

진입: 파티 또는 박스에 보유 개체가 있다.
목적: 작업 상황과 취향에 맞게 함께할 포켓몬을 바꾼다.
근거: [파티와 박스](game.md#파티-표시와-박스-보관), [교체](game.md#개체-획득과-파티-교체).

| 행동 | 사용자 결과 | 게임 상태 |
|---|---|---|
| 숨기기 | 화면에서만 사라진다. | 파티 칸 유지. 적립·친밀도 성장·배고픔·버프 시간 진행 |
| 다시 표시 | 같은 개체가 다시 보인다. | 숨김 동안의 상태를 그대로 사용 |
| 박스 보관 | 개체가 파티에서 빠진다. | 적립 중단. 친밀도·배고픔·남은 버프 시간 보존 |
| 맞바꾸기 | 파티 개체와 선택한 박스 개체의 위치가 바뀐다. 들어온 개체는 꺼낸 상태다. | 각 개체의 기록을 유지 |

같은 종의 여러 개체를 보유하고 함께 배치할 수 있다. 박스는 30칸 박스 여러 개로 나누고 넘겨 본다. 박스는 8개로 시작하고 상점에서 사서 늘린다. 파티와 박스에 빈 칸이 없으면 새 개체를 얻는 조작을 거절한다([둘 곳이 없을 때](game.md#둘-곳이-없을-때)).
공유 `sid` 계열의 예외: 지정한 단일 포켓몬 진화 계열은 박스에서 사용할 종을 교체한다. 두 종은 박스에서 각각 칸으로 보인다. 파티에 나가 있는 종의 칸은 `파티에 있음`이며 고를 수 없다. 두 칸에 공유 표시를 붙이고 박스 사용 칸 수는 1마리로 센다. 베베놈과 아고용 같은 선택지는 같은 개체의 상태를 공유한다. 두 종을 동시에 꺼내지 않는다. 일반 개체 맞바꾸기와 달리 새로운 개체를 생성하지 않는다. 파티에 같은 `sid`가 있으면 그 칸을 선택한 종으로 교체한다. 빈칸이 있어도 추가 배치하지 않는다. 파티가 가득 찼어도 같은 칸을 교체한다. 교체해도 칸의 표시 상태는 바꾸지 않는다(`src/dex/forms.ts` `setForm`).
표시 개체가 없는 경우의 복귀 경로:

1. 트레이에서 관리 화면을 연다.
2. 파티로 이동한다.
3. 모두 숨긴 상태이면 원하는 파티 개체를 다시 표시한다.
4. 파티가 비었으면 박스에서 보유 개체를 선택해 배치한다. 배치한 개체는 꺼낸 상태로 화면에 나타난다.

트레이는 관리 화면의 마지막 탭을 연다. 복귀를 위해 포켓몬을 클릭할 필요는 없다. 관리 화면 진입만으로 개체를 자동 배치하거나 표시하지 않는다.
교체 저장에 실패하면 두 개체를 원래 위치에 둔다. 완료한 교체를 재시도해도 위치를 되돌리지 않는다.
확정 전에 취소하면 두 개체를 원래 위치와 표시 상태로 둔다. 공유 `sid` 종 교체도 같은 거래로 처리한다. 저장에 실패하면 현재 종과 파티 칸이 그대로 남는다.
파티 탭의 `교체`나 빈 파티 칸을 누르면 교체 화면(박스 탭과 파티 기기 창)이 열린다. 박스 칸을 눌러 개체를 든 뒤 파티 칸을 누르면 맞바꾸거나 배치한다. 두 위치는 한 번에 바뀐다.
빈 파티 칸에 놓은 개체는 꺼낸 상태로 배치된다(`src/party/placement.ts`). 종 도감에서 새 개체를 무상 생성하지 않는다. 모달에는 검색·정렬이 없다. 규칙은 [개체 획득과 파티 교체](game.md#개체-획득과-파티-교체)를 따른다.
종료 상태: 각 개체는 파티 또는 박스에 한 번만 존재한다. 숨김과 박스 보관을 같은 조작으로 표시하지 않는다. 알에서 태어났거나 약으로 바뀐 이로치 개체는 숨김 해제·박스 복귀 후에도 이로치를 유지한다.
수용 확인: 같은 종 A·B를 바꿔도 친밀도가 섞이지 않는다. 숨겨서 배고픔만 멈출 수 없다. 보관·재배치로 버프가 초기화되지 않는다.
복귀 확인: 전원 숨김과 전원 박스 보관 각각에서 트레이로 관리 화면을 열고 파티로 이동한다. 사용자가 원하는 보유 개체를 선택한다. 숨김 중에는 적립이 계속된다. 파티가 비었으면 파티 개체의 적립은 없다. 박스에서 배치하거나 맞바꾼 개체는 꺼낸 상태로 들어온다. 숨긴 개체와 맞바꿔도 들어온 개체는 꺼낸 상태다.
부분 진행 확인: 박스에 넣기 전 쌓이던 포인트 진행을 개체별로 보존한다. 박스에서는 정지하고 파티 복귀 후에 이어간다. 친밀도와 적립 간격이 같다면 1포인트까지 30초 남았던 개체는 복귀 후에도 30초가 남는다. 맞바꾸기로 다른 개체에 진행이 복사되지 않는다.
박스로만 보내는 조작은 교체 화면에서 파티 개체를 든 뒤 박스 빈 칸을 누르는 것이다. 확인 창은 없다.
`[스펙 미확정]` 개체를 구별하는 화면 정보.

## SC-08 놀이공간 변경

진입: 기본은 화면 전체다. 사용자가 활동 영역을 바꾸고 싶다.
목적: 포켓몬을 곁에 두면서 작업할 공간을 확보한다.
근거: [일상 사용 계약](game.md#일상-사용-계약).

최소 크기는 넓이 기준이다. 모서리를 끌어 크기를 조절한다. 값은 [일상 사용 계약](game.md#일상-사용-계약)을 따른다.

1. 놀이공간 변경을 선택한다.
2. 설정의 `화면 전체 | 영역 지정` 전환 버튼에서 고른다. `영역 지정`을 고르면 `영역 그리기`가 나타난다.
3. 영역 지정이면 드래그해서 범위를 그린다.
4. 미리보기를 확인하고 적용한다.
5. 지정한 공간에서 활동을 이어간다.

취소하거나 저장에 실패하면 적용 전 영역을 유지한다.
모니터 구성이 바뀌어 영역이 어느 화면과도 겹치지 않으면 화면 전체로 대신한다. 영역 값은 지우지 않는다.
영역은 한 화면 안에서만 그린다.
종료 상태: 활동 범위 변경만으로 친밀도·파티·포인트를 바꾸지 않는다.
수용 확인: 튜토리얼은 설명만으로 끝낼 수 있다. 드래그를 취소할 수 있다. 영역 밖 개체가 영구히 보이지 않게 되지 않는다.
`[스펙 미확정]` 영역 경계에서의 행동.

## SC-09 도감·입수처·파티 확장

진입: 사용자가 새 종이나 더 많은 파티 칸을 원한다.
목적: 가능한 획득 방법을 알고 선택한다.
근거: [입수처](game.md#개체-레벨과-입수처), [칸 확장](game.md#파티-칸-확장과-박스-수용).

1. 도감에서 종과 입수처를 확인한다.
2. 구매·알·진화의 기본 입수 조건을 읽는다. 특수 기믹은 발견 전 힌트만 읽는다.
3. 구매·알·진화는 해당 경로의 해금·입수 조건을 따른다. 특수 기믹 전용 종은 선행 해금 없이 해당 기믹을 수행해 해금과 개체 획득을 함께 진행한다. 미해금 종을 알로 우회 획득하지 않는다.
4. 새 개체는 빈 파티 칸에 꺼낸 상태로 들어간다. 빈 칸이 없으면 박스에 들어간다.
5. 파티를 넓히고 싶으면 포인트 구매 또는 업적 경로를 이용한다.

구매는 총 2칸을 추가한다. 업적은 총 2칸을 추가한다. 기본 2칸과 합쳐 최대 6칸이다. 공통 필수 순서는 없다.
두 번째 칸 업적의 조건은 [파티 칸 확장과 박스 수용](game.md#파티-칸-확장과-박스-수용)을 따른다. 상점 칸을 모두 구매하는 것은 업적 조건이 아니다. 어떤 업적이든 달성만으로 칸을 열지 않는다.
알의 상점 기기 창은 돌보미집이 가득 찼을 때 `구매` 를 비활성으로 둔다. 문구와 줄 구성은 바꾸지 않는다.
`[스펙 미확정]` 진화 전용 종에서 대상 개체를 확인할 수 있게 한다. 특수 기믹의 성공적 획득을 발견 판정으로 제안한다. 보류하고 지금 동작을 유지한다.
종료 상태: 해금, 실제 개체 획득, 업적 달성, 보상 수령이 구분된다.
수용 확인: 전용 입수처를 우회하지 않는다. 구매 칸과 업적 칸을 중복 지급하지 않는다. 특수 기믹의 정확한 방법을 발견 전에 노출하지 않는다.
특수 기믹 확인: 해당 종의 도감 해금을 기믹 수행의 선행 조건으로 요구하지 않는다. 해금 후에는 종별로 지정한 상점·알 입수처와 조건을 적용한다. 후속 입수처를 허용하지 않은 종은 추가하지 않는다.
조건부 알 분기: 종별 조건을 충족하면 해당 종을 도감에 해금하고 알 후보에 추가한다. 이후 직접 부화로 무작위 획득한다. 조건 미달이면 후보에서 제외한다. 조건 달성만으로 개체를 지급하지 않는다. `[스펙 미확정]` 100종은 예시이며 실제 기준은 미정이다.
해금 수 확인: 초기 후보와 레벨 조건으로 해금한 미진화 종도 각각 한 종으로 센다. 보유하지 않아도 해금되어 있으면 포함한다. 같은 종을 여러 마리 얻어도 종 수는 늘지 않는다.
리전폼 집계 확인: 일반 대검귀 `503`과 히스이 대검귀 `503-1`은 별도 도감 항목이다. 둘 다 해금하면 2종으로 센다. 일반 대검귀만 해금했으면 1종이다. 각 항목에서 중복 개체를 획득해도 해금 수는 늘지 않는다. 진화 전 리전폼은 다른 종과 같은 규칙으로 해금한다. 진화로 얻는 리전폼은 실제로 진화할 때 해금한다. 규칙은 [리전폼](game.md#리전폼)을 따른다.
이로치 기록 확인: 같은 도감 항목에 이로치 획득 여부를 추가한다. 해금 종 수는 늘리지 않는다. 낮은 확률의 알 부화 또는 상점의 모습이 바뀌는 약 사용으로 이로치를 얻는다. 단일 종은 약으로 변경한다. 돌아오는 약은 0원이며 일반색으로 되돌린다. 약은 새 개체를 만들지 않는다. 확률과 변경 약 가격은 [밸런스 수치](balance.md)를 따른다. 돌아오는 약으로 일반색이 되어도 도감의 이로치 획득 기록은 남는다. 현재 색상과 획득 이력을 구분한다. 상세 계약은 [이로치와 색상 변경 약](game.md#이로치와-색상-변경-약)을 따른다.
단일 종 분기: 해당 저장에서 이미 획득한 단일 포켓몬은 다시 지급하지 않는다. 다른 허용 입수처로도 총 획득 1회 제한을 우회할 수 없다. 현재 표시·보관 상태와 관계없이 획득 이력을 사용한다.
단일 종은 알 입수처를 허용하지 않는다. 일반 알의 후보 범위에서 제외한다.
수용 확인: 단일 종을 최초 획득한 뒤 숨기거나 박스에 보관해도 재획득하지 않는다. 일반 종의 복수 개체 보유는 유지한다. 실제 단일 종 목록은 전설·환상 분류만으로 자동 확정하지 않는다.
기존 알에는 구매 후 새로 해금한 종을 추가하지 않는다. 종 지정 구매 가격은 [가격](balance.md#가격)을 따른다.
`[스펙 미확정]` 특수 기믹과 발견 판정, 허용 입수처에서의 저장 실패·재시도 처리, 연쇄 해금 평가 방식.

## SC-10 중단과 다음 날 재개

진입: 첫 선택, 튜토리얼, 거래, 부화 준비 또는 일상 사용 중 앱을 닫는다.
목적: 이전 상태에서 손실 없이 다시 시작한다.
근거: [일상 사용 계약](game.md#일상-사용-계약).

1. 앱을 종료한다. 파티 숨기기나 관리 화면 닫기와 구분한다.
2. 종료 중에는 게임 상태를 진행하지 않는다. 포인트와 부화 준비를 소급 진행하지 않는다.
3. 다시 켜면 마지막으로 저장한 상태에서 이어간다.
4. 스킵하거나 닫은 튜토리얼은 재실행 후에도 표시하지 않는다. 진행 중인 튜토리얼이 앱 종료로 끊겼으면 재실행 후 그 튜토리얼을 처음부터 다시 보여준다. 튜토리얼 상태는 `save.tutorials`에 튜토리얼마다 상태·끝낸 단계 수·대기 시각으로 저장한다(`src/tutorial/queue.ts`). 이 항목은 내부 구현이다. 동작은 코드를 따른다.

업적의 미수령·수령 상태를 보존한다. 재실행 후에도 미수령 보상을 업적창에서 받을 수 있다.
시작 포인트 지급 여부, 개체·알 ID, 부화 결과를 각각 보존한다. 거래 중 종료되면 저장 결과를 확인하고 같은 거래를 임의로 다시 실행하지 않는다. 시작 포인트는 첫 개체를 만드는 거래에서 한 번 준다(`src/party/starter.ts`). 개체 ID 는 `p숫자`로 가장 큰 번호 다음을 쓴다. 알 ID 는 `eggSeq`로 다시 쓰지 않는다. 부화 결과는 새 개체로 같은 거래에서 저장한다. 이 항목은 내부 구현이다. 동작은 코드를 따른다.
PC 잠금·절전도 앱 종료와 같이 배고픔·친밀도·포인트·버프 시간·알 준비 시간을 멈춘다. 남은 시간과 적립 중인 진행량을 보존한다. 중단 기간을 소급 진행하지 않는다. 설정창만 닫거나 포켓몬을 숨기면 기존 규칙대로 계속 진행한다. 감지 방식은 [실행 상태별 시간](game.md#실행-상태별-시간)을 따른다.
복귀 확인: 알 준비 1분과 버프 3분이 남았을 때 PC를 잠그거나 절전해도 복귀 후 잔여 시간은 그대로다. 절전 해제 후에도 PC가 잠겨 있으면 정지를 유지한다. 잠금 해제와 앱 실행 조건을 모두 만족하면 중단한 진행을 이어간다.
종료 상태: 사용자는 중단 때문에 첫 선택·구매·부화를 다시 할 필요가 없다.
수용 확인: 재실행으로 시작 포인트를 더 받지 않는다. 완료한 부화를 재추첨하지 않는다. 종료 시간을 배고픔이나 적립에 더하지 않는다.
알림 재개 확인: 이미 표시한 부화·진화·업적 배너는 같은 미처리 상태를 다시 알리지 않는다. 클릭하지 않았어도 이 규칙을 적용한다. 재실행 후 해당 메뉴에는 부화 가능·진화 가능·업적 미수령 상태가 유지된다. 아직 표시하지 않은 대기 배너는 재실행 후 이어서 표시한다. 대상이 여전히 미처리 상태일 때만 표시한다. 표시 중에 종료된 배너는 표시한 것으로 처리한다. 기다리는 동안 대상을 이미 처리한 배너는 표시하지 않는다.
`[스펙 미확정]` 저장 실패 후 종료 처리.

## SC-11 선택적인 에이전트 연동

진입: 사용자가 지원하는 에이전트를 사용하고 추가 이득을 원한다.
목적: 기본 생활 경험에 선택적인 보상을 더한다.
근거: [친밀도 획득과 확장 후보](../design.md#친밀도-획득과-확장-후보).

사용자 모달의 `연결` 탭은 연결 상태만 보인다. 상태는 미설치·연결 안 됨·연결됨·연결됨 · 갱신 필요·확인 필요 다섯 가지다(`src/renderer/manage/manage.ts` `agentRow`). 연결됨에는 마지막 신호나 점검 결과를 붙인다([설정과 연결](game.md#7-설정과-연결)). 갱신 필요는 등록된 이벤트나 훅 파일이 지금 버전과 다를 때다. `갱신` 단추가 맞춘다. CLI 연결은 이 탭의 단추로만 한다. `pokebuddy setup` 은 등록하지 않는다(2026-09-28 사용자 결정). 이 탭은 얻은 추가 이득을 보이지 않는다.
연결하지 않아도 SC-01부터 SC-10까지의 기본 경험을 제공한다. 에이전트 보상은 공통 보너스 한도를 대신 채우는 경로가 아니다.
감지 실패 또는 연결 해제 시 기본 돌봄과 적립은 유지한다. 친밀도와 포인트는 흐른 시간으로 쌓인다(`src/state/time.ts` `applyTime`). 에이전트 작업 시간은 그 위에 추가분으로만 더한다.
보상 계산은 에이전트 작업 시간을 쓴다. 토큰량은 보상 계산에 쓰지 않는다. 수치는 [밸런스 수치](balance.md#버프와-친밀도)를 따른다.
`[스펙 미확정]` 확인된 활동의 중복 지급을 막는다.
수용 확인: 에이전트 연결이 첫 만남이나 부화의 필수 조건이 되지 않는다. 기본 보상과 추가 이득을 구별한다.

## 화면과 모듈 연결

담당 영역의 경계와 책임은 [모듈 계약](modules.md)을 따른다. 아래 표는 담당 영역과 흐름 ID의 대응이다. 기술 디렉터리와 UI 배치를 정하지 않는다.

| 담당 영역 | 책임 | 연결 흐름 |
|---|---|---|
| 단계별 튜토리얼 | 행동을 관측하고 적절한 튜토리얼을 제시한다. 포인트·개체를 직접 소유하지 않는다. | SC-01, 03, 04, 05, 10 |
| 놀이공간과 표시 | 움직임, 표시·숨김, 영역 편집 | SC-02, 07, 08 |
| 개체 육성 | 친밀도, 경험치, 배고픔, 기간형 효과, 진화 가능 여부 | SC-02, 06, 07 |
| 경제와 상품 | 포인트 적립, 가격 검증, 거래, 재고 | SC-02, 03, 06, 09, 11 |
| 돌보미집 | 알별 타이머, 부화 가능 상태, 직접 열기 | SC-03, 04 |
| 보유와 파티 | 개체 ID, 배치·박스, 표시 상태, 맞바꾸기 | SC-01, 04, 05, 07, 09 |
| 도감과 입수 규칙 | 해금, 허용 입수처, 발견과 힌트 공개 | SC-01, 03, 04, 06, 09 |
| 업적 | 조건 달성, 미수령, 수령 완료 | SC-05, 09 |
| 저장과 재개 | 상태 저장, 실패 복원, 중복 요청 처리, 재실행 복원 | SC-01~11 |

여러 상태를 바꾸는 행동은 하나의 사용자 결과로 확인한다. 예를 들어 부화는 알 소비·개체 생성·파티 또는 박스 배치·돌보미집 칸 비우기를 함께 다룬다.
설정창의 탭은 파티 / 박스 / 도감 / 상점 / 가방이다. 돌보미집은 박스 탭의 모달이다. 업적창과 설정은 헤더 아이콘으로 여는 모달이다. 닫으면 보던 탭으로 돌아간다.

구매·사용·보상 수령의 실패 흐름: 관련 상태를 이전 값으로 유지하고 실패로 처리한다. 실패 복구용 선택값 보존과 다시 시도 버튼은 제공하지 않는다. 자동 재시도도 하지 않는다. 이후 정상 조작은 가능하다. 완료된 거래의 중복 지급·차감 방지는 유지한다.
부화·진화·교체도 같은 실패 흐름을 따른다.
