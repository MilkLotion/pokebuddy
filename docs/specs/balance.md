# 밸런스 수치

이 문서는 가격·적립·성장 같은 밸런스 수치를 모은다. 코드의 규칙표는 이 수치를 따른다. 규칙은 [게임 규칙](game.md), 흐름은 [사용자 시나리오](scenarios.md)를 따른다.

## 읽는 기준

이 문서는 숫자만 모은다. 규칙의 뜻은 기능 계약을 따른다. 숫자는 놀아 보며 고친다. 값을 바꿀 때는 이 문서와 `data/`를 함께 고친다.
시간 값은 ms 정수로 저장한다. 화면 표기는 초·분 단위로 올림한다. [모듈 계약](modules.md#저장-구조)을 따른다.

## 기준점

기준: 하루 4시간 정도 켜 두면 랜덤알 하나를 살 수 있다. 다른 가격은 이 기준으로 정한다.

| 항목 | 값 |
|---|---|
| 포인트 적립 간격 | 개체 1마리당 2분에 1포인트 |
| 친밀도에 따른 단축 | 친밀도 100이면 1분에 1포인트. 최대 2배 |
| 적립 대상 | 파티에 배치한 개체마다 각자 적립한다. 숨겨도 적립한다. 박스 보관은 멈춘다 |
| 기준 수입 | 1마리 4시간에 120포인트 |
| 돌봄 보너스 | 친밀도 100인 개체는 기분과 버프로 적립이 더 빨라진다. 수치는 [돌봄 보너스](#돌봄-보너스)를 따른다 |

## 성장

레벨 곡선은 원작의 성장 속도를 따른다. 종마다 성장 속도를 데이터에 둔다. 원작의 여섯 가지는 빠름, 보통 빠름, 보통 느림, 느림, 불규칙, 변동이다. 100레벨까지 누적 경험치는 약 60만에서 164만이다. 최대 레벨은 100이다.

| 도구 | 경험치 |
|---|---|
| 경험사탕XS | 100 |
| 경험사탕S | 800 |
| 경험사탕M | 3,000 |
| 경험사탕L | 10,000 |
| 경험사탕XL | 30,000 |
| 이상한사탕 | 레벨 1 상승. 새 레벨의 진행은 0부터 |

환산: 보통 빠름 종을 100레벨까지 키우면 약 100만 경험치다. XL 사탕 약 34개이며 10,880P다. 하루 4시간 기준 약 3주다. 작은 사탕은 단가가 비싸며 미세 조정용이다.
데이터: 종별 성장 속도는 `data/species.defaults.json`의 `growthRate`에 있다. 1089종 기준으로 보통 빠름 450, 느림 266, 보통 느림 263, 빠름 67, 불규칙 29, 변동 14다.

## 만복도와 돌봄

시간은 앱 실행 중이며 PC를 쓸 수 있을 때만 흐른다.

| 항목 | 값 |
|---|---|
| 만복도 감소 | 시간당 30. 2시간에 60 |
| 구간 | 배부름 100~60 · 보통 60~40 · 배고픔 40~15 · 매우 배고픔 15~0 |
| 말풍선 | 배고픔(고기 1개)과 매우 배고픔(고기 3개)에 들어가면 띄운다. 머무르면 배고픔 10분, 매우 배고픔 5분마다 다시 띄운다. 한 번에 5초 보인다. 보통 구간에서는 없음 |
| 기본먹이 회복 | 20. 무료이며 무제한 |
| 밥 주기 쿨타임 | 10분. 기본먹이와 프리미엄먹이가 공유 |
| 프리미엄먹이 | 만복도를 100으로 채운다 |
| 배고픔 디버프 | 배고픔 구간 친밀도 증가량 −30%. 매우 배고픔 −60%. 누적 친밀도는 깎지 않는다 |

밥 주기는 만복도가 가득이 아니고 쿨타임이 아니면 언제나 할 수 있다. 개체 상세와 포켓몬 위 우클릭 메뉴에서 한다.

## 버프와 친밀도

| 항목 | 값 |
|---|---|
| 든든함 (프리미엄먹이) | 친밀도 증가량 +100%. 2시간 (2026-09-29 사용자 결정) |
| 신남 (놀아주기 3중첩) | 친밀도 증가량 +50%. 30분 (2026-09-29 사용자 결정) |
| 들뜸 (놀아주기 2중첩) | 친밀도 증가량 +20%. 30분 (2026-09-29 사용자 결정) |
| 장난감 버프 | 신남과 같다. 지속시간은 2시간이다 (2026-10-02 사용자 결정) |
| 버프 갱신 | 같은 버프를 다시 걸면 남은 시간을 그 지속시간으로 바꾼다. 더하지 않는다. 남은 시간이 더 길면 그대로 둔다 |
| 버프 중첩 | 증가량을 더한다. 곱하지 않는다. 든든함 +100%, 신남 +50%, 들뜸 +20%. 든든함과 신남이 함께면 +150%. 화면도 "+N%" 꼴로 적는다(2026-10-04 사용자 결정 "+% 하나"). 신남과 들뜸은 함께 켜지지 않는다 — 3중첩이 되면 들뜸이 신남으로 바뀐다(제안, 사용자 확인 전) |
| 친밀도 시간 획득 | 10분에 1. 표시와 숨김이 같다. 박스 보관은 멈춘다 |
| 친밀도 돌봄 획득 | 밥 주기 2, 놀아주기 3. 쿨타임마다 한 번 |
| 놀아주기 쿨타임 | 10분. 밥 주기와 따로 센다 |
| 놀아주기 상태 | 놀아주면 20분 붙는다. 그 자체로는 효과가 없다 |
| 들뜸·신남 조건 | 상태가 남아 있는 동안 이어서 2번 놀아주면 들뜸, 3번이면 신남. 신남이 남아 있으면 들뜸을 새로 걸지 않는다(제안, 사용자 확인 전) |
| 하루 상한 | 없다 |
| 에이전트 작업 보너스 | 에이전트가 작업하는 시간은 친밀도와 포인트 적립 시간을 두 번 센다. 적립 속도가 2배다. 배율은 기본 적립과 같다. 파티 칸 개체만 받는다. 상한이 없다. 토큰량은 쓰지 않는다 |

환산: 친밀도 100까지 약 16시간이다. 친밀도가 오르면 포인트 적립 간격이 2분에서 1분으로 짧아진다.

## 돌봄 보너스

친밀도가 100인 개체는 돌봄 보너스를 받는다(2026-10-02 사용자 결정). 친밀도가 100 미만이면 받지 않는다.
포인트 적립 속도는 기본 속도 × (100% + 기분 보너스 + 버프 보너스)다. 구현은 `src/state/time.ts` `carePercent` 다.

| 항목 | 값 |
|---|---|
| 기분 최고 (80 이상) | +30% |
| 기분 좋음 (60 이상) | +15% |
| 기분 보통 이하 | 없음 |
| 들뜸 | +20% |
| 신남 | +50% |
| 든든함 | +100% |
| 합산 | 기분 보너스와 버프 보너스를 더한다. 곱하지 않는다. 신남과 들뜸은 함께 세지 않는다. 최대 280%다 |
| 배고픔 | 포인트를 직접 줄이지 않는다. [기분](#기분)의 감소 배율로만 작용한다 |
| 에이전트 작업 보너스 | 적립 시간을 두 번 세므로 돌봄 보너스와 곱해진다 |

환산: 친밀도 100인 1마리는 시간당 60P다. 기분 최고는 78P다. 든든함은 2시간에 120P를 더한다. 장난감 신남은 2시간에 60P를 더한다.
도구 값을 뺀 시간당 수입은 기분 최고 78P, 장난감 추가 98P, 프리미엄먹이 추가 108P, 둘 다 128P다.

## 기분

친밀도가 100 미만인 개체의 기분은 보이기만 한다. 친밀도가 100인 개체는 기분 단계가 포인트 적립을 올린다. 수치는 [돌봄 보너스](#돌봄-보너스)를 따른다. 기분은 친밀도와 움직임을 바꾸지 않는다.

| 항목 | 값 |
|---|---|
| 범위와 시작 | 0~100. 새 개체는 60 |
| 밥 주기 | +10. 기본먹이·프리미엄먹이 |
| 놀아주기 | +15. 클릭 놀아주기와 장난감 |
| 시간 감소 | 파티 칸 개체는 10분에 1. 숨김도 같다. 박스 보관은 멈춘다 |
| 배고픔 배율 | 배고픔 구간은 감소 2배, 매우 배고픔은 3배 |
| 단계 말 | 80 이상 최고, 60 이상 좋음, 40 이상 보통, 20 이상 시들, 그 아래 우울 |

환산: 100 에서 돌보지 않으면 약 6시간 40분 뒤 60 이 된다. 놀아주기 쿨타임마다 놀아주면 줄지 않는다.

## 줍기

규칙은 [줍기](game.md#줍기)를 따른다. 구현 값은 `src/find/rules.ts` `FIND_RULES` 다.
판정은 마리마다 따로 한다. 주울 확률·항목 가중치·포인트 양은 2026-09-29 사용자 결정이다. 이 결정은 앞선 "도구 하루 5번·포켓몬 3일에 1번"과 "10분마다 20%"를 대신한다. 그 밖의 값은 제안이다. 사용자가 확인하기 전이다.

| 항목 | 값 | 출처 |
|---|---|---|
| 주울 확률 | 마리가 조건을 채운 1초마다 1/2000. 마리끼리 독립. 30분에 약 59% | 2026-09-29 사용자 결정 |
| 항목 가중치 | 주웠을 때 포인트 100 · 도구 50 · 진화용 도구 20 · 포켓몬 1. 포켓몬 수집 난이도 가중치를 따른다 | 2026-09-29 사용자 결정 |
| 포인트 양 | 5~10P 균등 | 2026-09-29 사용자 결정 |
| 굴리는 때 | 전역 시계의 1초 틱마다 마리별로 한 번. 확률은 1 − (1 − 1/2000)^(초) | 2026-09-29 사용자 결정 |
| 틱 상한 | 마리마다 한 틱에 최대 1건. 틱 사이가 5초(`TIME_RULES.maxGapMs`)를 넘는 틈(절전 복귀 등)은 굴리지 않는다 | 제안 |
| 도구 후보 | `data/items.json` 에서 상점가가 0 초과 200 이하인 도구. 기본먹이·돌아오는 약·모습이 바뀌는 약·경험사탕XL은 빠진다 | 제안 |
| 도구 가중치 | 1/가격. 성격민트는 2026-09-30 부터 후보가 아니다 | 제안 |
| 도구 수량 | 1개 | 제안 |
| 진화용 도구 후보 | `data/evo-items.json` 전부. 균등. 1개 | 제안 |

## 메가진화

규칙은 [메가진화](game.md#메가진화)를 따른다. 값은 `src/dex/rules.ts` `MEGA_RULES` 다. 네 조건을 모두 채우면 메가스톤이 생긴다.

| 조건 | 값 | 근거 |
|---|---|---|
| 친밀도 | 100 | 2026-10-02 사용자 결정 |
| 레벨 | 60 이상 | 2026-10-02 사용자 결정 |
| 파티에서 보낸 시간 | 친밀도 100 뒤 24시간 | 항목은 사용자 결정, 값은 제안 |
| 돌봄 누적 횟수 | 친밀도 100 뒤 밥 주기와 놀아주기 합 100회 | 항목은 사용자 결정, 값은 제안 |

환산: 밥 주기와 놀아주기는 쿨타임이 10분씩이다. 100회는 쿨타임마다 둘 다 하면 약 8시간 20분이다.
사용자는 함께한 기간 조건을 뺐다(2026-10-02 "14일은 너무길어서 음.. 함께한 기간은 빼자.").

## 로토무의 모습 바꾸기

규칙은 [특수 폼](game.md#특수-폼)의 "로토무의 모습 바꾸기"를 따른다. 값은 `src/dex/rules.ts` `SHIFT_RULES` 다. 계정의 에이전트 작업 시간(`save.totals.workMs`)이 50시간(`180,000,000ms`) 이상이면 다섯 모습이 한꺼번에 열린다(2026-10-04 사용자 결정 "50시간").

## 서버 검증 상한

서버가 올린 저장을 직전 서버 저장과 견줄 때 쓰는 상한이다([서버 저장 검증](modules.md#서버-저장-검증)). 상한은 규칙상 정상 최대치에 여유 1.1 을 곱한다. 틈 Δt 는 서버 시각이고 72시간에서 자른다. 파일 쓰기(15초)·틱(30초) 지연 때문에 Δt 에 60초를 더한다.

| 규칙 | 상한 |
|---|---|
| 포인트 | 시간 적립 2,016P/시간(파티 6마리 × 친밀도 배율 2 × 작업 배율 2 × 돌봄 보너스 2.8, 2분에 1P) × Δt × 1.1 + 1 + 줍기 포인트 + 우편 포인트(새로 넣은 편지 id 의 선물, 민트는 개당 100P) + 새로 받은 업적의 포인트 보상 + 판매가(가방에서 줄어든 도구) + 포켓몬 판매가(사라진 개체 수와 같은 틈에 얻어서 판 개체 수 × 가장 비싼 판매가 50P) + 민트 환불 |
| 산 것 | 출처(직전 가방·줍기·우편·업적 보상) 없이 늘어난 도구와 새 알(연 알 수만큼은 보너스 알, 새로 받은 알 보상 업적 수만큼은 값이 없다)의 값 ≤ 그사이 쓸 수 있었던 포인트 × 1.1. 팔지 않는 도구(기본먹이 등)는 출처 없이 늘 수 없다 |
| 우편·업적 | 새로 넣은 편지는 서버에서 받은 편지여야 한다. 새로 받은 업적은 `data/achievements.json` 에 있어야 한다. 업적의 달성 조건은 검증하지 않는다. 보상은 업적마다 한 번이라 받을 수 있는 양에 끝이 있다 |
| 작업 시간 | Δt × 1.1 + 1분 |
| 레벨·경험치 | 레벨 1~100, 경험치 0~1,640,000(가장 느린 곡선의 100레벨), 레벨 ≤ 그 종 곡선에서 경험치가 허락하는 레벨 |
| 경험치 증가 | 기존 개체의 증가와 새로 얻은 개체(교환 제외)의 경험치 합 ≤ (쓴 사탕 양 + 남은 포인트로 살 수 있는 사탕 양) × 1.1. 이상한사탕은 한 레벨 간격 최대인 68,116 으로 센다 |
| 친밀도 | 줄지 않는다. 개체마다 (시간 30/시간 + 돌봄 30/시간) × Δt × 1.1 + 5(밥·놀기 한 번씩)을 넘는 몫은 장난감(3씩)으로 올렸어야 한다. 장난감은 모든 개체가 함께 쓴다 |
| 새 개체 | 연 알 + 줍기 포켓몬 + 새로 받은 포켓몬 업적 + 우편 포켓몬 + 교환으로 받은 개체 + 남은 포인트로 살 수 있었던 알·종(최저가 120P) |
| 교환으로 받은 개체 | 받은 제안(서버 저장 값)과 종(같은 틈의 진화 포함)·성격이 같고 레벨이 제안 이상이어야 한다. 레벨이 높은 제안부터, 레벨·경험치가 가장 가까운 개체와 맞춘다. 제안보다 늘어난 경험치는 사탕 예산으로, 친밀도는 시간·돌봄 상한을 넘는 몫을 장난감 예산으로 센다 |
| 이로치 | 새 이로치는 연 알 + 줍기 포켓몬 + 교환으로 받은 개체 + 살 수 있었던 알 이하. 교환으로 받은 뒤 약으로 켠 이로치는 약 예산으로 센다. 기존 개체가 이로치가 된 수는 쓸 수 있었던 모습이 바뀌는 약 이하 |
| 종·성격 | 종 변경은 진화 간선(앱의 `nextOf`, 모습 슬러그 포함)·`forms` 안에서만. 성격·성별은 바뀌지 않는다. `since` 가 바뀐 개체는 새 개체로 센다 |
| 로토무의 모습 | 로토무의 다섯 모습인 개체가 있으면 작업 시간이 50시간 이상이어야 한다(`form-lock`) |
| 메가진화 | 메가스톤을 지닌 개체는 친밀도 100, Lv.60 이상이어야 한다. 메가 모습인 개체는 메가스톤이 있어야 하고 모습이 그 종의 메가 모습이어야 한다. 파티 시간과 돌봄 횟수는 보지 않는다 |
| 개체 번호 | 새 개체의 id 는 `p<번호>`이고 번호는 직전 저장의 `petSeq`(없으면 가장 큰 개체 번호)보다 크다. 같은 틈에 얻어서 판 개체는 번호만 늘고 저장에 없다. 그 수는 새 개체 수에 더해 출처 수와 견준다 |
| 알 | 6개 이하 |
| 알 | 이미 있는 알의 종류·후보는 바뀌지 않는다. 새 알의 id 는 `e<번호>`이고 번호는 직전 저장의 가장 큰 알 번호보다 크다. `eggSeq`는 줄지 않는다. 새 알의 후보는 그 알의 범위(단일·고정 후보 알은 그 목록, 랜덤알은 랜덤알에 나올 수 있는 종) 안이다. 같은 틈에 만들어 연 알은 연 알 수를 넘는 만큼 산 것(120P)으로 센다 |
| 알 결과 | 열린 알마다 계정 시드로 다시 계산한 결과(보너스 알 종류, 또는 종·이로치)가 새 저장에 있어야 한다. 한 틈에 여러 알을 열면 여는 순서를 모두 대입해 하나라도 맞으면 된다. 부화한 개체는 같은 틈에 진화·모습 바꾸기·이로치 약을 썼을 수 있다. 같은 틈에 만들어 연 보너스 알의 결과는 대조하지 않는다 |

줍기 기록은 최근 20건만 남는다. 기록에 없는 줍기는 포인트 10P·가장 비싼 판매가로 센다.
